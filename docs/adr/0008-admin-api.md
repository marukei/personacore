# ADR-0008: 管理機能は `/admin/` の HTTP API に置き、書き込み経路を1つに保つ

- 状態: 採用
- 日付: 2026-08-13
- 関連: [ADR-0001](0001-openai-compatible-boundary.md) / [ADR-0004](0004-session-identification.md) /
  [07-prompt-compiler.md](../07-prompt-compiler.md)

## 背景

マイルストーン1〜2（起動と `/v1/models`）は達成したが、
**キャラクターを登録する手段が無い。** `store` に作成 API はあるものの、外から叩く経路が無く、
`/v1/models` は常に空の一覧を返す。マイルストーン3以降には必須。

選択肢は「CLI サブコマンド」「起動時のシードファイル」「管理 HTTP API」。

判断を左右したのは**フェーズ3**。`character_appearance`（固定タグ・LoRA 指定）と
`generated_image`（プロンプト・seed・生成画像のギャラリー）は
**本質的に視覚的な管理対象**であり、CLI で扱うのは無理がある。

## 決定

**管理機能は `/admin/` 配下の HTTP API に置く。**

- **書き込み経路はこの API だけ。** `store` を直接叩く経路を他に作らない
- **初期の投入手段は「JSON を POST するスクリプト」**（PowerShell / curl）。Rust コードを書かない
- **キャラ管理 FE はマイルストーン5の検証後**に着手する

## 理由

1. **書き込み経路が1つに保たれる。** CLI に `store` を直接叩かせると**2つ目の書き込み経路**ができ、
   検証ロジックが二重管理になる。本プロジェクトが繰り返し潰してきた形
   （`Store::pool()` の抜け穴、`Seg::Lit` 連結による綴りの再生）と同じ構造。
2. **`/v1/` と分離する。** OpenAI が将来 `/v1/characters` 等を定義しても衝突しない。
   ADR-0001 の「**両側で同じ規格を話す**」という境界が曖昧にならない。
3. **スクリプトなら捨てられる。** FE ができた時点で役割を終える。
   CLI を作ると、引数パースの自作か `clap` の追加が必要なうえ、
   **エンドポイント経由にするならサーバ起動が要る点はスクリプトと変わらない。**
4. **FE を後にするのは「検証してから道具を作る」ため。**
   マイルストーン5（性格を変えると応答が変わる）が崩れたらプロンプト設計を見直すことになる。

### 却下した選択肢

- **CLI サブコマンド** — `store` を直接叩くなら2つ目の書き込み経路。
  API 経由にするならサーバ起動が要り、スクリプトに対する利点が消える。
  加えて引数パースの自作か依存追加が要る。
- **起動時のシードファイル** — 同じく2つ目の書き込み経路。
  「起動するだけ」の手軽さはあるが、検証ロジックの二重管理と引き換えになる。
- **`/v1/` 配下に混ぜる** — OpenAI の仕様拡張と衝突しうる。

## 結果

### 得られたもの

- **書き込み経路が1つ。** FE も CLI もスクリプトも「管理 API のクライアント」になる
- **フェーズ3の画像管理が同じ土台に乗る**（`character_appearance` / `generated_image`）
- FE の着手を遅らせても、その間の作業が無駄にならない

### 諦めたもの / 前提

- **OpenAI 互換だけでは完結しなくなる。** ADR-0001 の
  「既存の OpenAI 互換クライアントをそのまま FE として使う」は**チャット部分のみ**に縮小する。
  管理は別クライアント（当面はスクリプト）が要る。
- **認証は無い**（[01-overview.md](../01-overview.md) のスコープ外事項）。
  防御は `127.0.0.1` バインドのみ。
  **管理 API は破壊的操作を持つので、外部公開の禁止がこれまで以上に重要になる。**
  `BindAddr` がループバック以外を表現できないことが、そのまま防御になっている。

### 設計上の制約

- **`memory` を UPDATE / DELETE する管理 API を作らない。**
  [03-data-model.md](../03-data-model.md) の不変条件2（`superseded_by` は時系列保持）は
  **API を生やさないことが唯一の防御**であり、`/admin/` はその例外にならない。
  > **⚠ 前提が変わった**（2026-08-22 / 作業単位 14 / [ADR-0022](0022-repairing-memories-without-deleting.md)）。
  > **記憶を直す導線を生やした。** ただし**「消す」道は作っていない** ——
  > **訂正版を追加し、古い行の `superseded_by` にそれを指させるだけ。**
  > **不変条件2はそのまま守られている。**
  >
  > **API の形でもそれを表現してある** —— 1件の記憶を指すパス
  > （`/admin/characters/{handle}/memories/{id}`）を**生やしていない**ので、
  > **`PUT` と `DELETE` が自然に置ける場所そのものが存在しない。**
  > 生えているのは `GET .../memories`（修復のための一覧）と
  > `POST .../memories/{id}/corrections`（訂正の追加）の2本だけ。
  >
  > **「唯一の防御」も、もう唯一ではない** —— SQL のテキスト走査が
  > **後継の印を消す文**を落とす（射程は
  > [ADR-0022](0022-repairing-memories-without-deleting.md) の「走査で守れる範囲」）。
  かつて SQL 走査テストの許可リストは `src/store/**` と `migrations/**` しか
  見ておらず、**`server` に生の SQL を書けば走査の外に出た**。
  この抜け道は塞いである（Rust 側の走査対象は `src/**` 全体）。
  **範囲を `src/store` に戻さないこと。** 戻すと `src/server/admin.rs` に1行書くだけで
  見張り番を回避できる（回避したことは誰にも見えない）。
- **キャラクター名は `CharacterName` を通す**（ADR-0004）。
  > **⚠ ゴースト行の衝突はもう起きない（2026-08-16 / 0004b-2）。**
  > [ADR-0017](0017-handle-is-a-restricted-alphabet.md) で識別子に空白を書けなくなり、
  > 正規化キーの索引ごと落とした。**`ConflictingUnnormalizedName` は消えている。**
  > 以下は当時の設計判断として残す。

  ~~ゴースト行との衝突（`ConflictingUnnormalizedName`）は
  正当な重複と**区別できる形でレスポンスに出す**こと。
  区別しないと「一覧に出ない・チャットは404・しかし作ろうとすると既に存在する」という
  袋小路を利用者に押し付ける。~~
- **ペルソナ本文は `Persona` を通す。**
  空・空白のみ・長すぎるものを受け付けない。
  **上限は `Persona::MAX_CHARS` が正。ここに数字を写さない**
  （~~1000 文字~~ → **12b で 600 に下げた**。理由は
  [ADR-0009](0009-character-attributes-and-facts.md)「上限の数字と、その出どころ」）。
  この API には**更新も削除も無い**ので、巨大なペルソナを1つ通すと
  「以後のチャットが必ず予算超過で失敗し、アプリ経由では直せないキャラクター」ができる
  （`MemoryContent::MAX_CHARS` とまったく同じ構造）。
  検証は**リクエスト型ではなく `domain` の型**に置く。読み出し側も同じ型を通るので、
  DB を直接編集した不正なペルソナは `InvalidStoredValue` で止まる
  （**黙って一覧から除外しない**。名前は正常なので、除外すると上と同じ袋小路になる）。
