## 4. 設計判断とその理由 / 却下した代替案

ADR に書いたものは ADR が権威（0041〜0044）。**ここには ADR に書いていない、推論の中だけにあった判断を書く。**

### 4.1 作業単位の切り方
- **F-4b を b-1（起動時）/ b-2（走ったまま差し替え API）/ b-3（画面）に割った。** 理由: `AppState` の LLM クライアントを可変にする変更は `llm::LlmClient` の継ぎ目に触り（`upstream_leaks` の台帳）、起動時の起こし方と一緒にすると1単位が大きすぎる。画面はさらに別（司令塔しか実機確認できない）。
- **origin#2 は API に絞り、画面は origin#24 へ**。「起動したらコントロールできる」は origin#24 で満たす。origin#2 が先なのは、画面が呼ぶ口が無いと画面の受け入れ条件が書けないから。
- **B-52 / B-53 は勝ちの線に割り込ませた。** どちらも「使ってみる」の既定の道がそのまま壊れる欠陥で、先回りではない。

### 4.2 ADR-0044（B-53）で「案A: 帳簿の付け替え」を採り「案B: 自前の Migrator」を却下した理由
sqlx の `migrate!` は `build.rs` の追跡と型が一体。付け替え1段のほうが小さく、sqlx の帳簿の意味も変えない。**付け替えの条件を「CRLF 版に一致し LF 版に一致しない」だけに絞った**のは、編集された SQL を通す経路を作らないため（レビュアーが「常に付け替える」変異で 2 赤を確認）。**`if crlf == embedded` の分岐は到達不能な防御**（等価変異）で、逆向き（CRLF で組んだ exe が LF の帳簿を開く）を止めているのは CR 走査のほう。

### 4.3 リポジトリ全体を LF にしなかった理由
`.gitattributes` は `migrations/*.sql` だけ。CLAUDE.md §4 の CRLF に関する知見（変異検査の道具が当たらない、`sed -i` が潰す、隔離ワークツリーで緑でも `main` で赤）は**全部 autocrlf の作業ツリーを前提**にしている。全体を LF にすると前提が丸ごと変わるので、**別の決定として ADR を書くこと**（確度: 高。やる値打ちはあるが、この期間の範囲ではない）。

### 4.4 B-52 で見本の llama を 8081 にした理由
personacore の `DEFAULT_PORT` は 8080 で、llama.cpp の慣習も 8080。**どちらかを変えるなら見本のほう**（`DEFAULT_PORT` を動かすと `tests/readme.rs` / `start_script.rs` の帳簿と利用者の習慣が全部動く）。検証はポートだけを見てホストの綴りは見ない（`127.9.9.9` のような別名なら同居できるが案内していない）。

### 4.5 `default-run = "personacore"`
偽の `llama`（`tests/support/fake_llama.rs`）を `[[bin]]` に足した瞬間、素の `cargo run` が曖昧になって `start.ps1` が死んだ（**実機確認で初めて出た**）。`start.ps1` を `--bin` にする形は却下（素の `cargo run` が動くのが F-1 の約束）。

### 4.6 `stop()` と `kill_on_drop` の二重の守りをそのまま置いた
単独ではどちらの変異も緑、組で赤（第5の分類）。`stop()` にしか無い主張は「終了を `wait` する」「`Store::close` より前」「`Stopped` を書く」の3つで、**3つとも見張り番が無い**（`wait` を `try_wait` にする変異が 2157 全緑）。**F-4b-2 で「次を起こす前に前の終了を待つ」経路ができて初めて決定的に測れる**ので持ち越した（origin#2 のコメントに書いてある）。

### 4.7 `PERSONACORE_PORT=0` では B-52 の門が効かない
`port_conflict` は要求したポートを見る。`0` なら判定しない。**`tests/upstream_cli.rs` は `PERSONACORE_PORT=0` で走るので、実行ファイル経由の経路ではこの門は一度も効いていない。** 直すなら `bind` 後の `local_addr` を渡す形（引数の型が変わる）。**いまの実害はゼロ**（エフェメラル範囲を名指しするプロファイルだけ）なので doc に書いて据え置いた。

### 4.8 「使ってみる」の道を 09-setup ではなく `scripts/README-start.md` に置いた
`docs/09-setup.md` は「歩いていない道に手順を書かない」を見張り番で強制している。本物の llama を作業者は起こせないので手順は書けない。**歩いた記録が要るなら司令塔が歩いて 09-setup に足す**（origin#25 でやる）。

### 4.9 却下したもの（ADR に無いぶん）
- **`--upstream=<名前>` の形**: 受理する形を2つ持たない（`--fresh=1` と同じ扱い）。
- **`main` の中身を `server` へ1段出して `--fresh` の配線をテストする案**: 穴が1段ずれるだけ。**実行ファイルそのものを起こす**（`CARGO_BIN_EXE_personacore`）形を採った。
- **`sha2` を直の依存にする案**（B-53）: sqlx の `Migration::new` が checksum を計算して持つので不要。ただし**それで「sqlx と同じ値」を測ると同義反復**になるので、CRLF 側の権威は「実ファイルを CRLF に直して `Migrator::new` に読ませた値」に置いた。

## 6. サブエージェントの使い方の実態

### 体制
- **作業者** `rust-implementer`（Opus 固定 / `isolation: "worktree"`）。1単位1エージェント。**ブランチは `main` から分岐するので、`main` で足した doc はそのツリーに無い**（ADR を先にコミット・push してから出す）。
- **レビュアー** `rust-reviewer`（Opus）。**同じレビュアーを是正の周で再利用した**（`SendMessage` で続き。文脈が残るので2周目以降が速い）。3単位を1人に続けて見せても破綻しなかった。
- **合流は司令塔**: ワークツリーで `git add <パス列挙>` → コミット（`Closes #N`）→ `git rebase main` → `main` で `--ff-only` → **司令塔が変異を1本自分で当てる**（是正前に緑だったもの）→ 検査一式 → push。

### うまくいった点
- **変異検査の「置換件数の門」と「`_noguard`（是正を外して緑に戻る）」を毎回要求した。** 是正の赤が別のアサート由来だった例（F-4b-1 の `--host`: 赤にしていたのはフィクスチャで、印の2行ではなかった）をレビュアーが捕まえた。
- **偽の `llama` を PATH の先頭に置いて本当に起こす**（`tests/support/fake_llama.rs` / `required-features = ["testing"]` で素の `cargo build` からは作られない）。GPU を掴まずに起動・停止・帰属が測れた。
- **実機確認は司令塔だけがやる**と決めていたのが効いた —— `cargo run` の曖昧さ（4.5）と、ポートの衝突（B-52）は**実機でしか出なかった**。
- **落ちたセッションからの再開**: 作業者は `SendMessage` で続きから動いた（transcript が残る）。ワークツリーは無傷だった。**再開の指示には「外から見た状態」を添える**（作業者は自分の見えていた最終状態と突き合わせて、私のスナップショットの古さを正しく指摘した）。
- **Issue ドリブン**: `gh issue create` → 番号を指示に入れる → `Closes #N`。経緯は Issue のコメント。ロードマップは順と理由だけ。

### うまくいかなかった点
- **司令塔の実機確認の道具が2回誤った**: ①起動器が4秒で死んだのに「何も残っていない＝Ctrl+C で止まった」と OK を出した（`ready` を条件にして直した）。②Ctrl+C の配達（3通り）が届かず、しかも `CTRL_C_EVENT` を group 0 に送ると Bash の道具の側が死んだ。**停止経路は利用者に頼んだ**（1分で済んだ）。
- **作業者の初版の見張り番が狙いを外した例が2件**（`[[bin]]` の節を数えて `src/main.rs` の自動発見を見ない／版 5 だけ植えて `migration = 5` の決め打ちが素通り）。**どちらもレビュアーか実機が捕まえた。** 作業者の自己申告だけで合流しないこと。
- **レビュアーの初版の変異が届かないことが1件**（B-52 の m2）。作業者が自分で「定義が誤っていた」と申告して測り直した。
- **`git worktree remove` は「Filename too long」で毎回失敗**する。`rm -rf` で消し、`git worktree prune` → `git branch -D`（rebase 後は `-d` が拒む）。
- **司令塔が `docs/README.md` の索引や ADR 索引の行を書き忘れる**ことは無かったが、**ADR の見張り番の数を写して食い違わせた**（F-4a: 「6つ／4本」→ 実際は 6/5/6 と動いた）。**数は自分で数えたものだけ書く。**

### 使い方の細部（次の司令塔が踏まないために）
- 作業者・レビュアーへの指示に必ず入れる: 複製ツリーは短いパス（`%TEMP%\pcXX-<agentId>\t`）／直列／置換件数の門／変異の定義をログの隣に／実機の `llama` を起こさない／ブラウザを起こさない／**コミットしない・`git add -A` しない**／指摘が無ければ「無い」と明言。
- レビュアーの複製は `.git` を写さない（本物のワークツリーを指すリンクが危険）。`web/node_modules` は写さず `pnpm install --frozen-lockfile`。
- **1つのワークツリーに触るのは常に1人。** レビュー中に作業者へ指示を出さない。
- 変異検査で残った偽 `llama.exe` は GPU を使わない。`Get-CimInstance Win32_Process -Filter "Name='llama.exe'"` で数える（自分の検索コマンドに当たらない形）。
