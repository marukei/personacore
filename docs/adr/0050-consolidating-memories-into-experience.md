## いまの決定（要約）

この ADR は1日のうちに測っては決め直した。**いま生きているのは次の4つだけ**で、下の「提案する決定（叩き台）」の決定1〜6 と「利用者に問うたこと」は経緯として残す（§「作る前」の測定と決め直し で置き換わった）。

1. **本文の想起は、利用者についての記憶（`subject=user`）だけ。** キャラクター自身の記憶は抽出・保存し、裏方（抽出の既知の記憶・軸の候補）は読むが、本文には載せない。絞るのは `build_prompt`（origin#59 で済）。
2. **キャラクター自身の記憶は、承認制で人格の変化（属性・性格値の提案）の材料にする。** 先回りせず、遊んだ後に設計する。
3. **約束・決まりは、v0.1 の間は属性として利用者が書く**（終わりは属性の書き換え・取り外し）。サブ LLM に分類・書き直しをさせる案は、測ると悪化したので採らない。**v0.2 で専用の DB 項目にする**（origin#60）。
4. **利用者についての記憶の「似たものをまとめる」と、記憶の出どころ**（会話を1つ消す口のため）は、困ってから作る。

## 背景

利用者の方針（2026-10-20）: **「記憶を整理する」**。似た記憶をまとめ、記憶を経験に変える。人間がしている形を軸にする。

origin#56 の測定（2026-10-21、弥生・Qwen 公式）で分かったこと:

1. **記憶が想起の枠を全部取り、履歴が0件になっていた**。これは予算の欠陥として origin#56 で直す（記憶と履歴で残りを半々に分ける）。**この ADR は、その後も残る問題を扱う。**
2. **自己強化の輪。** 有効な記憶 547 件のうち 391 件が `subject=character` で、大半はキャラクター自身の台詞の言い直し（「〜と定義した／宣言した」）だった。応答に初めて出た句は数秒で記憶になり、後の応答にほぼそのまま戻る。
3. **主題の重複。** 厳密な重複は少ない（外しても応答は変わらなかった）が、同じ主張の**言い換え**が大量にある（例: 「思考を停止し足元だけを想うことが唯一の正解」の言い換えが7行）。
4. **抽出は古い記憶を見ていない。** 既知の記憶として依頼に載るのは毎回 30〜43 件で、残りの約 510 件は載らない。古い記憶との言い換えに気付けない。
5. **記憶は出どころを持たない**（どの会話・どのメッセージから来たか）。

半々の修正で履歴は戻るが、記憶の側には「同じ主張の言い換え 50 件」がそのまま残り、想起の枠の中で同じ主張の比重が高いままになる。

## 提案する決定（叩き台）

> **⚠ この節の決定1〜6 は、§「作る前」の測定と決め直し で置き換わった。** 経緯として残す。いまの決定は §いまの決定（要約）。

### 1. まとめる単位は「似た記憶の束」で、まとめた結果は新しい1行の記憶（経験）

- 裏方が、同じキャラクターの有効な記憶から**似た束**を見つけ、サブ LLM に**束を1行の経験に言い直させる**（「〜と何度も話した」「〜という傾向がある」）。
- 束の元の記憶は**消さない**。`superseded_by` に経験の行を入れて**想起から外す**（想起は `superseded_by IS NULL` しか読まない）。CLAUDE.md §1 の「行を DELETE / UPDATE しない」と両立する。ただし `superseded_by` は今「直した」（ADR-0022）の意味で使っているので、**「まとめた」と区別する印**が要る（決定4）。
- 経験の行は、記憶の型（`MemoryContent` の上限）にそのまま従う。

### 2. いつまとめるか —— 会話の合間（人間の睡眠に当たる）

- 候補: (a) 会話が一定時間止まったとき、(b) 有効な記憶が一定件数増えるごと、(c) 利用者が画面から「整理する」を押したとき。
- いずれも**本文の応答を返し切った後の裏方**で、**トランザクションの外で LLM を呼ぶ**（CLAUDE.md §1）。
- 叩き台の推奨: **(b) を既定にし、(c) を画面に置く**。(a) では「止まった」を外から判定できない（ADR-0035 と同じ問題）。

### 3. 似た束をどう見つけるか

- 候補: (a) 想起がすでに持つ文字 n-gram の採点（`src/prompt/recall.rs`）を流用する、(b) 埋め込み（LM Studio に `text-embedding-nomic-embed-text-v1.5` が入っている。ADR-0003 は「必要になったら sqlite-vec」と書いた）、(c) サブ LLM に候補をまとめて渡して束ねさせる。
- 叩き台の推奨: **まず (a) で候補を絞り、(c) で束ねる**。(b) は新しい依存と上流の能力（ADR-0038）を増やすので、(a)+(c) で足りないと測れてから。

### 4. 記憶に「出どころ」と「どうして外れたか」を持たせる

- 新しい記憶に、取り出した**会話とメッセージ**を持たせる（新しいマイグレーション。既存の行は不明のまま）。これで ADR-0049 決定2（会話を1つ消すと、そこから来た記憶も一緒に消せる）が作れる。
- 想起から外れた理由を区別する: **直した**（ADR-0022）／**まとめた**（この ADR）。経験の行からは、まとめた元の行を辿れるようにする（画面で「この経験は、どの記憶から来たか」を見せられる）。

### 5. 自分の台詞の言い直しを、出来事として溜めない

- 自己強化の輪の入口を細くする。候補: (a) 抽出が `subject=character` を取るのを「行動・出来事・利用者との関係」に限り、「自分がこう宣言した」を取らない、(b) 取るが、まとめる対象に優先して入れる（溜まりにくくする）、(c) 想起で `subject=character` の取り分に上限を置く。
- **ADR-0037（文面をいじらない）との関係**: (a) は抽出の依頼の文面を変える案で、ADR-0037 が閉じた経路に当たる。**(b)・(c) は文面を変えずに効く**ので、叩き台の推奨は (b)＋(c)。

### 6. 経験から属性へ（今回は決めない）

まとめた経験が十分に安定したら、属性（ADR-0028）の提案にする。ADR-0028 が保留している「提案を出す側」の入口になりうる。**この ADR では決めない**（先回りしない）。

## 却下した選択肢

- **自分の台詞の言い直しを、抽出でそもそも取らない**（決定5 の (a)）。ADR-0037 が閉じた「抽出の依頼の文面をいじる」経路に当たる（決定5 自体も §決め直し 4 で置き換わった）。
- **ボタンだけ**／**自動だけ**（決定2）。利用者が両方を選んだ。
- **会話が止まったらまとめる**（決定2 の (a)）。「止まった」を外から判定できない（ADR-0035 と同じ問題）。
- **件数を減らすまとめで定型を直す**（決定1 を定型の対策として）。「作る前」の測定で、応答が変わらなかった。
- **キャラクター自身の記憶を、想起で少しだけ載せる**（取り分に小さな上限）。利用者は「人格の側へ移す」を選んだ。上限を測る案は取らない。
- **キャラクターの出来事・約束・決まりを、サブ LLM で分類し要旨に書き直して本文に戻す**（§決め直し 5 の当初の決定）。測ると、何もしないより悪化した。
- **キャラクター自身の記憶は抽出も想起もしない**（自己像はペルソナと属性だけ）。抽出の文面を変えることになり（ADR-0037）、人格の変化の材料も失う。

## 結果

- 「本文の想起から `subject=character` を外す」（§決め直し 1）は origin#59（A-11a）で済んだ。測った腕（利用者についての記憶だけ）を本番の形にしたもの。
- 約束・決まりは、v0.1 の間は属性として利用者が書く。v0.2 で専用の DB 項目にする（origin#60 A-12）。
- 「記憶を経験に変える」は、**利用者についての記憶のまとめ**ではなく、**キャラクター自身の記憶を、承認制で人格の変化に取り込む**ことが本筋になった（§決め直し 2）。
