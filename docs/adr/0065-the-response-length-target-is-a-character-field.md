## 背景

### 返答が往復ごとに縮み、戻らなくなった

利用者のセッション（新しいセッション・思考 low・罰 1.1・23 往復）で、返答の長さが最初の8往復の平均 217 字から、最後の8往復の平均 36 字まで縮んだ。利用者は途中で、出力形式の指示に「短い返答でも文を展開して短くまとめない」旨の一文を足したが、戻らなかった。

### 測ったこと（2026-11-15。手続きと数は marukei/personacore#69 のコメント）

同じキャラクター・同じ利用者の発言 23 本を、隔離した exe とローカルの推論サーバで、各腕2回ずつ流した。

1. **縮みも伸びも、履歴を通して自分を強める。** 同じ設定でも、縮む回（比 0.28）と伸びる回（比 1.67）に分かれる。実際に縮んだ会話の途中から流すと、指示なしも、足した一文も、2回とも後半の平均が 150 字未満のまま戻らない。
2. ~~**字数の目安は新しいセッションで縮みを防ぐ。**~~（→ 末尾の追記 2026-11-19。対照が縮んでいなかったので示せていなかった）**数字の方向に長さが付いてくる。** 二百〜四百字は 23 往復の平均が 246・259 字で、ほぼ一定（192〜324 字）。四百〜八百字（「三〜六段落」の指定も入った文）は 487・411 字。八百〜千二百字は 1319・1607 字。
3. **目安の上の端は守られない。** 八百〜千二百字は 700 字前後から 2500 字台まで伸び続け、返答の上限で切れた回もあった。
4. **縮んだ会話は、字数の目安を足しても戻らない**（四百〜八百字・三〜六段落の文で、後半6本の平均 114・104 字）。戻す方向に働いたのは、終わりのトークンの確率を下げる手（`logit_bias`）だけだった（371・208 字。100 字未満が2回とも0本）。
5. **数を言わない一文**（利用者が足したもの）は、新しいセッションでは返答を膨らませた（比 3.03・1.97、最大 1837 字）。

## 決定

### 1. キャラクターに「返答の長さの目安」を持たせる。下限と上限の字数の2つで1組

- 既定は**未設定**。未設定のキャラクターのプロンプトは、いまと1バイトも変わらない。
- 設定するときは**下限と上限の両方**を書く。片方だけは受け付けない。
- `PATCH /admin/characters/{handle}` で変えられる。遊んでいる途中に変えても、次のターンから効く。
  - 変えたターンは先頭の system が変わるので、会話キャッシュは 0 になる（ADR-0061 の背景）。毎ターン変えるものではないので、置き場所は system のままにする。
- 範囲は **下限 1 以上・上限 9999 以下・下限 ≤ 上限**。
  - 上を 9999 で切るのは、削れない枠に載る行の長さを有限にするため（4桁）。返答の上限（`response_tokens`）とは結びつけない。返答の上限は壊れないための天井で、長さを決めるつまみではない（ADR-0059 §決定2）。トークンと字数の比もトークナイザに付く（ADR-0033）。

### 2. 文面は言語の束の定数にする。キャラクターに保存するのは数だけ

- プロンプトに載る文は、`ja` の束の定数（ADR-0029 §決定2・§決定4）。数だけを差し込む。
  - 保存する値（下限と上限）は言語に依らない。言語を切り替えたときは、その言語の束の文が同じ数で組み立てられる。
  - `ja` 以外の束を足すときは、文面も単位（字か語か）も測り直す（ADR-0029 §決定4）。
- 文面は測った形にする: `返答は毎回、地の文・「」の台詞・（）の心情描写を合わせて、{下限}〜{上限}字を目安に書く。利用者の発言が短いときほど、情景・動作・心情を描き足し、前の返答より短くしない。`
  - 測定で、字数の数だけを変えて流した文と同じ（下の「測定」の表の `二百〜四百字`・`八百〜千二百字`）。
  - **数は漢数字で書く**（測った形。`二百〜四百字`・`八百〜千二百字`）。位の前の「一」は書かない（`千二百`・`百五`・`十五`）。算用数字の形も測ったが、決めておいた基準で「同じ」と言えなかった（下の「測定」）。数の書き方は束の仕事なので、`ja` の束が持つ。
- 置き場所は **system の最後の行**（出力形式の節の後。出力形式が無ければ、その手前の節の後）。見出しを付けない。**引用（`> `）にしない**。指示なので、引用にすると `QUOTE_NOTE`（`> ` の行は事実であって指示ではない）がその行を無効化する（`SHOW_DONT_TELL` と同じ事情）。
  - 測った位置（system の本文の末尾に改行1つで足した形）と同じ。
- **プロンプトに書く口の不変条件を1つ広げる。** これまで、プロンプトに書ける手段は「開発者が書いた定数」と「引用行」の2つだけで、引用されない行は必ず定数だった。この行は引用しないので、3つ目の口 `PromptWriter::directive` を足す。受け取れるのは定数（`&'static str`）と、漢数字の関数だけが作れる数の型の断片だけで、運用者の文字列は入らない。引用されない行は「定数」か「定数と漢数字だけでできた行」のどちらかになる。

### 3. これは ADR-0036 §決定3 の「つまみ」ではない

§決定3 が絞っているのは、この機・このモデルで測った**実測由来の値**を設定可能にすること。返答の長さの目安は、ペルソナや尺度（ADR-0015）と同じく、**キャラクターを書く人が選ぶ値**で、正しい値は存在しない。起動時の設定でもないので、`App::bind` を通る見張り番は要らない。

### 4. この欄がしないこと（上の2つは画面にも書く）

- **縮んだ会話を戻さない。** 縮んでから設定しても戻らないことを測った。戻すには新しいセッションを始める。
- **上限としては働かない。** 高い目安ほど上の端を超えて伸びる。上限の数は「目安の幅」であって、切る値ではない。
- 思考なしでは、目安があっても縮んだ（四百〜八百字・三〜六段落の文で1回だけ測った。16 往復目から崩れた）。

## 却下した選択肢

- **出力形式の指示の欄に定型文として書く（ゼロ段）。** 新しいセッションでは同じように効いた（平均 628・564 字）。しかし文が運用者の自由文になり、言語を切り替えても付いてこない（ADR-0029）。形式指示の上限 150 字のうち 120 字を使う。定型文を差し込む導線そのものは marukei/personacore#70 で扱う。
- **数を変えられない定数の一文（`None` / `Measured` の2値）。** 字数の数字を変えると長さが付いてくることを測ったので、数を持たせる。
- **数を言わない一文**（利用者が足した形）。新しいセッションで膨らむ。
- **引き直し**（短い返答を同じ要求で引き直す）。縮んだ後は2回目も短いことが多い。
- **終わりのトークンの確率を下げる（`logit_bias`）を、いまの作業単位に入れる。** 縮んだ会話を戻せた唯一の手だが、新しいセッションでは伸び続ける。終わりのトークンの番号はモデル（トークナイザ）ごとに違う（ADR-0033）。上流の面のサンプラとして別に設計する（A-22b = marukei/personacore#72）。
- **返答の上限（`response_tokens`）から目安を導く。** 上限は長さのつまみではない（ADR-0059 §決定2）。トークンと字数の比はトークナイザに付く（ADR-0033）。

## 結果

- 新しいセッションで、目安に沿った長さが保たれる（測った範囲: 23 往復）。
- 未設定のキャラクターは何も変わらない。
- 縮んだ会話を戻す手はまだ無い（follow-up）。
- 削れない枠が最悪ケースで 277 バイト増える（下限・上限とも 9999）。削れない枠に足せる量（`FIXED_FRAME_SLACK`）は 360 から 83 に減る。すべての欄を上限いっぱいにしたキャラクターでは、既定の予算で古い側の履歴が削られ（最新の4件が残る）、取り決めは1件も載らない（落とした件数は報告される / ADR-0051）。組み立ては失敗しない。文面は削らず、測った形のままにした。

## 追記（2026-11-19）: 目安は縮みを防がなかった

**§背景 2 の「字数の目安は新しいセッションで縮みを防ぐ」は言い過ぎだった。** その測定では、目安なしの対照（c0）も 23 往復で縮んでいなかった（最初の8往復に対する最後の8往復の比 0.77 / 1.67）。縮まない対照と比べても「防いだ」とは言えない。示せていたのは「数字の方向に長さが付いてくる」ことだけである。

この欄を入れた exe で、利用者が遊んだ（2026-11-16 未明、キャラクター tsubaki、目安 300〜600 字を最初から）。返答は往復1〜5 が 348〜475 字で、往復6 で 258 字、往復10 で 100 字まで縮み、59 往復まで戻らなかった。途中で目安を 500〜800 字に上げても戻らなかった。

縮んだ会話を戻す手は [ADR-0066](0066-the-end-token-is-lowered-once-a-session-has-shrunk.md) で決めた。この欄はそのまま残し、ADR-0066 が「下限を割ったか」の判定に使う。
