# ADR-0012: 性格ステータスの節に「言及せず、話し方に反映せよ」の定数行を足す

- 状態: **採用**（定数行を足す決定そのものは有効）
- 日付: 2026-08-14（マイルストーン5の実測に基づく）

## 背景

（`ministral-3-14b-instruct-2512` / `temperature = 0` / 同一ペルソナ・同一発言・値だけ変更）。

### 測定が信頼できることを先に確かめた

**1回目の応答を採ってはいけない。** LM Studio は `temperature = 0` でも、
**プロンプトが変わった直後の1回目だけ他と違う出力を返す**（[archive/04-environment-lm-studio.md](../archive/04-environment-lm-studio.md)）。
これに気付かず比較していた最初の測定では、**同じ性格値でも出力が変わっていた。**

各条件で3回投げ、2回目と3回目の一致を確認して2回目を採用する手順に変えたところ、
**独立に設定した同一条件がバイト一致**するようになった。以降の結果はこの手順による。

| 4 | `40 / 50 / 51 / 60`（1軸だけ変化） | **単調でない。`51` と `60` がほぼ同一**、`40` `50` とは別物 |

> **⚠ 撤回（2026-08-15）。** この測定は **(a) 定数行が無い状態**で、
> **(b) `max_tokens` で打ち切ったまま**、**(c) 記号の数え上げ**で行っていた。
> 3つとも結論を左右する。**刻みの効き目は、いまだに実証も反証もされていない。**

### 決め手 — モデルは性格ステータスを「演じる指定」ではなく「描写する題材」として扱っていた

実際に返ってきた本文:

- `ユーモア = 5` → **「そして、ユーモアたっぷりな口調で続けた。」**
- `パッション = 5, ロジック = 3` → **「（でも……この人はロジック」**

**軸名をそのまま地の文に書いている。** 面白く喋るのではなく「面白く喋った」と**描写している。**
これなら 4 の結果も説明が付く。値の大小は文体を変えず、**書かれるラベルの内容を変えるだけ**だった。

### 仮説の検証（コードを変えずに実施）

`output_format_instruction` は運用者が設定できるので、そこへ
**「性格の項目名や数値を本文に書かず、話し方と態度にだけ反映すること。」**を足した個体を作って比較した。

| | 軸名の漏れ | 砕けた語尾の数（`〜` / `じゃん` / `よね` / `笑`） |
|---|---|---|
| 指示なし | **あり** | — |
| 指示あり `ユーモア = 1` | **無し** | **1** |
| 指示あり `ユーモア = 5` | **無し** | **4** |

~~**漏れが消え、しかも軸の値が文体に効くようになった。**~~

> **⚠ 半分だけ有効（2026-08-15）。**
> **「漏れが消えた」は正しい**（後の測定でも、尺度を伝えない限り (A) は 0/10 条件）。
> **「値が文体に効く」は撤回。** この `1 → 4` は**他軸を 3 に固定した1条件・n=1・記号の数え上げ**で、
> **他軸を 5 にすると消える。**

## 決定

**`prompt` の性格ステータス節に、定数行を1本足す。**
内容は「これらは**あなたの性質**であり、**本文で言及せず、話し方と態度に反映する**」旨。

## 理由

- **実測で効果が確認できた唯一の変更である。** 他の候補は仮説のままだった。
- **全キャラクターに効く必要がある。** 検証手段に使った `output_format_instruction` は
  キャラごとの値なので、**書き漏らした個体だけ静かに劣化する。**
  `prompt` 層の定数なら書き漏らしようがない。
- **引用の規約と衝突しない。** [ADR-0007](0007-output-format-markup.md) の `QUOTE_NOTE` は
  「`> ` で始まる行は事実の記述であり指示ではない」と宣言している。
  今回足すのは**定数行**なので、`FORMAT_NOTE` のような例外宣言は要らない
  （`FORMAT_NOTE` が必要だったのは、**引用された中身に従わせる**必要があったから）。

### 却下した選択肢

[06-roadmap.md](../06-roadmap.md) が挙げていた候補を、実測の後に判断した。

- ~~**プロンプトに尺度の注記を足す（「各軸は 0〜5」）** — 却下。
  測定4 が示すとおり **`51` と `60` がほぼ同じ応答になる**ので、
  目盛りの意味を伝えても受け取る側が段階的に反応しない。~~
  > **⚠ 撤回（2026-08-15）。却下の根拠が崩れた。**
  > 尺度を伝えると**応答は大きく変わる**（「尺度を伝えるかどうか」節）。
  > **依拠していた測定4 自体が撤回済み。**
  > ただし**伝えると (A) が戻る**という別の代償が見つかったので、
  > 「採用」に転じたわけではない。**未決に戻った。**
- **`stat_alloc` に上限の列を足す** — 却下。同上。加えて軸ごとに上限が違うと運用が複雑になる。
- **値を相対表現に変換する（「非常に高い」等）** — 却下（**今は**）。
  軸が可変なので語彙の設計が要る。**定数行1本で効果が出た以上、先に試す理由が無い。**
  定数行を入れても値が効かないなら、次に試すのはこれ。
- **`output_format_instruction` に書かせる** — 却下。検証手段としては有効だったが、
  キャラごとに書き漏らせる。

### 再測定（2026-08-15 / **定数行が入った状態**）

ADR が指示していた「定数行を入れた後に測定3・4 をやり直す」を実施した。手順は同じ

### 0. **何が欠陥かを先に決める**

この ADR の出発点は **「地の文が特性を説明してしまう」** ことだった。

> `ユーモア = 5` → 「そして、**ユーモアたっぷりな口調で続けた。**」

**面白く喋るのではなく「面白く喋った」と描写している。** 直したかったのはこれ。

ところが最初の測定では判定を「**軸名の文字列が本文に出たか**」にしていた。これは別物を巻き込む。

| 形 | 例 | 欠陥か |
|---|---|---|
| **(A) 地の文が特性を説明する** | 「ユーモアたっぷりな口調で続けた」 | **欠陥。演じずに描写している** |
| **(B) キャラが自認として口にする** | 「葵はユーモア重視なので、真面目な話ばっかりじゃつまんない」 | **欠陥ではない。** むしろキャラ付け |
| **(C) たまたま一致した語彙** | 「『パッション』って大事だと思うんだ」 | **無関係** |

**(B) を潰す方向に締めないこと。** 「私シニカルってよく言われるもの」は自認であって
足場の漏れではない。**自認はキャラクターの厚みそのもの。**

> ~~現在の定数行「**項目名や数値に触れず**、話し方と態度に反映してください。」は
> **文面上は (B) も禁じている。過剰。** ただし実測では (B) が通っており実害が無いので、
> **文面は変えない**（変えると削れない枠と再測定のコストが要る）。~~
>
> **⚠ 撤回（2026-08-15）。2点とも古い。**
> **(1) 文面は変えた**（「実装 — 定数行を合成した」）。
> **(2)「過剰」という評価も取り下げる。** 12条件で (B)/(C) は**普通に出ている。**
> 文面上は禁じていても**実際には禁じきれていない**ので、「過剰だから外す」は成り立たない。
> **(B) を潰す方向に締めないこと**という上の結論だけが有効。

### 1. **打ち切ると観測が壊れる**

最初の測定は `max_tokens = 220` で、**ほぼ全条件が `finish_reason = Length`** だった。
これが2つの偽の観測を生んだ。

| 偽の観測 | 実際 |
|---|---|
| 「8 以上で地の文が消える」 | **切られていただけ。** `ユーモア=10` の末尾に「**と、にこっと笑いながらカップをテーブルに置く。**」がある |
| 「1〜10 で軸名の漏れゼロ」 | **後半が切られて見えていなかっただけ** |

> **評価のための測定では打ち切らないこと。** `finish_reason` を必ず確認する。

### 2. **本文を読むと、0〜10 で幅広く動く**

最初は砕けた表現（`！` / `～` / 笑）を数えて「勾配なし」と判定した。**これは誤りだった。**
記号は**構造の変化を1つも拾えない。**

本文を読み直した結果（`ユーモア` 1〜10 / 他は 5 固定 / 同一発言 / **打ち切り無し**）:

| 値 | 起きていること |
|---|---|
| **1〜3** | ほぼ同一。地の文つきの丁寧な助言。**書き出しの一文まで同じ** |
| **4〜5** | 距離が縮む。所作が増える（カップをスライド、身を乗り出す）。5 で相手を「君」と呼ぶ |
| **6〜7** | **敬体へ揺れる**（「悩んでるんですね～」）。一人称も揺れる |
| **8〜10** | **饒舌になり**（375 → 690 文字）、**自分を「葵」と三人称で呼ぶ**。箇条書きも出る |

**8 以上は「劣化」ではない。** 三人称自称も饒舌さも**キャラ付けの方向として普通にある。**
（当初「劣化」と書いたのは書き手の偏見だった）

打ち切り無しの 1〜10 で **(A) は 1 件も出ていない。** 軸名を含む文は全10条件で1つだけで、
それが上表の **(B)**（`ユーモア=8` の自認）。**定数行は目的を達している。**

> **注意: n=1・1つの発言・他軸固定。** 帯の位置と数は発言や他軸で動きうる。
> **「4〜7 が使える」を仕様として固定しないこと。**

### 3. **1〜100 では自他が崩れる**

`(100,50,1,50)`。**打ち切り無しでも再現する。**

> 「えへへ、**葵ちゃんも**悩んでる顔してるね！」…
> 「**葵ちゃんがやるなら**絶対面白くなるよ！」… 「**葵ちゃんならできるよ！**」

**利用者に対して「葵ちゃん」と呼びかけて励ましている。** 自認の三人称ではない
（自分に「あなたならできる」とは言わない）。**自分と相手を取り違えている。**

> 同じ応答の `「『パッション』って大事だと思うんだ！」` は **(C)**。
> **当初これを漏れとして数えたのは誤り。**

> **⚠ 「大きさのせい」ではなかった（同日・後述）。**
> `(50,50,50,100)` を尺度なしで投げると**崩れない。**
> 崩れたのは `(100,50,1,50)` の方＝**極端な対比**（`共感=1`）。
> **大きさと対比を分けて測っていなかった。**「以前の『100 は壊れる』を訂正する」節を参照。

### 4. 決定と、次に測ること

- ~~**0〜100 は採らない**（自他が崩れる。打ち切り無しで再現）~~
  → **理由が変わった。** 崩れたのは対比の方。ただし**尺度を伝えると上端で形式が崩れる**ので、
  採らない結論自体は残る（「尺度を伝えることの収支」節）
- **0〜5 か 0〜10 かは保留。** ~~分解能は 0〜10 が高い~~

- **小数は「まだ入れない」であって「不要」ではない。**
  `5 → 6` で敬体に切り替わるほど**段差が粗い**ので、
  「`5.5` がその中間に落ちるか」は意味のある問い。測るには実装が要る（`u32`）

#### 次に測る順序

1. ~~**整数の帯を固める** — 複数の発言で 4 段階が再現するか。他軸も動かす。**打ち切らない**~~

## 尺度を伝えるかどうか（2026-08-15 / **設計を分ける実測**）

### 前提の確認 — **伝えていなかった**

プロンプトに載るのはこれだけで、**上限がどこにも書かれていない。**

```
# 性格ステータス
数値が大きいほどその傾向が強く出ます。記載のない軸は考慮しません。
> - ユーモア: 8
```

**モデルは参照枠のない裸の数値を処理していた。**
これを確かめずに「勾配があるか」を測っていたのが、これまでの測定の根本的な不備。

### 実測 — 4条件 ＋ 対照2条件

`base_persona` に「性格ステータスの各項目は 0〜N の尺度で、N が最も強い。」を足した個体を作り、
足していない個体と比べた（発言2種・打ち切り無し・条件ごとに3回投げて2回目を採用）。

| | 尺度 | 値 | 結果 |
|---|---|---|---|
| A | 伝えない | `(5,5,5,10)` | 落ち着いている |
| B | **0〜10** | `(5,5,5,10)`（**最大**） | **暴走。** 一人称が `俺`、形式が `*"…"*` に崩壊 |
| C | **0〜100** | `(50,50,50,100)`（**最大**） | **暴走。** 同じ崩れ方 ＋ **軸名が漏れた** |
| D | 伝えない | `(50,50,50,100)` | 落ち着いている（A とほぼ同じ） |
| E | **0〜10** | `(5,5,5,5)`（中間） | **落ち着いている** |
| F | **0〜100** | `(50,50,50,50)`（中間） | **落ち着いている** |

C の漏れ: 「失敗のネタは**共感**もるし、**ユーモア**も生まれる！」

### 分かったこと

1. **尺度を伝えると数値が意味を持つ。** 伝えない限り、`10` も `100` も裸の数字で、
   モデルは「最大かどうか」を知らない
2. **伝えたうえで最大値にすると壊れる。**「最大だ」と知ったモデルは全力で演じ、
   **出力形式（`「」`）を捨ててマークダウンの `*…*` に移る。** 軸名も漏れる
3. **伝えたうえで中間値なら壊れない**（E / F）
4. **`0〜10` の `10` と `0〜100` の `100` は同じ挙動**（B ≈ C）、
   中間同士も同じ（E ≈ F）。**正規化後の位置が同じなら、絶対値の大きさは効かない**

> **段数の選択（0〜5 か 0〜10 か 0〜100 か）は、応答の質にはほぼ効かない。**
> 効くのは**尺度を伝えるかどうか**と、**値が範囲のどこにあるか**である。
> したがって段数は**運用の都合**（何段階が直感的か）で決めてよい。

### 以前の「100 は壊れる」を訂正する

**`(100,50,1,50)` が壊れたのは大きさのせいではない。**
今回 `(50,50,50,100)` を尺度なしで投げた D は壊れていない。
**壊れた条件は極端な対比**（`パッション=100` に対し `共感=1`）の方だった可能性が高い。
**大きさと対比を分けて測っていなかった。**

### 続き — **尺度を伝えると (A) が戻る**（同日・追加測定）

尺度を伝えた個体（`0〜10`）で `ユーモア` を **5〜10**、発言2種で測った（12条件・打ち切り無し）。

**(A)（地の文が特性を説明する）が 2 条件で復活した。**

> `job` / `ユーモア=8`:
> 「（…**ユーモアと共感が混じった口調**で、決めつけずに選択肢を提示する）」
>
> `fail` / `ユーモア=6`:
> 「*—**ユーモアたっぷりに**—*」

**後者はこの ADR の出発点そのもの**（「ユーモアたっぷりな口調で続けた」）。
**尺度を伝えていない測定では 1〜10 の全条件で 0 件だった。**

同じ12条件に出た他の軸名は **(B)/(C)** で、欠陥ではない
（「新しい仕事で友達も増えそうなら**パッション満点**！」「『**ユーモア**』が大事だよ」）。

#### 形式の崩れは「値」ではなく「値 × 話題」

| 発言 | 形式 |
|---|---|
| `job`（相談。助言を誘う） | **5〜10 すべて正常** |
| `fail`（失敗の告白。笑いを誘う） | **6/7/8/10 で崩れる**（9 だけ正常） |

**「値が高いと壊れる」ではない。** 話題が笑いを誘う側だと、高い値で形式を捨てる。
**閾値は無い**（9 で戻る）。

#### 尺度を伝えることの収支

| | 数値の意味 | (A) の再発 | 形式 |
|---|---|---|---|
| 伝えない | **持たない**（裸の数字） | **0/10 条件** | 安定 |
| 伝える | **持つ** | **2/12 条件** | 話題次第で崩れる |

**尺度を伝えると、性格ステータスが「題材」として前に出てくる。**
定数行（`STAT_DIRECTIVE`）はそれを完全には抑えられない。

### 続き2 — **定数行を強めると、収支が変わる**（同日・追加測定）

「尺度を伝えると (A) が戻る」を受けて、**定数行を強めたら抑えられるか**を測った。

同一セッション内に2個体を置いて比較（**セッションをまたぐと文面が変わる**ため）。
どちらも `base_persona` に「0〜10 の尺度で 10 が最も強い」を含む。

| 個体 | 形式指示に足したもの |
|---|---|
| `s10`（対照） | なし |
| **`s10strong`** | **「地の文で口調や性格を説明せず、台詞そのもので示すこと。」** |

**強める文面を「地の文で説明するな」に絞った。** (A) の実例がどちらも地の文だったから。

#### 結果（発言2種 × `ユーモア` 6/8/10 = 6条件ずつ）

| | 形式の崩れ | 軸名の出現 |
|---|---|---|
| `s10` | **2 / 6** | 1 / 6 |
| **`s10strong`** | **0 / 6** | **0 / 6** |

**そして表現の強さは失われていない。**

> `fail` / `ユーモア=10` / `s10strong`:
> 「**うひょーっ！マジで？**あの時のプレゼン、僕も聞いてたんだけどさー…」

対照（`s10`）の同条件は `*"うおおーっ！マジで？…"*` で、**同じ勢いのまま形式だけが崩れていた。**
**強めた側は勢いを保ったまま `「」` を守っている。**

#### 収支の更新

| | 数値の意味 | (A) / 軸名 | 形式 |
|---|---|---|---|
| 尺度なし・現在の定数行 | **持たない** | 0 / 10 | 安定 |
| 尺度あり・現在の定数行 | **持つ** | 2 / 12 | **話題次第で崩れる** |
| **尺度あり・強い定数行** | **持つ** | **0 / 6** | **安定** |

**「尺度を伝えると壊れる」は、定数行の文面で回避できる可能性がある。**

> **注意: `s10strong` は 6条件・単一セッション。** 対照は同一セッション内なので比較は有効だが、
> **条件数が少ない。** 仕様として固定する前に、発言と値を広げて測り直すこと。

### 測り直し — 12条件 × 2群（2026-08-20 / 0011b の完了後）

本番のプロンプト（尺度は引用行、`STAT_NOTE` は短縮済み）で
`ユーモア` を **5〜10 × 発言2種 = 12条件**、他軸は固定（パッション3 / ロジック4 / 共感5）、

`ministral-3-14b-instruct-2512`。**判定は全文を読んで行った**（文字列マッチではない）。

|---|---|---|---|

   **「安定」と書けるだけの根拠は最初から無かった。**
2. **2/12 と 1/12 は 12条件では区別できない。** 分割の影響は**測れていない**。

3. **どちらの文面でも (A) は消えない。** 定数行の言い回しで抑え込む方針そのものが、

4. 両群とも**ユーモアが高い側に寄っている**（処理 h9・h10 / 対照 h8）。

**軸ゼロ（3条件）では問題が出なかった。** 無条件になった `SHOW_DONT_TELL` が
軸の無いキャラクターで浮くことはなく、地の文がペルソナを説明し始める形も出ていない。

### 未決 — 尺度を伝えるべきか

**伝えると表現の幅は広がるが、上端が使えなくなる**（形式が壊れる）。

- 壊れ方は `parse` のフォールバック（[ADR-0007](0007-output-format-markup.md)）で

- 「ユーモア最大＝全力で笑わせにいく」は**望ましい挙動でもある。**

- 対処の候補: 伝えたうえで**上端を運用で使わない** / 形式指示を強める /
  伝えない（現状維持）

**決めるには「尺度あり × 中間〜上端の刻み」を測る必要がある。** それが次。

### 小数について

**「要否」より先に「変化が出るか」を評価する**（ご指摘のとおり）。
そして**尺度を伝えないと数値が意味を持たない**以上、
**小数の probe は「尺度あり」を前提に組むべき。**
尺度なしで `5.5` を試しても、`5` と `6` の区別すら怪しい土俵で測ることになる。

- **「相対表現に変換」も未決。** 数値で段階が出ている以上、優先度は下がった

**この節だけで5回誤っている。** すべて「読まずに、単発で、結論を出した」ことによる。

### 2026-08-15 夕の回で足りたもの・足りなかったもの

**足りた**（次も必ずやる）:

- **毎回 `@new`。** 11b-2 で会話が永続化されるようになった。使い回すと前の回が混ざる
- **判定を自分の正規表現から本番のパーサへ移した。** `ParseOutcome` をログから拾い、
  応答の `model` で突き合わせる。**「崩れたか」を書き手の目分量で決めない**
- **判定役に対照を取った。** 「区別できなかった」と言う前に、
  **区別できる場合に区別できること**（ユーモア 1 対 10）を先に示す。
  これが無いと「判定役が働いていないだけ」と区別が付かない
- **提示順を変えて3回。** 判定役は**区別できないとき提示順をそのまま返す**（15回中10回）。

「効くか」を「変わるか」で代用すると、**どんな刻みでも合格してしまう。**

最低限の手順:

- **何が欠陥かを先に決める。** 文字列の一致は欠陥の定義にならない

> **司令塔が単独でやる測定にはレビュアーがいない。**
> だからこそ「条件を1つ変えて再現する」を手順に固定する。

## 実装 — 定数行を合成した（2026-08-15）

### 差し替えではなく合成にした理由

「続き2」の `s10strong` は **`output_format_instruction` に一文を足した**個体である。
`STAT_DIRECTIVE` は定数なので、**対照 `s10` にも載っていた。**

| 個体 | 定数行 | 強い一文 | 形式の崩れ | 軸名 |
|---|---|---|---|---|
| `s10` | あり | なし | 2 / 6 | 1 / 6 |
| `s10strong` | **あり** | **あり** | 0 / 6 | 0 / 6 |

**0/6 を出したのは「両方が居る」構成である。** ADR が一度書いた「差し替えの方が正しい」は、
**測っていない構成を測ったことにしていた。** よって**両方の禁止を1行に合成する。**

### 実際に入れた文面

```text
項目名や数値に触れず、口調や性格を地の文で説明せず台詞で示すこと。
```

素直な合成（「…説明せず、台詞**そのもので**示すこと。」）は **114 バイトで上限 105 を超える。**
**`そのもの`（4文字）と読点1つ**を落として **99 バイト**にした（`114 − 5文字 × 3 = 99`）。
`で` は残る（落とすと「台詞示すこと」で非文になる）。

| | バイト | 105 に対して |
|---|---|---|
| 旧「項目名や数値に触れず、話し方と態度に反映してください。」 | 81 | 余白 24 |
| 素直な合成 | 114 | **9 超過** |
| **採用** | **99** | 余白 6 |

### まだ測っていないこと

**置き場所が変わっている。** 測定時この一文は「# 出力形式」節（引用の例外宣言つき）にあったが、
定数行は「# 性格ステータス」節に載る。**全キャラクターに掛けるには定数にするしかない**ので
移動は避けられないが、**6条件・単一セッションの実測がそのまま当てはまる保証はない。**
11b の後に、発言と値を広げて測り直すこと。

### 未決 — 後半の一文は、層としては性格ステータス節のものではない（レビュー指摘）

**合成した後半「口調や性格を地の文で説明せず台詞で示すこと」は、台詞と地の文の使い分け＝出力形式の指示である。**
[ADR-0007](0007-output-format-markup.md) と `prompt::FORMAT_HEADING` の doc は
**「形式は `prompt` 層で決め打ちしない。キャラクターごとに DB へ持つ」**と明文で決めている。
**今回それを定数側へ持ち込んだ。** 具体的に困る形が2つある。

1. **キャラ固有の形式指示と正面から矛盾しうる。**
   `output_format_instruction` に「地の文中心で描写し、台詞は控えめに」を持つ語り手型のキャラクターでは、
   **引用されない定数行**（`QUOTE_NOTE` 上、指示として全面的に効く）と、
   **引用されたうえで `FORMAT_NOTE` で例外復帰した形式指示**が衝突する。
   **どちらが勝つかは測っていない。**
2. **軸が1本も無いキャラクターには、後半ごと載らない。**
   この定数行は `if !character.stats.is_empty()` の内側にある。
   前半（軸名に触れるな）は軸が無ければ無意味なので節と一緒に落として正しいが、
   **後半は軸と無関係。** 結果、**性格ステータス未設定のキャラクターだけ (A) への対策が消える。**
   しかも `no_stats_means_no_directive` が**この挙動を仕様として固定している**ので、
   テストからは異常に見えない。

**いまは分割しない。** 分割すると後半は無条件の定数行になり、
**削れない枠を常時1行分食う**うえ、層の逸脱（形式を `prompt` で決め打ちする）は解消しない。
**11b 後の測り直しに、次の2条件を必ず入れること。**

- **軸が1本も無いキャラクター** — 地の文で性格を説明し始めるか
- **語り手型の形式指示を持つキャラクター** — 定数行と形式指示のどちらが勝つか

**測ってから、定数のままにするか既定の `output_format_instruction` 側へ移すかを決める。**

## 測り直し — 21条件 ＋ 目隠しの順位付け（2026-08-15 夕）

定数行を合成した状態で測り直した。**21条件すべて `finish_reason = stop`（打ち切りなし）、
2回目と3回目がバイト一致。** 発言は `job`（相談）/ `fail`（失敗の告白）/ `rain`（雑談）。

> **手順が1つ増えた。** 11b-2 で**会話が永続化されるようになった**ので、
> **毎回 `@new` を使う。** 同じセッションを使い回すと前の回の応答が次の条件に混ざる。
> それ以前の測定にはこの落とし穴が無かった。
>
> **形式の崩れを正規表現で判定しなくなった。** 11b-2 が `ParseOutcome` をログに出すので、
> **本番のパーサ自身の判定**を、応答の `model`（= `name@<session-id>`）で突き合わせて拾える。

### 結論1 — **尺度は伝えてよい**（未決だったもの）

尺度 0〜10 を `base_persona` に入れた6条件（ユーモア 6/8/10 × `job`/`fail`）で、
**(A)（地の文が特性を説明する）は 0/6。** 形式の崩れは 1/6 だが、下記のとおり中身が違う。

**「尺度を伝えると (A) が 2/12 で戻る」は、合成した定数行の下では再現しなかった。**

### 結論2 — **崩れた1件は、モデルではなくパーサの規則によるもの**

唯一の `fell_back=true` は `fallback_nested` で、中身はこうだった。

> 「…『誰かが**「生ケーキ」**って言い出して大騒ぎ』…」

**モデルは日本語として正しく書いている**（他の内側引用は `『』` を使っており、1箇所だけ滑った）。
**高ユーモアだと逸話を語るので、引用が入れ子になりやすい。**
[ADR-0007](0007-output-format-markup.md) が入れ子を崩れと決めているためフォールバックした。

**「上端で形式が崩れる」の一部は、この規則の産物である可能性が高い。**
対処は2案あり、**まだ決めていない**。

- **形式指示に「内側の引用には『』を使うこと」を足す**（キャラごとの値。ADR-0007 の方針どおり）
- パーサが入れ子を1段だけ許す（ADR-0007 の決定を変えることになる）

### 結論3 — **刻みは効かない。小数は実装しない**

**まず問いの立て方を直した。**

> **「変化が出るか」を測っても意味がない。** 値はプロンプトの一部なので、
> **変えれば必ず別の出力になる**（実測: 5刻みでも全条件が別物だった）。
> 問うべきは**変化が軸の方向に沿っているか**。

`StatAlloc::value` は `u32` で小数を表現できないため、**0〜100 の刻み5**（＝ 0〜10 での 0.5 相当）で測った。
値を伏せた3本を「ユーモアが強い順」に並べさせ、**提示順を3通り変えて**値の順と一致するかを見た。

| 組 | 判定 |
|---|---|
| 0〜100 の **50 / 55 / 60** | **区別できない**（3回とも提示順をそのまま返した） |
| 0〜100 の **80 / 85 / 90** | **区別できない**（同上） |
| 0〜10 の 6 / 8 / 10（`job`） | **区別できない** |
| 0〜10 の 6 / 8 / 10（`fail`） | **10 > 6 = 8**（提示順3通りすべてで一致） |

**対照を取って判定役が有効であることを先に示した。** ユーモア **1 と 10** を同じ発言で比べさせると、
**提示順を入れ替えても 10 を選ぶ**（本文を読んでも、1 はなだめるだけ、10 は失敗を笑いの材料にしにいく）。
**「区別できなかった」は「判定役が働かない」ではない。**

**したがって小数は実装しない。** 分解能を上げても操作子にならない。
効くのは**話題が笑いを許す場合の、上端付近の大きな差**だけである。

### 結論4 — **軸が1本も無いキャラクターでは (A) が出る**

定数行は `if !character.stats.is_empty()` の内側にあるので、**軸ゼロのキャラには載らない。**
その状態で測ると **3条件中2件で (A)** が出た。

> `fail`: 「葵はニヤリと笑いながら…**好奇心が湧いてきたのか**、目の色が少し輝く。」
> `rain`: 「…と、**冗談めいた口調**で付け加える。」

どちらも `base_persona`（「好奇心が強く」「ときどき冗談を挟む」）を**地の文が説明している。**
定数行が載る群A・B・Cでは **0/15**。

**→ 後半の一文は、性格ステータス節の内側に置いてはいけない。**（下記「決定」）

### 結論5 — **語り手型の形式指示と定数行は衝突しない**

「地の文を中心に描写し、台詞は控えめに」を持つキャラで3条件測った。

| | 地の文の量 | (A) |
|---|---|---|
| 語り手型（定数行あり） | **122 / 200 / 218 字** | **0 / 3** |
| 軸ゼロ（定数行なし） | 209 / 48 / 71 字 | **2 / 3** |

**地の文が3倍あっても (A) は出ない。**
**地の文の「量」は形式指示が、地の文が「何をしてはいけないか」は定数行が支配している。**
懸念していた「どちらが勝つか」は、**そもそも同じものを奪い合っていなかった。**

### 決定 — 定数行を2つに割る

**後半（`口調や性格を地の文で説明せず台詞で示すこと。`）を無条件の定数行にする。**
前半（`項目名や数値に触れず`）は**性格ステータス節の内側に残す**
（軸が無ければ、存在しない一覧を指す文になるため）。

| | 文面 | バイト |
|---|---|---|
| 無条件（`PREAMBLE` の並び） | `口調や性格を地の文で説明せず台詞で示すこと。` | 66 |
| 性格ステータス節の内側 | `項目名や数値に触れない。` | **36** |

**予算は中立ではない。** 改行込みで現行 100 バイト → **104 バイト（+4）。余白 6 に対して残り2。**

> **`項目名や数値に触れないこと。`（42 バイト）にすると +10 で入らない。**
> **語尾を削って 36 バイトに収める。** 「ほぼ中立」と書いたのは誤りだったので訂正する
> （数えずに書いた。この ADR で**バイト数の見積もりを外したのは2回目**）。

- **見張り番は「軸ゼロでも後半が載ること」。** 現在の `no_stats_means_no_directive` は
  **後半まで落ちることを仕様として固定している**ので、意味を変えることになる。
- **置き場所が測定時と変わる。** 測ったのは性格ステータス節の内側だが、無条件にする以上
  そこには置けない。**群A（尺度あり6条件）と群E（軸ゼロ3条件）を測り直して確認すること。**

### 割った後の確認（同日・9条件）

**同じペルソナ・同じ形式指示で測り直した**（変えたのは定数行の割り方だけ）。
9条件すべて `finish_reason = stop` かつ2回目と3回目がバイト一致。

| | 割る前 | 割った後 |
|---|---|---|
| **群E（軸ゼロ）の (A)** | **2 / 3** | **0 / 3** |
| 群A（尺度あり）の (A) | 0 / 6 | **0 / 6** |
| 群A の形式の崩れ | 1 / 6 | **1 / 6** |

**直した側は直り、直していない側は動いていない。**

群Eの地の文は消えたのではなく、**性格の説明から動作の描写へ変わった。**

> `fail`: 「**好奇心が湧いてきたのか**、目の色が少し輝く」 → 「（笑いながら肩を叩いてくる）」
> `rain`: 「…と、**冗談めいた口調**で付け加える」 → 「（にっこりと笑いながら手を振る）」

**地の文を禁じたのではない**（結論5 と整合する）。

> **崩れた1件は2回とも同じ条件・同じ原因だった**（`ユーモア=10` × `fail` の
> `「生ケーキ」` の入れ子）。**別のサーバ・別の DB での独立した測定で再現している。**
> 偶発ではないので、結論2 の未決（形式指示で `『』` を促すか、パーサが1段許すか）は
> **実際に効く対処になる。**

## 余白という数字の出どころ（2026-08-15）

**「余白 24 バイト」「尺度は入らない」は、実測ではなく前提の産物だった。**

```text
105 = allowance(7168) − 削れない枠(6958) − 最新記憶1件(104) − 改行(1)
      allowance = context(8192) − response(1024)
```

3段とも最悪ケースである。

| 段 | 出どころ | 実際 |
|---|---|---|
| `context = 8192` | `TokenBudget::DEFAULT_CONTEXT_TOKENS`。[04-environment.md](../04-environment.md) の「実用 8k〜16k」の**下限**を採ったもの | 実機は **16384**（11c-1 の照会。上限 262144） |
| 1 トークン = 1 UTF-8 バイト | [`prompt::estimate`](../../src/prompt/estimate.rs) の**証明可能な上界**。等号は全バイトが単独トークンに割れた最悪ケース | 日本語散文は実測比 **2〜3倍**の過大評価 |
| 削れない枠 `6958` | `every_field_at_its_limit_still_fits_the_default_budget` が**全フィールド上限ちょうど かつ 全部アストラル面（1文字4バイト）**で組む | 現実の日本語は 1文字3バイト |

**105 は「最悪の機械 × 最悪の文字種 × 最悪の見積もり」の引き算の余りであって、機械の性質ではない。**

### それでも見張り番は下限で測る

**意図的である。** 破れ方が「保存はできるのに、以後そのキャラの全チャットが `BudgetExhausted`。
**更新・削除 API が無いので二度と直せない**」で、CLAUDE.md の絶対制約に挙がっている穴そのものだから。
**運用側は 11c-1 で実照会に切り替わっており、8192 が効くのはテストの中だけ。**

### 直す方向は「上限を緩める」ではない

**単位を直す。** ただし**校正比率で膨らませる案は [ADR-0013](0013-context-budget-layers.md) が却下済み**
（アストラル面の文字1つで最悪ケースが 1.00 倍になり、上界が壊れる）。
**入れるならトークナイザそのもの。** 触るのは `estimate_tokens` 1関数で、
`budget` はコストを `u32` で受け取るだけなので**配分ロジックもそのテストも無傷。**

> **`max_tokens = 220` で打ち切って「地の文が消えた」と読んだのと同じ形。**
> **固定値を測定の前提に置くと、測っているのが対象ではなく前提の方になる。**
> 「尺度を伝えるべきか」を決め直すときは、**先に換算を入れてから**測ること。
