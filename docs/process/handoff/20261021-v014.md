## 3. この期間に分かった、運用の形

- **グローバルの CLAUDE.md（2026-10-09 版）が、シェルでのファイルの書き換えを禁じた**（EDR の `kill_process` を誘発する）。変異は「`cp` した複製に Edit ツールで当てる」に変えた（CLAUDE.md §4）。**レビュアー（`rust-reviewer`）は Edit ツールを持たないので、変異を当てられない** —— 「当てるべき変異」を挙げさせ、作業者か司令塔が当てる。
- **変異のテストは関係するバイナリに絞る**（全部を回すと1本18分）。依頼に書かないと全部を回す。
- **前景の Bash が上限に当たっても、裏で動き続ける**（待ちが積み上がった）。長い待ちは `run_in_background` で。
- **exe を起こすときは `PERSONACORE_UPSTREAMS` も隔離する**（`PERSONACORE_DB_PATH` だけ変えた作業者が、利用者の本物の llama を起こした）。
- **作業者の報告が届かないことがある**（コミットはしてあった）。「報告だけ送れ」で取れた。依頼に「最後に必ず報告を送ること」と書く。
- **測定のエージェントは、ログの一部（起動時の警告）だけを見て誤った結論を書いた**（「全部 8192 の前提」→ 実際は 10 秒後に 16384）。結論の前にログを最後まで読ませる。
- 利用者の DB（`%LOCALAPPDATA%\personacore\`）は、司令塔のシェルからも読めた（MSIX の振り替えの対象外だった）。**写しを取って測るのは、利用者の了承を得てから。**
- 測定の置き場所: `<measurements>\b59-99981812\`（原因の切り分け）、`b59b-99981812\`（まとめ・要旨・約束の腕）、`b59c-99981812\`（サブ LLM の分類と書き直し）。
