# ADR-0035: 中継の見張りは「報告する」。打ち切りは緩い天井と人が決める

- 状態: **採用**（[ADR-0019](0019-relay-idle-watchdog.md) §3 を**置換**）
- 日付: 2026-08-26
- 関連: [ADR-0019](0019-relay-idle-watchdog.md)（§4 は**そのまま生きている**） /
  [ADR-0036](0036-the-range-of-machines-is-a-constraint.md)（**この判断を一般化したもの**） /
  [ADR-0032](0032-upstream-frame-is-a-precondition.md) / [ADR-0034](0034-extraction-asks-per-subject.md)

## 背景

### 30 秒は、この機のトークン間隔から出た数だった

[ADR-0019](0019-relay-idle-watchdog.md) §3 の根拠は**そのまま引くとこうである:**

> **通常のトークン間隔はローカルで数十ミリ秒。3桁の余裕がある。**

**「数十ミリ秒」はこの機（RTX 4070 / 14B が VRAM に載る）の値。**
**3桁の余裕は、その1台の上でだけ 3 桁である。**

### ⚠ そして ADR-0019 は、自分で反例を書いている

同じ節の直後にこうある:

> **フェーズ3で見直す。GPU を画像生成と取り合うと、
> トークン間が 30 秒を超えることがありうる（未実測）。**

**「超えうる」と書いてある値を、打ち切りの権威として使っている。**

### 反例はほかにもあり、どれも異常ではない

| 起きること | なぜ異常ではないか |
|---|---|
| **`Max Concurrent Predictions > 1`** | 上流が時分割する。**自分の流れが飢えるのは混雑であって停止ではない。** しかも**設定で起き、API に出ない**（[ADR-0032](0032-upstream-frame-is-a-precondition.md)） |
| **VRAM に載らない機** | CPU オフロード。**トークン間隔は秒〜十数秒。** スワップが絡めばさらに |
| **蓋を閉じる / スリープ / 省電力** | **壁時計の空白はいくらでも伸びる。** モデルは何もしていない |
| **思考を流さない上流** | 実装によっては**思考中は1トークンも出ない** |
| **画像生成との取り合い** | ADR-0019 自身が書いている（フェーズ3） |

### ⚠ 本題 —— **外から「遅い」と「死んだ」は区別できない**

**これは測り方の問題ではなく、原理的に区別が付かない。**
**つまり正しい定数は存在しないし、正しい適応も存在しない。**
**観測から適応させても、外したときにターンが死ぬことは変わらない。**

### 代償が非対称である

| | 起きること |
|---|---|
| **打ち切る** | **そのターンは1行も保存されない**（[ADR-0019](0019-relay-idle-watchdog.md) §4）。**破壊的** |
| **待つ** | 接続が1本ぶら下がる。**安い** |

**安い側を、当たらない推測で選んでいた。**

## 決定

### 1. **[ADR-0019](0019-relay-idle-watchdog.md) §3 を撤回する。中継は固定の秒数で打ち切らない**

`relay::IDLE_BUDGET` は**打ち切りの権威をやめる。**

### 2. **見張りは残す。役目を「打ち切る」から「言う」へ移す**

**一定時間（既定 30 秒）トークンが来なかったら `warn` を1本出す。中継は続ける。**

**これが本題である。値を消すのではなく、外れても壊れない場所へ移す。**
**外れた場合に起きるのは「余計なログが出る」か「出ない」だけで、ターンは死なない。**

### 3. **打ち切りの天井は `llm` 層が持つ。そこだけ設定可能にする**

`DEFAULT_IDLE_TIMEOUT`(180秒) / `DEFAULT_REQUEST_TIMEOUT`(300秒) が天井になる。

**つまみは `PERSONACORE_LLM_IDLE_TIMEOUT`（秒）1つだけ**で、
**残り3つ（全体上限・照会・接続）はそこから導出する**（実装 / 2026-08-27）。
**`0` は受け付けない** —— 導出した接続の上限まで 0 に潰れ、**上流への接続を1度も試みなくなる**ため。
**上端は縛らない**（大きすぎる天井が起こすのは「待たされる」だけで、それは §決定4 のとおり人が決める）。

> ## ⚠ **この天井は、無通信のときにしか効かない**（2026-08-27 / B-6 のレビューが発見）
>
> **全体上限（`request_timeout`）はストリーミングに適用されない**（`llm/lmstudio.rs` の doc が明言）。
> **残る歯止めは `read_timeout` だけで、これは「1回の読み取り」の上限。**
>
> **つまり上流がコメント行（`: keep-alive`）や部分行を細く送り続けると、
> `read_timeout` は毎回リセットされ、`events.next()` は永久に返らない。**
> **B-6 の前は中継の 30 秒がこれを切っていた**（`events.next()` 単位の予算だったので）。
> **いまは `warn` を出しながら無限に回り続ける。**
>
> **⚠ つまり「打ち切りの天井は `llm` 層が持つ」は、この形には成り立たない。**
>
> **受け入れる。** 理由はこの ADR の主題そのもの ——
> **待つのは安く、止めるのは人**（§決定4）。**そして画面の「中止」は在る。**
> **クライアントが切れれば SSE が drop されて上流の接続も落ちる**ので、
> **残るのは「繋いだまま待ち続けるクライアント」だけ**で、それは待っている人が居る場合である。
>
> **⚠ ただし、非対話のクライアントには止め手が無い。**
> **絶対上限を足すなら、その数はまた機械に依存する**（1応答の長さは機械で桁が変わる）ので、
> **[ADR-0036](0036-the-range-of-machines-is-a-constraint.md) の言い方だと「痛んだら測る」側。**
> **ロードマップ B-10 に積んである。**

**⚠ この2つには根拠となる計測が無い**（`llm/lmstudio.rs` の doc が明言している）。
**根拠が無く、外すと破壊的で、こちらからは導出できない。**
**その3つが揃った値だけを設定可能にする。**

> **⚠ つまみは無料ではない。** 起動時に決めるものを増やすと、
> **本番の入口を通るテストを足さない限り配線が観測対象から外れる**
> （`App::bind_with_client` の実例 / CLAUDE.md）。
> **足すつまみ1つにつき、`App::bind` を通る見張り番を1本足すこと。**

### 4. **「もう待たない」を決めるのは、待っている人**

~~**画面に停止を置く。** 中断の配線は D-1 で既に入っている~~
~~（画面を離れると `AbortSignal` が飛び、その回は保存されない）。~~

> **⚠ 訂正**（2026-08-27 / B-6 の着手前に司令塔が実測）。**「置く」ではない。もう在る。**
> **`ChatView.svelte` の「中止」ボタンは D-1 で入っており、`chat.ts` 側の中止の結末は
> D-0b の `chat-abort.test.ts` が4通り押さえている。**
> **残っているのは、ボタンそのものを見る見張り番だけ**
> （押したら `controller.abort()` が呼ばれること／送信中でなければ押せないこと）。

**⚠ それでも「緩めるのと同じ作業単位で」は変えない。**
**打ち切りを緩める側だけ入れて、人が止める側が壊れていたら、利用者はただ待たされる。**
**押せば止まることを、この作業単位で実際に確かめること。**

### 5. **見張りの秒数は設定にしない**

**決定2 で「言うだけ」になったので、外しても壊れない。**
[ADR-0019](0019-relay-idle-watchdog.md) §3 / [ADR-0020](0020-context-length-requery.md) §2 の
**「設定可能にしない」の理由（つまみ1つに見張り番1本）はここでは生き続ける。**

## 理由

### 却下した選択肢

- **別の固定値に差し替える**（60 秒 / 120 秒）—— **同じ誤りを別の数で繰り返すだけ。**
- **観測から適応させる**（直近の最大 × 係数）——
  **打ち切りの権威である限り、外れればターンが死ぬ。**
  **「正しい適応は存在しない」に当たる。**
  **⚠ ただし決定2 の「言う値」を賢くする余地は残る**（言うだけなので外しても安全）。
- **見張りを消す** —— **停止が観測できなくなる。**
  `[DONE]` を受けずに黙る上流は実在し、**それを数える手段が要る。**
- **[ADR-0019](0019-relay-idle-watchdog.md) §4 を開けて「未完でも保存する」** ——
  **打ち切りが安くなるので、逆向きの解き方になる。**
  **§4 には理由がある**（言いかけの文を、次のターンでモデルが自分の発言として読む）。
  **今回は触らない。**
  > **⚠ この ADR は §4 に依存している。**
  > **§4 を開けるなら、この判断も測り直すこと。**

## 結果

### 得られるもの

- **混雑・CPU オフロード・スリープ・画像生成との取り合いで、ターンが死ななくなる。**
- **[ADR-0034](0034-extraction-asks-per-subject.md) の行列の危険が「遅い」に落ちる** ——
  抽出が2本になっても、**壊れるのではなく待つだけになる。**
- **値を外しても壊れない。** これは**この機以外で動かすための前提**
  （[ADR-0036](0036-the-range-of-machines-is-a-constraint.md)）。

### 諦めたもの / 前提

- **⚠ 停止の検出が遅くなる。** 30 秒 → 天井（180 秒）。
  **見えるのは `warn` と、画面の停止ボタンだけになる。**
- **⚠ 天井を超えれば、やはりターンは死ぬ。** **無くしたのではなく、遠ざけた。**
- ~~**⚠ 停止ボタンが無い間は、緩めたぶん待たされるだけになる**（決定4）。~~
  **→ ボタンは既に在った**（決定4 の訂正）。**残っていたのは、それを見る見張り番だけ。**
- **⚠ `QUEUE_SAFE_MAX_EXTRACTION_RESPONSE_TOKENS`(368) の導出が宙に浮く。**
  **あれは「`IDLE_BUDGET` 30 秒に対する余裕」から出た数**なので、
  **30 秒が打ち切りでなくなると根拠が変わる。**
  **→ 導出をやり直すか、天井を基準に読み替えるかを決めること**（ロードマップ B-5 / C-2）。
