# ADR-0043: 作業単位は GitHub Issue で開き、`Closes #N` で閉じる。ロードマップは順番と理由を持つ

- 状態: **採用**（2026-09-18 / 利用者が「そろそろ `gh` を使って Issue ドリブンに移行したほうがよい」と提起し、同日に移行した）
- 日付: 2026-09-18
- 関連: [ADR-0012](0012-stat-section-directive.md)（**同じ発見を2箇所に書かない**、の実例になった回）/
  [08-work-log.md](../process/08-work-log.md)（**2回崩れた台帳**）/ [06-roadmap.md](../06-roadmap.md)（**この ADR が役目を絞る文書**）

## 背景 —— **「済んだ印を付ける場所」が2つあって、2回とも片方が止まった**

この家は作業単位に `B-48` のような番号を振り、**開いている一覧と済んだ印を [06-roadmap.md](../06-roadmap.md) の表に、経緯を [08-work-log.md](../process/08-work-log.md) の台帳に**書いてきた。

**台帳は2回止まった。** 1回目は 2026-08-26〜27 の2日（司令塔が気づいて足した）。2回目は **2026-08-28 から 2026-09-18 までの3週間**で、
**その間に済んだ作業単位（B-14〜B-50 / C-11〜C-19 / D-8〜D-12a / E / F / G / A-3a / A-7）は1つも台帳に無い。**
済んだ印はロードマップの表にだけ付いていた。**印を付ける場所が2つある限り、片方は必ず止まる**（2026-09-18 に台帳を閉じた理由）。

**ロードマップの表にも実害があった:**

- **1284 行の中に、開いている行が取り消し線の海に沈んでいる。** 2026-09-18 の棚卸しで「開いている行」を数えるのに、`grep -v "~~"` を掛けて目で拾う必要があった。
- **済んだ印が付いていない行から、作業単位が生まれた**（`B-22（新）` / 2026-09-03。**作業者が着手前に確かめて、実装せずに差し戻した**）。
- **レビューで出た穴の要約が行に書き足されて、行が数百文字になる。** 「何をやるか」と「何が分かったか」が同じセルに同居している。

**利用者の提起（2026-09-18）:** `gh` で Issue ドリブンへ。**併せて、docs・プラン・Git の外にある要素を整理する。**

---

## 決定

### 1. **開いている作業単位 ＝ open な Issue。1作業単位1 Issue**

- **題名は `<番号>: <短い名>`**（例 `B-48: モデルは、自分が前のターンで書いた ** を履歴で見続ける`）。
  **この家の番号（`B-48` / `F-4b-1`）は残す** —— docs とコミットの散文はその綴りで参照しており、Issue 番号より意味を運ぶ。
- **ラベルは「箱」**（ロードマップの「この表の使い方」の A〜F をそのまま）**＋ `先回りしない`（痛んだら測る）＋ `進行中`（作業者に出している）。**
  既定のラベル（`bug` / `enhancement` 等）は消した。箱は「並行できるか」を言うので、そちらだけで足りる。
- **本文は「何 / なぜ / 権威（ADR・ロードマップの節）/ 閉じる条件」。** 測定の数は書かない（権威は ADR）。

### 2. **司令塔が作業単位を切るとき、先に Issue を作る。作業者への指示は Issue 番号を含む**

**Issue の無い作業単位を作業者に出さない。** `B-22（新）` の形（済んだものを知らずに出す）は、Issue の一覧を見てから切れば起きない。

### 3. **閉じ方は `Closes #N` を持つコミット**

- **マージのコミットメッセージに `Closes #N`。** 作業単位ごとに `main` へ載せて push する運用（[personacore-workflow]）はそのまま。
- **レビューで出た穴のうち「決定」になったものは ADR、ならなかったものは Issue を閉じるコメント。** ロードマップの行には**取り消し線と `#N` だけ**を付け、要約を写さない（**同じ発見を2箇所に書かない**）。
- **ロードマップの行を新しく足さない。** 開くものは Issue。ロードマップには「順番と理由」だけを書く。

### 4. **[08-work-log.md](../process/08-work-log.md) は 2026-08-27 で閉じたまま。[06-roadmap.md](../06-roadmap.md) の役目は「順番と理由」に絞る**

- **台帳の役目は Issue（閉じたもの）が引き継ぐ。** 経緯（レビューの穴・是正の周数）は Issue のコメントに残る。
- **ロードマップは消さない。** 箱の定義、順番の合意、「なぜその順か」、過去の行（取り消し線つき）は歴史として残す。
  **開いている行は、対応する Issue へのリンクを持つ。** 2026-09-18 に開いていた 19 行を origin#1〜origin#19 に写した（**題名と権威の参照だけ。行の要約は写していない**）。

### 5. **Git の外にあるものの一覧は [04-environment.md](../04-environment.md) が持つ**

測定の台本（`<measurements>\`）、DB とログ（`%LOCALAPPDATA%\personacore\`）、上流プロファイルの写し（`scripts/upstreams.json`）、
Claude のメモリ、複製ツリーと `%TEMP%`。**「どこに・何が・誰のもので・消えたら何が起きるか」を1つの表に。**
ロードマップにも Issue にも置かない（**環境の事実**なので、環境の文書）。

## 却下した選択肢

| 案 | なぜ採らない |
|---|---|
| **閉じた作業単位も Issue に写す**（B-1〜B-46 等） | 歴史はロードマップと ADR とコミットに在る。写すと「同じ発見を2箇所に」になる |
| **マイルストーン** | 順番の合意はロードマップの「順番が決まった」節が持つ。**箱が「並行できるか」を言い、順番は司令塔と利用者が直列で決める**ので、いまは要らない。要る日に足す |
| **プロジェクトボード** | 一覧は `gh issue list --label` で足りる。増やすほど「見る場所」が増える |
| **ロードマップの表を消して Issue だけにする** | 「なぜその順か」「箱の定義」「順番の合意」は Issue の形に乗らない。残す |
| **ラベルに `bug` / `enhancement` を残す** | 箱と二重になる。**箱は「並行できるか」を言い、`bug` は言わない** |
| **ADR 番号を Issue に持たせる（`adr:0042` ラベル等）** | 本文の「権威」の行で足りる |

## 結果

- **開いているものを知りたいときは `gh issue list`。** ロードマップを 1284 行読まなくてよい。
- **済んだ印を付ける場所は1つ**（Issue を閉じる）。ロードマップの取り消し線は「Issue へのリンクの上に引く」だけ。
- **失うもの: ロードマップの行に書いていた「レビューの穴の要約」が、Issue のコメントへ移る。** 1箇所で読めたものが2箇所に割れる。
  **決定になったものは ADR に在る**ので、設計の理由を辿るときに困らない。経緯の細部は Issue。

## 見張り番

**無い。** これは作法であって、見張る仕掛けは1つも無い（CLAUDE.md §4「作法がある」と「見張り番がある」は別）。
**崩れる形は予想できる** —— Issue を作らずに作業者へ出す／`Closes #N` を忘れて Issue が開いたまま残る／ロードマップに新しい行を足す。
**3つとも `gh issue list` と `git log --grep=Closes` を突き合わせれば見える。** 見張るなら、そこに走査を置く。**いまは置かない**（置くなら ADR-0043 を改める）。

## 追記（2026-11-06）: 公開の後は、Issue と PR を公開側に置く

公開の手順（O-6 / [ADR-0048](0048-open-source-policy.md) の追記 2026-11-06）の後は、§1〜§3 を次のように読み替える。

- **Issue は公開側 `marukei/personacore` で開く。** origin に開いている Issue は、着手するときに公開側で開き直す。
- **§3 の「作業単位ごとに `main` へ載せて push する」は、「作業単位ごとに PR を開いてマージする」になる。** 公開側の `main` は PR 必須で、直接の push は通らない。
- **閉じるキーワードは、コミットの本文では `Closes marukei/personacore#N` と完全な形で書き、PR の本文では `Closes #N` でよい。** 公開側のコミットは origin の `main` にも取り込むので、短い形のコミットは origin の同じ番号の Issue を閉じる。
- §3 の「ロードマップの行には取り消し線と `#N` だけを付ける」の `#N` は、O-5 の後は `origin#N`、公開の後に開いた Issue は `marukei/personacore#N` と書く。
- §見張り番の「`git log --grep=Closes` と突き合わせる」は、PR の本文で閉じた Issue を拾わない（PR の本文はマージコミットに写さない）。見張りを置くときは、`gh pr list --state merged` の側も見る。
