# ADR-0053: 上流が本文に漏らした思考は、保存を除くすべての読み手の手前で剥がす。閉じない思考は末尾まで思考とみなす

## 背景

C-20 で Bonsai-2-27B（Qwen3.8-27B の三値量子化）を本文に使うと、`reasoning_effort: "none"` を送っていても
上流は `content` に英語の思考 `<think>…</think>` を漏らした（B 20/34・B+L 14/34。B+L は閉じタグだけが残った1ターンを含む数で、RESULT.md の 13 は `<think` を含むターンの数。llama を `--reasoning off` で起こしても 3/34）。
personacore はこれを3か所へ素通しにしていた。

1. **画面。** `web/src/lib/ChatView.svelte` は `raw_content`（実行中の回は届いた生の本文）をそのまま描く。
2. **次のターンのプロンプト。** `prompt::history_turn` は `raw_content` を戻す。
3. **裏方のサブLLM。** 記憶抽出は生の返事を `character_message` として読む。

測定の生の本文（`<measurements>\c20-2026-10-24\*/transcript.jsonl`）を数え直すと、形は次のとおりだった。

- 先頭に閉じた思考、後ろに本文（B 19 / B+L 8 / B-off 3）。
- **思考だけで本文が無い**（B+L 5）。
- 閉じタグだけが先頭に残る（B+L 1）。テンプレートが生成の頭に `<think>` を置いた形。
- 先頭に思考が2つと、余った閉じタグ（B 1）。
- **閉じない思考は 0 件。** RESULT.md の「多くは閉じない」は、空白入りの `</think >` を閉じタグと数えなかった読みと思われる。

**綴りは `<think >` / `</think >`（`>` の手前に空白）が多数派だった。** 最初の漏れは素の `<think>` で、2回目以降が空白入りになる。
**この空白は personacore が入れている。** `history_turn` は `raw_content` を `SafeText::sanitize` に通し、
`prompt::safe::neutralize_control_tokens` が制御トークンの形 `<think>` を `<think >` に崩す。
モデルは履歴に載った自分の思考を見て、その綴りを写している。B-48（`**` の持ち越し）と同じ構図で、**持ち越しを増幅しているのはこちら側**である。

## 決定

### 1. 剥がす規則は1つの純粋関数に置く

`domain` に純粋関数を1つ置き、本文の読み手は全部それを通る。`prompt` と `parse` は本番コードで互いに依存しないので、置き場は両方が読める `domain` にする。
返すのは剥がした後の本文と、**剥がしたブロックの数**と**閉じなかったか**の3つ。剥がすものが無ければ元の文字列を変えずに返す。

### 2. 規則

左から走査し、「思考の中か」を状態として持つ。

- **タグの綴り。** 開きは `<think` に続く0個以上の半角空白・タブと `>`、閉じは `</think` に続く同じものと `>`。大文字小文字は区別する（観測は小文字だけ）。
  空白入りを受けるのは、personacore 自身の無害化がその綴りを作るからである。
- **最初に見つかったタグが閉じタグなら、先頭から思考が始まっていたとみなす**（テンプレートが開きを生成の頭に置いた形）。
- 思考の外で開きタグ → 思考に入る。思考の中で閉じタグ → 出る。思考の中の開きタグは思考の一部として捨てる。
- 思考の外の閉じタグ（余り）は、タグだけを捨てる。
- **閉じないまま末尾に達したら、開きタグから末尾までを思考とみなして捨てる。**
- 剥がした境目に残る空行は落とす。**行頭の字下げ（`　`）は残す**（地の文の様式。`parse` の「行頭の空白は保持する」と同じ理由）。

### 3. 閉じない思考は、末尾まで思考とみなす

本文が空になれば、既存の空の経路に入る。`ParseOutcome::Empty` として数えられ、画面は「応答が空でした。」を出す。

**生の出力へ戻す案は採らない。** B-46 の強調では、対にならない印には触らない（推測で書き換えない）。思考で同じ線を引かないのは、失うものの大きさが違うからである。
対にならない `**` は2文字の雑音だが、閉じない思考では**キャラクターではない英語の独白が応答の全部**になる。しかもそれが履歴に載れば、上の増幅の経路で次のターンの漏れを呼ぶ。
**生の出力は `raw_content` に残っている**ので、調べる材料は失わない。

**「思考の後ろの本文らしいところを探して拾う」案も採らない。** 推測による書き換えで、外れたときに理由が追えない。この形は測定では 0 件なので、起きたらログで分かる（決定5）。

### 4. どこで剥がすか —— 保存を除く全部の読み手

| 読み手 | 剥がすか |
|---|---|
| `message.raw_content`（保存） | **剥がさない**（絶対制約） |
| `parse_response` に渡す本文（保存する `dialogue` / `narration`、パース成功率のログ） | 剥がす（`server::turn` が剥がしてから分解する） |
| `prompt::history_turn`（次のターンのプロンプト） | 剥がす。**`SafeText::sanitize` より前に**（後だと綴りが `<think >` に変わっている。規則は空白入りも受けるが、それに頼らず順序で守る） |
| 裏方のサブLLM（記憶抽出の `character_message` ほか、返事の本文を読むもの全部） | 剥がす |
| 画面（`replyBody` と、実行中の回の本文） | 剥がす。規則は TS へ手で写し、Rust と TS の両方が読む手書きの表で固定する（B-46 の `emphasis_corpus.tsv` と同じ作り） |
| OpenAI 互換 API の使い手に返す本文（非ストリーミングの応答本文と SSE） | **この決定では剥がさない**（決定6） |

履歴から剥がすと、思考だけだった回は `history_turn` が空として往復ごと落とす（既存の挙動）。

### 5. 剥がした数をログに残す

`応答を分解しました` の行に、剥がしたブロックの数と、閉じなかったかを欄として足す。**0 の回も出す**（分母が作れなくなるため。軸名の漏れや強調の欄と同じ理由）。
画面には出さない。

### 6. API の使い手に届く本文は、別の作業単位で決める

SSE は「1チャンク受けたら1イベント返す」（`server::relay`）で、思考の境目はチャンクをまたぐ。剥がすには、`<think` の途中まで届いた分を持ち越す状態機械が要る。
非ストリーミングの応答本文は上流の JSON を書き換えることになる。どちらも「いま画面と履歴が汚れている」を直すのに要らず、重さが違うので切り離す。
ADR-0047 は API を本体と呼ぶので、置いたままにはしない（Issue を別に開く）。

## 却下した選択肢

- **上流の設定で止める**（`--reasoning off` / `reasoning_effort`）。C-20 で両方を入れても 3/34 残った。上流の設定は第一の手段だが、それだけには頼れない。
- **画面だけで剥がす。** 履歴の増幅と裏方の汚れが残る。
- **`raw_content` を剥がして保存する。** 絶対制約に反する。
- **`parse_response` の中で剥がす。** `parse` は崩れたら生出力を丸ごと地の文にする作りで、その「生出力」が思考込みに戻ってしまう。履歴と裏方も別の入口から同じ規則が要るので、分解の手前で剥がす。

## 結果

- Qwen 系の思考モデル（同じ `<think>` を使う他系統を含む）を本文に使っても、画面・履歴・裏方に思考が出なくなる。
- 綴りの違う思考の印（`<thinking>`、gpt-oss の channel 形式など）は扱わない。観測が無いため。起きたら規則に足す。
- **閉じない思考を末尾まで捨てる規則は、モデルが閉じタグを書き忘れて本文を続けた場合に本文を失う。** そのときは画面が「応答が空でした。」になり、ログの欄が閉じなかったことを示す。測定では 0 件。
