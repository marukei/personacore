## 背景

v0.4.0 の利用者が、別の推論サーバの API を `127.0.0.1:8080` で動かしたまま `personacore.exe` をダブルクリックすると、窓が一瞬見えて閉じた。personacore の既定のポート（`src/server/config.rs` の `DEFAULT_PORT`）も 8080 だった。

B-76 で、止まるときにポートの番号と直し方（`PERSONACORE_PORT`）を言い、ダブルクリックの窓では Enter を待つようにした。だが、直し方は環境変数しか無い。配布物の利用者に、起動のたびに PowerShell で環境変数を打たせるのは好ましくない（利用者の指摘）。8080 は推論サーバや開発用のサーバがよく使う番号なので、重なりは今後も起きる。

いまの事実（2026-11-09 に読んだ `main` = 69d9fcd）:

- personacore 自身の待ち受けの番号は、`PERSONACORE_PORT` か `DEFAULT_PORT` で決まる（`config.rs` の `from_lookup_with_data_dir`）。`0` は「OS に空きを選ばせる」として通る。プロファイル（`upstreams.json`）は、面の宛先の番号は持つが、personacore 自身の待ち受けの番号は持てない。
- 待ち受けを開くのは `App::bind_with` の `TcpListener::bind` の1か所で、そこで失敗しても後始末の要るもの（起こした子・開いた DB）はまだ無い。上流を起こすのは開いた後である（ADR-0042 §決定3）。
- 開いた後の番号（`local_addr`）は、ブラウザを開く URL・起動ログの `url=` と `addr=`・`Host` / `Origin` の検査（`host_guard`）・走ったままの差し替えの取り合い検査（`switch`）が使う。**どれも設定値でなく実際の番号を見る**ので、ずらしても壊れない。
- **設定値を見る場所が4つある。**
  - `bind_with` の中で、起こす面の宛先を自分の待ち受けと比べる `port_conflict(config.bind())`（B-52）。
  - 覚えた名前の事前検査（`main.rs` の `remembered_profile` の `check_before_starting(config.bind())`）。
  - 使用中の文に番号を渡す `explain_server_failure(err, config.bind().port())`（B-76）。
  - 起動ログ `設定を読み込みました` の `bind=`。
- 待ち受けのアドレスやポートを返す API の口は無い。設定を保存して「次の起動から効く」と言う画面も無い。
- **既定のポートが塞がっていることが、二重起動を事実上止めている。** 同じ exe を2回ダブルクリックすると、2つ目は 8080 で落ちる。単一起動の仕組みはほかに無い。2つ目に `--fresh` を付けると、待ち受けより前にある退避が、動いている側の DB に当たる（`main.rs` の退避は bind の前）。
- 同梱の見本プロファイル（`scripts/upstreams.sample.json`。exe に埋め込まれる）の llama の面は、どれも `127.0.0.1:8081` を使う。配布物の README も、llama には 8081 を勧めている。
- `scripts/start.ps1` は起動の前に自分でポートの到達性を見て、使われていれば止まる。画面の URL も自分で組み立てて出す。

## 決定

### 1. ずらすのは、番号を明示していないときだけ

ポートの出どころは3つある。

| 出どころ | 使われていたら |
|---|---|
| `PERSONACORE_PORT`（明示） | **ずらさずに止まる**（B-76 の文） |
| 画面で保存した番号（決定5） | ずらす |
| 既定（`DEFAULT_PORT`） | ずらす |

明示した番号は、既存のチャットクライアントの設定などに書いた番号のはずである。黙ってずらすと、そちらが繋がらなくなる。明示のときの振る舞い（面の番号と同じなら B-52 で止まる、事前検査が覚えた名前を捨てる）は、今までどおりにする。`PERSONACORE_PORT=0`（OS に選ばせる）も今までどおりで、ずらしの対象ではない。

### 2. 二重起動は、データのディレクトリのロックで止める（ポートの重なりに頼らない）

ずらすと、ポートの重なりは二重起動を止めなくなる。そこで、同じデータを使う personacore が2つ動くことを、ポートと独立に止める。

- **起動の最初に、DB と同じディレクトリに置くロックのファイル（例 `personacore.lock`）を、OS のファイルロックで排他的に取る。** 引数を読んで `--version` を処理した直後、`--fresh` の退避・上流への照会・待ち受けより前に取る。取れなければ、同じデータを使う personacore がすでに動いている。
- **動いている側は、待ち受けを開いた後に、ロックのファイルへ実際の URL と、画面を配っているか（`--no-ui` でないか）を書く。** ロックはプロセスが終われば OS が外す（異常終了でも残らない）。ファイル自体は残ってよい。
- **取れなかった2つ目は、何もせずに案内して終わる。**
  - ファイルに URL があれば「personacore はすでに `http://127.0.0.1:8081/` で動いています」と言う。動いている側が画面を配っていて、2つ目がブラウザを開く設定なら、その URL を開く。
  - URL がまだ無ければ（動いている側が起動の途中）、「personacore は起動の途中です」と言う。
  - 渡された `--fresh` や `--upstream` は使わず、使わなかったことを言う（`--fresh` が動いている側の DB を退避しようとしないように、ロックは退避より前に取る）。
  - 終了コードは 0。ブラウザを開いたときは Enter を待たない。開かなかったとき（`--no-browser`・`--no-ui` の相手・起動の途中・開けなかった）は、ダブルクリックの窓なら B-76 の判定で Enter を待つ（文が窓と一緒に消えないように）。
- **ポートの出どころと独立に働く。** `PERSONACORE_PORT` を明示した起動でも、同じデータなら同じロックで止まる。
- **データのディレクトリが違えば、別々に動ける。** `PERSONACORE_DB_PATH` を変えた起動（開発・テスト）は、別のロックを取る。
- ポートへの問い合わせ（`GET /openapi.json` の版のヘッダで相手を見分ける形）は採らない（却下した選択肢）。

### 3. 探し方: 1つずつ上へ、10 個先まで

元の番号から `+10` までを範囲とし、順に試して、最初に開けた番号で待ち受ける。

- **飛ばす番号:** `upstreams.json` の全部のプロファイルの `gguf` の面が使う番号（llama を起こす番号）。その起動の計画に入っているかどうかを問わない。覚えた名前で起きた起動（ADR-0055）は、上流を後で画面から起こすので、計画だけを見ると取り合いを見逃す。見本の 8081 もここで飛ぶ。番号を明示していないときは、**元の番号も**面と同じなら飛ばす。飛ばした番号も範囲の 10 に数える。
  - そのため、番号を明示していない起動は、旗も覚えた名前も無くても `upstreams.json` を読む（いまの「旗も覚えた名前も無ければ読まない」を、この目的に限って改める。読んだ中身で上流を決めることはしない）。読むのは、その起動が使う置き場所（`PERSONACORE_UPSTREAMS` が指す先か、既定の置き場所）。置き場所が決まらない・ファイルが無い・読めないときは、飛ばす番号を空にして進む（読めないときは警告を1本出す）。
- **ずらす失敗:** `AddrInUse` と、`PermissionDenied`（Windows の除外ポート範囲で返りうる）。ほかの失敗では、ずらさずに止まる。
- **上の端:** 範囲は 65535 で打ち切る。
- **全部だめなら:** B-76 の文を、試した範囲（例「8080〜8090」）を言う形に広げて止まる。番号を明示していたときの文は今までどおり。
- **OS に選ばせない**（`127.0.0.1:0`）。起動のたびに番号が大きく変わると、ブックマークや外部のクライアントの設定が毎回無駄になる。近い番号なら、利用者が見当を付けられる。
- **ずらした番号は覚えない。** 次の起動では、また元の番号から試す。元の番号を塞いでいたプログラムは、次には動いていないかもしれない。
- 試す番号は `BindAddr::loopback` で作る（`127.0.0.1` 以外にバインドする道を作らない）。
- 探す処理は `TcpListener::bind` の位置で完結させる。`Store::connect` より後に置かない（`App::bind` の doc とモジュールの doc の約束）。
- **設定値を見る4つの場所を直す。** `port_conflict` には実際に開いた番号を渡す（`launch.rs` の doc の「覆うなら `bind` の後の `local_addr` を渡す形になる」を、ここで塞ぐ）。事前検査（`remembered_profile`）は、番号を明示したときだけ番号の取り合いでプロファイルを捨てる（明示していなければ、決定3 が面の番号を飛ばすので取り合わない）。使用中の文は試した範囲を言う。`bind=` は決定4 のとおり。

10 は実測由来の値ではない。外れたとき（範囲が全部埋まっている機）は、止まって範囲と直し方を言うだけで、壊れる側には倒れない（ADR-0036）。設定できるようにもしない。

### 4. ずらしたことを、ログ・画面・API の三か所で知らせる

- **起動ログ:** 警告を1本出す（元の番号・実際の番号・出どころ・飛ばした番号）。`設定を読み込みました` の行の `bind=` は、出どころの番号（試し始めた番号）として残す。実際の番号は、この警告と、どの起動でも出る待ち受けの行の `addr=` で読む（`url=` は `--no-ui` では出ない）。
- **画面:** 全部の画面の上の帯（`App.svelte` のナビの並び。`main` の外）に、「8080 は他のプログラムが使っていたので、8081 で起動しました」と出す。番号を変える場所（決定5 の「設定」の画面）へのリンクを添える。同梱の画面は実際の URL で開くので、利用者が何かをする必要は無い。帯は、ブックマークや外部のクライアントの番号を直すきっかけを渡すためにある。
- **API:** `GET /admin/server`（決定6）に、元の番号・ずらしたか・飛ばした番号を載せる。外部のクライアントやスクリプトが読める。

### 5. ポートは画面で保存でき、次の起動から効く

- **置き場所は新しい「設定」の画面**（ナビに足す）。personacore 自身の設定が今後増えたら、ここへ置く。上流の画面には置かない（推論サーバの話と、personacore 自身の待ち受けの話が混ざる）。
- **保存先は覚えた上流の名前（`selected-upstream.txt`）と同じディレクトリの小さなファイル**（例: `listening-port.txt`）。置き場所の決め方と「既定の置き場所のときだけ読み・書く」は、`src/server/remembered.rs` の `remembered_path_beside` / `memory_for` と同じにする（`PERSONACORE_UPSTREAMS` で置き場所を変えた起動では読まない・書かない）。DB には置かない（`--fresh` で忘れない）。書き方は置き換え。
- **読めないときは、警告を1本出して既定で起きる。** 「読めない」には、範囲の外（1023 以下（`0` を含む）・65536 以上）の番号や、数でない中身を含む。ファイルは消さない（覚えた名前と同じ扱い）。
- **効く順:** `PERSONACORE_PORT` → 保存した番号 → `DEFAULT_PORT`。保存した番号は、環境変数と同じ入口（`config.rs` の `from_lookup` 系）へ流し、環境変数の既定の経路とプロファイル経由の経路（`config_for`）の両方が同じ番号を見るようにする（入口を増やさない / ADR-0042 §決定1）。ただし保存した番号を `PERSONACORE_PORT` の値として混ぜることはせず、**番号と一緒に出どころ（環境変数・保存・既定）を `AppConfig` に持たせる。** 決定1 の「明示か」と、`GET /admin/server` の出どころは、これで見分ける。覚えた名前の事前検査も、この番号を見る。
- **動いている間に待ち受けを移さない。** 保存したら、画面に「次の起動から効きます」と言う。環境変数が効いているときは、「`PERSONACORE_PORT` が効いているので、保存しても次の起動では使われません」と言う。
- **保存できる番号は 1024〜65535。** `0`（OS に選ばせる）は保存できない（開発とテストのための値で、毎回番号が変わる）。保存の前に、その番号がいま使われているかを確かめて応答で知らせる。いまこの personacore が使っている番号なら、使われているとは言わない。使われていても、保存は止めない（次の起動で決定3 がずらす）。
- **保存を消して既定に戻す**操作を置く。

### 6. API: `/admin/server` を足す。版は単位ごとに上げる

上流の観測の口（`/admin/upstream`）に、サーバ自身の話を混ぜない。新しい2つの口（`GET /admin/server` と `PUT /admin/server/port`）は、既存の口と同じ `router` に足す（`host_guard` を通る。ルータの2つ目の入口を作らない）。`PUT` は設定を書く口なので、DNS rebinding の検査（B-58）が守る経路そのものである。

| 単位 | 口と欄 | API の版 |
|---|---|---|
| F-12 | `GET /admin/server`: いまの待ち受け（実際の番号）、出どころ（`environment` / `saved` / `default`）、保存した番号（あれば）、次の起動で使う番号と出どころ、保存できるか（既定の置き場所か）。`PUT /admin/server/port`: 本文 `{"port": 8090}` で保存、`{"port": null}` で保存を消す。応答は `GET` と同じ形に、保存した番号がいま使われているかを足す | `1.4` → `1.5` |
| F-11 | `GET /admin/server` に、元の番号・ずらしたか・飛ばした番号を足す | `1.5` → `1.6` |

- ADR-0047 の版の上げ方（形を変えた単位の中で上げる。指紋の表の既存の行は書き換えない）に従う。v0.4.1 が名乗る版は `1.6` になる（`1.5` は公開の版には現れない）。
- 範囲の外の番号は 400（数の範囲の誤りに 400 を返す先例 `invalid_max_tokens` に倣う）。保存できない置き場所のときは 409（プロファイルの編集が保存できない置き場所で返す `upstream_profiles_read_only` に倣う）。

### 7. 起動のスクリプトと文書

- `scripts/start.ps1` は、番号を明示したとき（`-Port` か、引き継いだ `PERSONACORE_PORT`）だけ、事前に到達性を見て、使われていれば止まる。明示していなければ事前検査をせず、exe に任せる（保存した番号を使う・ずらす・すでに動いていれば案内する）。画面の URL は、明示していないときは自分で組み立てず、exe の `url=` を見るよう案内する。この分岐に見張り番（`tests/start_script.rs`）を足す。`.PARAMETER Port` の説明も直す。**これは F-12 で入れる**（保存した番号が効き始めた時点で、`DEFAULT_PORT` で事前検査して URL を組み立てる今の形は誤る）。
- `-Upstream` で起こすと `PERSONACORE_UPSTREAMS` が変わり、保存した番号を読まなくなる（決定5 の「既定の置き場所のときだけ」の帰結）。`scripts/README-start.md` にそう書く。
- 配布物の README の「うまくいかないとき」（B-76 で足した節）を書き換え、ふだんは番号をずらして起き、帯で知らせること、番号は「設定」の画面で変えられること、`PERSONACORE_PORT` を明示したときだけ止まることを書く。llama に 8081 を勧める一文は、ずらしが 8081 を飛ばすので残してよい。
- 根の README 3つ・API ガイド・`docs/09-setup.md`・`scripts/README-start.md`・`web/README.md` のポートの記述を、効く順に合わせる。
- `web/vite.config.ts` の開発用の proxy は、`PERSONACORE_PORT` か `DEFAULT_PORT` しか読まない。開発中の `cargo run` は既定の置き場所を読むので、保存した番号やずらしで、proxy の先とずれうる。`web/README.md` に「開発中は `PERSONACORE_PORT` を明示する」と書く（proxy に保存のファイルを読ませない）。

## 利用者が決めたこと（2026-11-09）

下書きで挙げた4つの問いに、利用者はどれも案のほうを選んだ。

| 問い | 決めたこと | 選ばなかったもの |
|---|---|---|
| ずらす探し方 | 1つずつ上へ 10 個先まで（決定3） | OS に空きを選ばせる（番号が毎回大きく変わる） |
| 保存した番号も、使われていたらずらすか | ずらす（決定1） | 保存した番号は明示とみなし、止まる |
| 画面の置き場所 | 新しい「設定」の画面（決定5） | 上流の画面の下に節を足す |
| API の置き場所 | 新しい `/admin/server`（決定6） | `GET /admin/upstream` の応答に欄を足す |

決めた後のレビュー（2026-11-09、2回）で分かったことを受けて、司令塔が次を足した。データのディレクトリのロックで二重起動を止めること（決定2）、面の番号を全部のプロファイルから飛ばすこと（決定3）、作る順を F-12 → F-11 にして API の版を単位ごとに上げること（決定6・作業単位）。**このうち決定2 は利用者から見える振る舞い（2つ目が案内して終わる）を新しく決めるので、利用者に確かめ、利用者がこの形でよいと決めた**（2026-11-09。選ばなかったのは「案内せず、エラーで止まる」）。

## 却下した選択肢

- **既定のポートを 8080 から変える。** 重なりの起きにくい番号へ移しても、どこかで何かと重なる。今の利用者の設定（ブックマーク・外部のクライアント・`tests/readme.rs` / `scripts/start.ps1` の帳簿）を全部直すことになる。ずらす仕組みがあれば、既定の番号の選び方は効きが小さい。
- **明示した番号もずらす。** 既存のチャットクライアントに書いた番号と黙って食い違う。
- **二重起動を止めずに、ずらして2つ目を起こす。** 同じ DB・同じ覚えた名前を2つが書く。裏方の書き込み（抽出・変容）も重なる。これまでは、8080 の重なりが偶然それを止めていた。
- **塞いでいる番号へ問い合わせ、版のヘッダ（`x-personacore-api-version`）で相手が personacore かを見分ける**（下書きの決定2）。2つの穴がある。元の番号を別のプログラムが使っていると、1つ目はずれた先にいるので、元の番号だけを問い合わせる2つ目は1つ目を見逃して、さらにずれる。1つ目がまだ起動の途中（待ち受けを開いてから応答を始めるまでの間に、マイグレーションを含む DB の接続がある）だと、問い合わせに応答が無く、別のプログラムとみなしてずれる。2回続けてダブルクリックしたときは、典型的に後者になる。問い合わせの応答を待つ時間の上限が外れたとき（相手が上限より遅かったとき）に倒れる先が二重起動（壊れる側）なので、ADR-0036 の問いに照らして採らない。
- **動いている間に待ち受けを移す。** 開いている接続・画面・外部のクライアントが全部切れる。起動し直すのと変わらず、仕組みだけが増える。
- **保存先を DB にする。** `--fresh` で忘れる。マイグレーションが要る。覚えた上流の名前と置き場所が割れる。
- **保存先を `upstreams.json` にする。** 上流の設定とサーバの設定が1つのファイルに混ざる。プロファイルの編集の検証（ADR-0042）にサーバの欄が入り込む。
- **F-11 を先に入れる。** F-11 だけでは、ずらしの対象になる出どころが `DEFAULT_PORT`（利用者の 8080）しか無く、exe を起こすテストでずらしを観測するには、テスト専用の継ぎ目（新しいつまみ）が要る。帯からのリンク先（「設定」の画面）も無い。F-12 の保存した番号があれば、テストは空いている番号の近くを保存して、そこを塞いで観測できる。
- **F-11 と F-12 で版を1つにまとめる（未公開の版の行を書き換える例外を ADR-0047 に足す）。** 指紋の表の約束を緩めることになる。版が1つ余分に進むだけなら、約束を守るほうを採る。

## 結果

- 既定のポートが他のプログラムと重なっても、ダブルクリックで起きる。利用者は環境変数を打たなくてよい。
- 2回ダブルクリックしても、2つ目は1つ目を案内して終わる（二重起動を偶然でなく決定で止める）。ポートを変えた起動や、ずれた起動でも止まる。
- 起動のたびに、ロックのファイルと、番号を明示していなければ `upstreams.json` を読む。
- 外部のクライアントは、ずれたことを帯か `GET /admin/server` で知る必要がある。黙って繋がらなくなる場面は残る（帯を見ない・API を読まない使い方）。
- 起動ログの `bind=` は試し始めた番号で、実際の番号は別の行（警告と `addr=`）で読む。
- 画面・API・保存のファイルが1つずつ増える。API の版が2つ進む（v0.4.1 は `1.6`）。
