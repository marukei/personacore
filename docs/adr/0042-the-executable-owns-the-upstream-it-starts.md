## 背景 —— **配布の軸を入れると、「起こさない・選ばせない」は置き場所を失う**

`D-9`（2026-09-07）で利用者はこう決めていた —— **「モデルは見えるだけでよい。personacore はプロセスを起こさない。選ばせもしない。」**
**その決定は `F-9`（2026-09-18）で一段曲がった** —— `start.ps1 -Upstream <名前>` は、プロファイルが gguf を名指ししていれば `llama serve` を起こし、控えた PID だけを止めて終わる。
**曲がったのはスクリプトであって exe ではなかった**ので、決定の文言は保たれていた。

**[ADR-0041](0041-one-executable-per-os.md) で配布物が exe 1本になると、スクリプトは配布物から消える。**
利用者の指摘（2026-09-18）:

> モデルの置き場所が変わったりする可能性を含めて、特定のモデルを指定して起動したり、
> あるいは文章途中でモデルを差し替えるために起動しなおしたりというケースが当然に想定される。
> OpenAI 互換の上流を触れる機能は持たせないと辛そう。llama.cpp だけをターゲットにしてでも検討の余地あり。

**環境差異を吸収する層を3つに分けた**（同日に合意）:

| 層 | 何を吸収するか | どこで |
|---|---|---|
| 0 | 上流のエンドポイントと名乗り。答えたモデル名を画面で見せる | exe（`F-4a` まで。環境変数） |
| **1** | **名前つきのプロファイル（エンドポイント＋モデル＋任意で gguf と起動）。gguf の実在確認。llama の起動・後始末・差し替え** | **exe（この ADR / `F-4b`）** |
| 2 | モデルの探索・ダウンロード・選択 GUI | **exe には入れない。** LM Studio と `hf` に委ねる |

**層2を外に置く理由は ADR-0038 と同じ向き** —— personacore の関心は「上流がこう振る舞うこと」であって、モデルの取得ではない。

**差し替えの土台は既にある。** personacore は上流へ**要求ごとに**繋ぎ、セッションは SQLite に在る。
ターンとターンの間で上流が入れ替わっても会話は切れない（`start.ps1` の doc が「先にこちらを起動して、あとから上流を起動する」で動くと書いているのと同じ性質）。
**無いのは、exe が自分の子を止めて別のを起こし、上流の観測（`G-3b` の `UpstreamFacts`）を測り直すこと。**

## 決定

### 1. **プロファイルの形は `F-9` のまま。置き場所は DB と同じディレクトリ**

- 形は `scripts/upstreams.sample.json` と同じ —— **名前 → 面（`main` / `sub`）→ `endpoint` / `model` / 任意の `gguf` / `args`。**
  **`F-9` の検証規則をそのまま引き取る**: 知らない面・知らない鍵は名前を挙げて止まる／`sub` が無ければ抽出は本文と同じ上流（ADR-0039 §決定1）／
  **gguf を書いた面の `endpoint` はループバックだけ**（`--host` に渡るため）／`~` は展開する。
- **鍵を1つ足す: `command`（任意。既定 `llama`）。** 「モデルの置き場所が変わる」と同じ理由で、**実行ファイルの置き場所も変わる。**
  PATH に無い `llama` を絶対パスで指せるようにする。**それ以外の鍵は足さない。**
- **置き場所は [ADR-0041](0041-one-executable-per-os.md) §3 の DB と同じディレクトリ**（Windows `%LOCALAPPDATA%\personacore\upstreams.json`）。
  **1箇所にする。** 設定と DB の場所が割れると、「どこを見ればよいか」が2つになる。
  **`PERSONACORE_UPSTREAMS` で上書き可**（開発中はリポジトリの `scripts/upstreams.json` を指す）。
- **`--upstream <名前>` で起動時に選ぶ。** 旗が無ければ**今と同じ環境変数の経路**（振る舞いを1バイトも変えない）。
  **旗があってファイルが無い／名前が無いときは、パスと在る名前を挙げて止まる**（黙って既定へ落ちない。`F-9` と同じ）。

### 2. **gguf を名指しした面だけ、exe が起こす。起こしたものしか止めない**

- **`tokio::process::Command`**（Windows と Mac で同じコード）。`command serve -m <gguf> --host <h> --port <p> <args…>`。
  **標準出力・標準エラーは DB と同じディレクトリの `upstream-logs/` へ**（`F-9` と同じ。**exe のログに混ぜない**）。
- **PID は起こした直後に控える。載るのを待つ前に。** `F-9` の回帰（控える前の窓）をそのまま規則にする。
- **止めるのは自分が控えた PID だけ。** LM Studio が内側で立てる `llama-server` にも、利用者が手で立てた llama にも触らない。
  **止めたら終了を待つ。** 待たずに次を起こすと VRAM の取り合いになる（`C-16` の形）。
- **gguf の実在は起こす前に確かめ、無ければパスを挙げて止める。** CLIP の架空タグと同じで、無い物を指したまま先へ進ませない。

### 3. **待ち受けを先に開き、載るのは待たない。状態を持って言う**

`F-9` の `start.ps1` は**載るまで待ってから** `cargo run` に進んだ。**exe はその順を逆にする:**

1. 待ち受けを開く（画面が使える。キャラクターの作成は上流が無くても出来る —— `start.ps1` の doc と同じ根拠）。
2. 起こす。
3. **背景で**「答えた名前」を待つ —— `/v1/models` が **gguf のファイル名**を名乗るまで（**依頼したモデルの綴りでは確かめない**。`B-45` と同じ根拠）。

**面ごとに状態を持つ**: `起動していない（外の上流）` / `載せている（開始時刻）` / `準備完了（答えた名前・窓）` / `失敗（理由・ログの場所）` / `止めた`。
**`GET /admin/upstream` と `#/upstream` の画面がこれを言う**（`G-10` / `D-9` の口に足す）。

**待ちは [ADR-0035](0035-the-watchdog-reports-the-human-decides.md) の作法**: **固定の秒数で殺さない。** 経過を報告する。
**天井は緩く1つだけ持ち、超えたら「まだ載っていない」と言うだけで止めない**（20 GB の gguf は載るまで1〜2分。**画像生成と取り合えばもっと**。ADR-0019 が自分で書いた反例）。
**⚠ ただし、子プロセスが自分で終了したら即「失敗」にする**（`F-9` の `HasExited` と同じ。**死んだ書き手を待たない** —— CLAUDE.md §4「上限は待つ側に」）。

**載っていない間の要求は、今の上流エラーの形で返る**（接続拒否）。**隠さない。** 画面が「載せている」と言っているので、原因に近い。

> **⚠ 2026-09-26 に前提が崩れた**（利用者が v0.1.2 で遊んで指摘 / origin#37）——
> **「画面が言っている」のは `#/upstream` だけで、利用者が居る会話の画面は何も言っていなかった。** 起動直後もプロファイルの切り替えの直後も、会話の画面は開いていて、載る前に送れる。
> **決定: 会話の画面も本文の面の状態を言い、personacore が自分で起こした本文の面が「載せている／失敗／止めた」か差し替えの最中なら、送信を止めて理由を言う。**
> **外の上流（personacore が起こしていない面）では止めない** —— 状態を知らないので、止める根拠が無い（ADR-0035: 外から「遅い」と「死んだ」は区別できない）。
> **裏方の面の状態では止めない**（本文は返る。裏方が載るまでの抽出・変容は今までどおり飛ぶ）。
> **サーバの振る舞いは変えない**（上の段落のまま。外のクライアントには今の上流エラーの形で返る）。

### 4. **走ったまま差し替える —— `POST /admin/upstream/profile`**

- 本文 `{ "name": "<プロファイル名>" }`。**面ごとに**: 新旧の面を比べ、
  **gguf を持つ面は「自分の子を止める → 終了を待つ → 起こす → 待つ → 測り直す」**、
  **gguf の無い面は「宛先と依頼するモデルの綴りを差し替える → 測り直す」**（LM Studio の JIT はこれで載せ替わる。プロセスは触らない）。
- **測り直し**: `G-3b` の `UpstreamFacts`（窓・答えた名前・どちらの読み手が答えたか）を**その面だけ**書き直す。
  **古い事実を残さない** —— 残すと画面が前のモデルの窓を言い続ける。
- **同時に1つだけ。** 進行中に次を頼まれたら `409`（理由つき）。**列に並べない**（並べると「いまどれに向かっているか」が言えなくなる）。
- **受け付けた差し替えは、依頼の接続が切れても最後まで走る**（2026-10-22 / origin#39 B-56）。差し替えはハンドラから切り離したタスクで走り、ハンドラはその結果を待つだけ。以前は画面を移ると POST が落ち、止める段の途中で差し替えが止まって、面が死んだ子の古い「準備完了」のまま残っていた（5/5 で再現）。その間の次の依頼は、今までどおり `409`。**終了（Ctrl+C）の後に錠を取った差し替えは断る**（終了の途中で新しい子を起こさないため）。
- **飛んでいる最中のターンは守らない。** 子を止めた瞬間、そのターンは上流エラーで終わる（本文は中継の途中で切れ、`raw_content` はそこまでが保存される）。
  **非同期の抽出も同じ**（そのターンの抽出が失敗として報告される）。**待って合流する経路は作らない** —— 待つと「いつ差し替わるか」が要求の長さに依存し、外から見えなくなる。
- **「進行中」（`409` を返す範囲）は、止めて起こすまで。載るのを待つ間は含めない**（`F-4b-2` の実装で決めた / 2026-09-24）。
  載らないまま黙る子（ADR-0035 で殺さない）がいると、含めた形では二度と差し替えられなくなる。
  **その代わり、載っている最中に次の差し替えが来たら、載りかけの子を止める。**
- **差し替えた面の予算と抽出の上限は、落とし所へ戻してから測り直す。** 前のモデルの窓のまま組むと、窓の小さい上流ではプロンプトの先頭が黙って切られる。
  **窓を名乗らない外の上流では、次の引き直しまで落とし所のまま**になる。
- **`AppState` の LLM クライアント（本文・抽出）は差し替え可能な形になる。** これが `F-4b-2` を `F-4b-1` から分ける理由 ——
  クライアントは `App::bind` で組まれて不変であり、そこを可変にする変更は継ぎ目（`llm::LlmClient`）に触る。**`upstream_leaks` の台帳を測ってから更新する**（ADR-0039 §決定5）。

### 5. **画面は「自分が書いたプロファイルから選ぶ」まで。探さない、落とさない**

`#/upstream` に**プロファイルの一覧と現在の状態と、選ぶ操作**を足す。
**一覧は面ごとの中身（書いたままの値）まで出す**（`F-4b-3` / origin#24 で「足す・直す」を置いたため。名前だけでは直す対象が見えない）。**観測した値とは別の節に置く。**
**一覧に載るのは利用者が `upstreams.json` に書いたものだけ。** モデルの探索・カタログ・ダウンロードは載せない（層2）。

**`D-9` の「選ばせもしない」はこれで置き換わる。** 当時の理由は「切り替えが高い（プロセスを手で立て直す）ので、選ばせても意味が無い」だった。
**決定4で切り替えが安くなるので、条件のほうが消える。** 「見えるだけ」の決定は**モデルの取得について**は残る。

### 6. **`start.ps1` の `F-9` の部分は exe へ委ねる**

`start.ps1 -Upstream <名前>` は **`cargo run -- --upstream <名前>` に流すだけ**になり、PowerShell 側の起動・待ち・後始末（`Start-UpstreamProcess` / `Wait-UpstreamReady` / `Stop-Process`）は消す。
**同じことをする実装を2つ持たない**（片方が黙って古びる）。**`PERSONACORE_UPSTREAMS` に `scripts/upstreams.json` を渡す**ので、開発中の置き場所は変わらない。

### 7. **`upstream-logs/` は面ごとに最新 5 世代だけ残す**（2026-09-24 / 利用者の決定）

決定2のログは起こすたびに面ごとに2ファイル（標準出力・標準エラー）増え、決定4の差し替えで増え方が速くなる。
**exe が起こす直前に、その面の古い世代を消し、自分が起こすぶんを含めて最新 5 世代にする。**

- **世代の単位は「1回の起動」**（同じ起動の `.log` と `.err.log` は一緒に残り、一緒に消える）。**数えるのは面の綴りごと**（`main` の差し替えが `sub` のログを消さない）。
  **本文と裏方が同じ子を共有するときの綴り `main+sub` も1つの単位として数える**ので、共有と別々を行き来すると合計で最大 15 世代が残る。
- **同じ秒に2回起こしたら、2回目以降は `<面>-<時刻>-<N>`**（N はその秒の最大の次）で、既存のファイルは開き直さない（`create_new`）。並びは時刻、同じ秒なら番号の順。
- **消すのは exe が名付けた形のファイルだけ**（`<面>-<時刻>.log` / `.err.log`）。利用者が同じディレクトリに置いた他のファイルには触らない。
- **消せなかったら止めない。** 経過として報告し、起こすほうを続ける（ログの掃除は上流を起こす理由より弱い）。
- **5 は実測値ではなく方針**（ADR-0036 の問い「外すと壊れるか」に対しては「遅くも壊れもしない。残る数が変わるだけ」）。つまみにしない。

却下: **面ごとに1ファイルを上書き**（差し替えた直後に、1つ前の失敗のログが読めなくなる）／**消さない**（差し替えが安くなるほど、利用者の知らない所で増え続ける）。

### 8. **画面から `upstreams.json` を書くのは exe だけ。書く先は既定の置き場所だけ**（2026-09-24 / `F-4b-3` の着手前）

`F-4b-3`（origin#24）で画面から足す・直す。**利用者のファイルを書き換える**ので、書き方を先に決める。

- **書くのは既定の置き場所（決定1）だけ。** `PERSONACORE_UPSTREAMS` が別のファイルを指しているときは、**画面は読むだけ**にして、読んでいるファイルと「ここからは直せない」ことを言う。
  理由: `start.ps1 -Upstream` はそれを `scripts/upstreams.json` か、**コミットされた見本 `scripts/upstreams.sample.json`** へ向ける。画面の保存がリポジトリのファイルを書き換える経路を作らない。
- **保存する内容は、ファイル全体が読み込みの検証（決定1・`F-9` の規則）をもう一度通ったものだけ。** 通らなければ書かず、理由を画面に返す（理由は定数。パスは利用者自身が書いた値なので画面に出してよい）。
- **置き換えで書く**（同じディレクトリの一時ファイルに書いてから差し替える）。途中で落ちても、元のファイルは読める形で残る。
- **読んだ後に手で書き換えられていたら、上書きしない。** 画面が読んだときの内容の印（ハッシュ）を保存の依頼に添え、いまのファイルと違えば `409`。
- **書き直すと、手で整えた並びや空白は失われる**（JSON を組み直すため）。鍵の意味は変わらない。これは受け入れる。
- **消す操作はまだ置かない**（origin#24 の範囲外。利用者のファイルから行を消す経路は、要ると分かってから決める）。

### 9. **最後に選んだプロファイルで起きる**（2026-09-25 / origin#28 の着手前 / 利用者の決定を含む）

> **⚠ 2026-11-01: 覚えた名前で起きたときは gguf の面を起こさない**（[ADR-0055](0055-do-not-start-the-remembered-upstream-at-launch.md)）。下の「覚えた名前が使えないとき」の5つの形（名前が消えた・検証に通らない・gguf が無い 等）では今も既定へ落ちるが、**起こせない（`command` が無い）形は起動時には分からず**、同じ名前で起こしたときに `failed` として出る。

利用者は LM Studio を外す。引数なしの起動が環境変数の既定（LM Studio の `127.0.0.1:1234`）に向き続けると、遊ぶたびに画面で切り替える1手が要る。

- **覚えるのはプロファイルの名前だけ。** 中身は `upstreams.json` が持つ（写しを作らない）。
- **置き場所は DB と同じディレクトリの小さなファイル**（`selected-upstream.txt`、名前1行）。**`upstreams.json` には書かない**（利用者のファイルで、知らない鍵は読み込みで止まる）。**DB にも置かない** —— `--fresh` は DB を退避するが、**どのモデルで起きるかは設定の側なので `--fresh` で忘れない**（利用者の決定）。
- **覚える時**: 画面の切り替え（`POST /admin/upstream/profile`）が受け付けられたとき、**と、起動時に `--upstream <名前>` で選んで起こしたとき**（利用者の決定 —— 「最後に使ったもの」）。載り終わるのは待たない。
- **優先順位**: `--upstream`（明示）＞ 覚えた名前 ＞ 環境変数の既定。
- **覚えた名前が使えないとき**（名前が `upstreams.json` から消えた／検証に通らない／gguf が無い）は、**止まらずに環境変数の既定で起き、警告を1本出す。** 覚えた名前は消さない（利用者が `upstreams.json` を直せば次から効く）。**明示の `--upstream` が使えないときは今までどおり止まる。**
- **`PERSONACORE_UPSTREAMS` で別のファイルを読んでいるときは、覚えも読みもしない**（開発中の `start.ps1 -Upstream` はリポジトリのファイルを読むので、その選択を利用者の遊びの設定へ持ち込まない）。
- 書くのは置き換えで（決定8と同じ）。書けなくても起動と切り替えは止めない（警告だけ）。

## 却下した選択肢

| 案 | なぜ採らない |
|---|---|
| **上流は環境変数のまま。起動はスクリプトに任せる** | 配布物からスクリプトが消える（ADR-0041）。Mac にスクリプトを写す向きになる |

| **画面からモデルを探す・落とす** | 層2。利用者の決定 |

## 結果（見込み。実装して測ったら書き直す）

- **配布した exe だけで、プロファイルを指定して起動でき、画面から差し替えられる。** Rust も pnpm も PowerShell も要らない。
- **`start.ps1` は薄くなる**（`F-9` の PowerShell 実装が消える）。
- **失うもの: 「personacore はプロセスを起こさない」という単純さ。** 代償は子プロセスの管理（PID・終了待ち・ログ）を exe が持つこと。
  **`F-9` が PowerShell で既に払った代償を Rust で払い直す形**で、新しい種類の危険は増えない。
- **⚠ 上流への要求（ADR-0038）は増えていない。** `llama serve` の引数の形に依存するのは決定2だけで、それはプロファイルの `args` に逃がしてある。

## 見張り番（作業単位が置くもの。`F-9` の教訓から）

- **PID を控えるのは待つ前** —— 控えの位置を見るテストではなく、**偽の `llama`（何もしない同名の実行ファイルを PATH の先頭に置く）で本当に起こして本当に止める**（CLAUDE.md §4「本物を起こせない経路は偽物で起こす」）。
- **止めるのは控えた PID だけ** —— 偽物を2つ起こし、片方だけを自分の子にして、もう片方が生きていること。
- **子が自分で終了したら即「失敗」** —— 偽物を即終了させる腕。
- **`/v1/models` が別の名前を名乗ったら「失敗」**（載ったのは別のモデル）。
- **gguf が無ければ起こさない**（偽物が一度も呼ばれないこと）。
- **`--upstream` 無しは環境変数の経路と同一**（着手前のテストが1本も変わらないこと。`git diff -U0` で確かめる）。
- **`F-4b-2`**: 差し替え中の `409`／古い `UpstreamFacts` が残らない／片面だけの差し替えでもう片面が触られない（`assert_ne!` で防げない帰属の族 —— 2面の値を全部違えること）。
- **`F-4b-2`（決定7）**: 6 世代目で最古の1組だけが消える／もう片面のログと、exe が名付けていないファイルは残る／消せなくても起こす。**「最新」は時刻の綴りで決まるので、同じ秒に2回起こす腕も要る。**
