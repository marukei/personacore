# ADR-0011: `character.name` を `handle` と `display_name` に分ける

- 状態: **採用**
- 日付: 2026-08-14

## 背景

**`character.name` が3つの役割を兼ねている。**

1. **プロンプトに載る呼び名** — `src/prompt/mod.rs` の `render_system` が
   `NAME_HEADING` の下に書き出す（見張り番は `the_character_name_is_always_present`）
2. **`model` フィールドで指す識別子** — `aoi` / `aoi@new`（[ADR-0004](0004-session-identification.md)）
3. **一意性のキー** — `UNIQUE` 制約 ＋ 正規化キーの索引

3 のせいで、**同じ名前で別のペルソナを持てない。**
ところが回避しようと `葵-実験A` と名付けると **1 が汚れる** —
プロンプトに「葵-実験A」という名前で載る。
**比べたいのはペルソナなのに、名前という別の変数が混ざる。**

これは「変種を並べて残しておきたい」場面で効く。
[06-roadmap.md](../06-roadmap.md) のマイルストーン5の検証手順そのものは
**同一キャラの値を書き換えて比べる**形なので塞がれていないが、
ペルソナの違う個体を共存させたくなった時点で行き止まりになる。

## 決定

**`name` を2つの列に分ける。**

| 列 | 役割 | `UNIQUE` | 例 |
|---|---|---|---|
| `id` | 内部キー（既存・変更なし） | — | 1 |
| `handle` | `model` で指す／`/v1/models` に並ぶ | **あり** | `aoi` / `aoi-v2` |
| `display_name` | **プロンプトに載る呼び名** | **なし** | `葵` / `葵` |

`aoi` と `aoi-v2` が**どちらもプロンプト上は「葵」**として共存する。

## 理由

現行の制約は、そのまま `handle` 側へ移す。

- **`@` 禁止**（`model` の予約語と衝突するため。ADR-0004）
- **登録時に正規化し、照合は完全一致**（同上）
- **正規化キーの `UNIQUE` 索引**（ゴースト行対策。同上）

`display_name` にはこれらが要らない。`model` に現れないので `@` を禁じる理由が無く、
一意である必要も無い。ただし**プロンプトの削れない枠に載る自由文**なので、
絶対制約どおり**上限を持つ型**にする。

型は分ける。`CharacterHandle` と `DisplayName` を別の newtype にして、
取り違えを型検査で落とす（`StatAxis` と `CharacterName` を分けたのと同じ理由）。

> **名前が概念に追いついたのは 2026-08-16（0004b-3）。**
> この ADR が識別子と呼び名を分けたのに、**識別子側は `CharacterName` / `character.name` のまま**で、
> 「名前」がどちらを指すのか読むたびに判断が要る状態が続いていた。
> **いまは `Handle` / `character.handle`**（`/admin/` の JSON も `handle`）。
> **`/v1/models` の `id` と `model` の書式は変えていない。**
> 以下の本文は当時の名前で書かれている。

### 却下した選択肢

- **UUIDv7 を内部キーにして、手打ち用のエイリアスを別に持つ** —
  「エイリアス」がここでの `handle` そのもの。UUID 側が追加で解くのは
  別マシンの DB のマージだけで、単一 DB 内の衝突しない内部キーは
  **`character.id` として既にある**（[ADR-0010](0010-session-id-identity.md)）。
  同じ設計に UUID の分だけ高くつく。
- **`display_name` を持たず、プロンプトから名前を落とす** — 名前が無いと
  キャラクターが自分を指せない。`NAME_HEADING` は削れない枠の中核。
- **同名を許して `UNIQUE` を外す** — `model` で一意に指せなくなる。ADR-0004 の前提が壊れる。
- **分けない（現状維持）** — 変種を並べられない。プロンプトに実験用の名前が載る。

## 結果

### 得られるもの

- **同じ呼び名で別ペルソナの個体を共存させられる。** 比較実験で名前が変数にならない
- `handle` が「利用者が打つ短い識別子」に純化する（`aoi-v2` のような命名が自然になる）

### 諦めたもの / 前提

- **`/v1/models` に並ぶのは `handle`。** 一覧の見た目が `葵` ではなく `aoi` になる。
  OpenAI のモデル id も同様の見た目なので許容する
- 列と API が増える。`/admin/characters` の要求・応答が変わる
- **`character` への列追加・改名は `ALTER TABLE` で足りる**（テーブル再構築が要る
  [ADR-0010](0010-session-id-identity.md) とは別のマイグレーションにできる）

### 実装の順序（2026-08-14 追記）

**2つの作業単位に割る。どちらも単独でコンパイルが通る形にする。**

| # | 内容 | 何が手に入るか |
|---|---|---|
| **0004a** | `display_name` 列と `DisplayName` 型を足す。`prompt` がそちらを載せる | **capability はここで全部手に入る**（`aoi` と `aoi-v2` が両方「葵」になる） |
| 0004b | `name` → `handle` の改名（列・型・API） | 名前が役割を語るようになるだけ |

0004a の時点で `name` は**実質すでに handle** である（一意・`@` 禁止・`model` で指す）。
改名しなくても機能は揃うので、**危険な部分（マイグレーション）と機械的な部分（改名）を混ぜない。**

> **`character` テーブルの再構築は避けること。** `character` は5テーブルから参照されており、
> [ADR-0010](0010-session-id-identity.md) で分かった「親を落とすには子を全部落とす必要がある」
> を適用すると**スキーマ全体の再構築**になる。`ALTER TABLE` で済ませる。

### 実装上の注意

- **`ModelSelector` は変更不要。** 返すのは「名前部」であり、
  それを `handle` として照合するかは呼び出し側の解釈。ただし型名は見直す
- **プロンプトに載るのは `display_name` だけ。** `handle` が混入していないことを
  `prompt` のテストで固定すること（混入しても動くので、テストが無いと気づけない）
- 正規化キーの `UNIQUE` 索引は `handle` に張り替える。
  [ADR-0004](0004-session-identification.md) の「ゴースト行が残ったときに何が起きるか」は
  そのまま `handle` の話として引き継がれる
