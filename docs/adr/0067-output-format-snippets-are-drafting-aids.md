# ADR-0067: 出力形式の指示の定型文は、画面で差し込む下書きにする。保存するのは自由文のまま

- 状態: 採用（2026-11-19。作業単位 D-22 = marukei/personacore#70）
- 日付: 2026-11-19
- 関連: [ADR-0007](0007-output-format-markup.md)（出力形式。形式指示はキャラクターごとに DB へ持つ）/
  [ADR-0029](0029-language-as-a-matched-bundle.md)（言語は束。束の文面は測定の結果物）/

## 背景

キャラクターの「出力形式の指示」（`output_format_instruction`）は、上限 150 字の自由文である。プロンプトには、その文字列が `# 出力形式` の節に引用（`> `）でそのまま載る（ADR-0007）。未設定なら節ごと落ちる。

利用者はキャラクターを作るたびに、ほぼ同じ指示を手で書いている。

- キャラクターの台詞は「」で囲む。
- 地の文はそのまま出す。
- 明確な心情描写は（）で囲む。
- 利用者の台詞を代弁しない。

これを項目ごとに選んで入れられるようにしたい。形は2つ考えられた。

1. 画面で差し込む下書きにする。保存されるのは、いまと同じ自由文。
2. 項目の選択として保存し、組み立てが言語の束の文を作る（ADR-0065 の目安と同じ形）。

## 決定

### 1. 定型文は画面の下書きの補助にする。サーバ・DB・プロンプトは変えない

- キャラクター編集画面の出力形式の欄の下に、項目ごとのボタンを置く。押すと、その文が欄の末尾に1行で入る。
- 入れた後は、運用者が手で書いた文と同じ自由文になる。自由に直せ、保存の検査（150 字の上限）も今までどおり。
- 欄のどれかの行がすでにその文と同じとき、入れると 150 字を超えるとき、保存中は、ボタンを押せない。

### 2. 文面は画面の側に置く。言語の束ができたら束へ移す

- 文面は利用者が長く使ってきたもので、測定していない。ADR-0029 §決定4 は束の文面を測定の結果物として扱う。測っていない文を束の定数にはしない。
- 言語の束の型はまだコードに無い（ADR-0029 は採用済みだが、実装はまだで、`ja` の定数が `prompt` に置かれているだけ）。束から文面を画面へ出す経路も無い。
- 束ができて、出力形式の定型文を束で持つことになったら、この文面を束へ移し、測る。

## 却下した選択肢

- **項目の選択として保存し、組み立てが文を作る。** 言語を切り替えても付いてくる。しかし、文面を測ってからでないと束の定数にできない（ADR-0029 §決定4）。触る面も広い（ADR-0065 の前例では、列の追加からプロンプトの見張り番、修復フォームまで全層に及んだ）。いま言語の切り替えは無いので、付いてくる利点はまだ使われない。
- **出力形式の欄の上限（150 字）を上げる。** 4項目は合わせて 54 字（行の間の改行を含めて 57 字）で、上限の中に収まる。削れない枠の余白（`FIXED_FRAME_SLACK`）は 83 バイトしか残っていない（ADR-0065 §結果）。

## 結果

- サーバ・DB・API・プロンプトは1バイトも変わらない。差し込んだ文は手で書いた文と区別されない。
- 言語を切り替える仕組みができても、差し込んだ文は付いてこない（運用者の自由文なので）。
- 「利用者の台詞を代弁しない」が実際にどれだけ効くかは、測っていない。
