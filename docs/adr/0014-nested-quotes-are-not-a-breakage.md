# ADR-0014: 入れ子の `「」` は崩れとしない。1段目を取り、発生を記録する

- 状態: **採用**
- 日付: 2026-08-15
- 関連: [ADR-0007](0007-output-format-markup.md) の「崩れの判定」を1つ変更する

## 背景

[ADR-0007](0007-output-format-markup.md) は崩れを3つに限定し、そのうち
`FallbackReason::Nested`（`「外「内」外」`）を**モデルの崩れ**と位置づけていた。理由は
「日本語の慣習では入れ子は `『』` を使う」。

**マイルストーン5の実測でこれが崩れではないことが分かった**
（[ADR-0012](0012-stat-section-directive.md) の結論2）。

> 「…『誰かが**「生ケーキ」**って言い出して大騒ぎ』…」

**モデルは日本語として正しく書いている。** 他の内側引用は `『』` を使っており、1箇所だけ滑った。
**ユーモアの値が高いと逸話を語るので、引用が入れ子になりやすい。**
この現象は**別のサーバ・別の DB での独立した測定で再現している**（`ユーモア=10` × 失敗の告白）。

現状の実装は入れ子を見つけた瞬間に**応答を丸ごと地の文へ落とす**ので、
**1段目すら捨てている。** 11b-2 で永続化が始まったため、この回の `dialogue` は `NULL` で溜まる
（`raw_content` は残るので後から再解析はできるが、その導線が別途要る）。

## 決定

**入れ子を崩れから外す。**

1. **1段目の `「` から、対応する `」` までを台詞とする。**
   内側の `「」` は**台詞本文にそのまま残す**（除去も置換もしない）。
2. **入れ子が起きたことを `ParseOutcome` に記録する。**
   フォールバックはしないが、**発生率をログで追えるようにする。**

`FallbackReason` から `Nested` を外し、崩れは `Unclosed` と `StrayClose` の2つになる。

## 理由

**大事なのは、地の文との続きでないことを明示する1段目の `「」` を確実に捉えること。**
内側の引用がどう書かれているかは、その判断に要らない。

### 却下: 形式指示で `『』` を促す

**読むときに違和感がある。** `「彼は『行く』と言った」` は慣習として自然だが、
**「内側は必ず `『』`」を強制すると、モデルが不自然な位置でも `『』` を使い始める。**
加えて形式指示はキャラクターごとの値なので、**書き漏らした個体だけ静かに劣化する。**

### 却下: 入れ子を「正当」と宣言するだけ（記録しない）

**実装は最小になるが、いつか破綻したときに気付けない。**
モデルの生成能力が上がる／キャラクターが饒舌になると、入れ子は増える方向にしか動かない。
**「許可」ではなく「捕捉して記録」にする。** 増えたら手を打てる。

### 却下: 現状維持

実測した条件で**台詞が失われ続ける。** `raw_content` があるので回復不能ではないが、
**分解済みの列を前提にする処理（フェーズ2の要約・想起）が、その回だけ静かに空になる。**

### `『』` を台詞の括弧に加えない方針は変えない

ADR-0007 の「`『』` を台詞に含めない」はそのまま有効。
**むしろこの決定で理由が強くなる**（内側の `『』` も `「」` も等しく本文として残るので、
慣習どおりに書かれた出力が崩れ扱いされることが無くなる）。

## 結果

- **`ユーモア` が高い個体で台詞が失われなくなる。** 実測で唯一の崩れだった条件が解消する。
- **入れ子の発生率が観測できる。** ADR-0012 が「上端で形式が崩れる」と呼んでいた現象の
  一部はこの規則の産物だったので、**切り分けたうえで残りを測り直せる。**
- **不均衡な入力の壊れ方は変わらない。** `「あ「い」` は閉じないので `Unclosed`、
  `」あ「い」` は `StrayClose` のまま。**崩れの判定が緩むのは入れ子だけ。**
- **`ParseOutcome` の値が増える。** 集計キー（`label()`）が増えるので、
  ログを数える側は新しいラベルを知らないと取りこぼす。
