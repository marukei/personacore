## 背景

### 1返答の暴走が、履歴を通って会話を壊し続ける（2026-11-13 の測定）

第三者の推論サーバ（marukei/personacore#30 と同じもの。以下「その推論サーバ」。モデルは Qwen3.8-Flash-Next の IQ3_S）を `repeat_penalty 1.0` の上流プロファイルで使った会話で、7往復目の返答が途中から短い単位の繰り返しに入った。単位は引用符で囲んだ1語と読点・三点リーダの組。次の返答は履歴にあるその繰り返しを引き継ぎ、最初からほぼ全文が繰り返しになって `max_tokens` で切れた。会話はそれきり戻らなかった。

利用者の DB の複製から本文の要求を捕まえ直し、値だけ変えて上流へ直接送り直した（数の詳細は marukei/personacore#55）。

| 要求 | `repeat_penalty 1.0` | `repeat_penalty 1.1` |
|---|---|---|
| 暴走の前（履歴は健全） | 2/20 が暴走 | 0/20 |
| 暴走が履歴に入った後 | 11/11 が暴走（8/10 が `max_tokens` で切れた。切れた回は 1 回 62〜91 秒） | 0/10 |

- **暴走は1返答ごとに1割ほどで起き、いったん履歴に入ると次のターンはほぼ必ず引き継ぐ。** 会話が壊れ続けるのはこの引き継ぎによる。
- marukei/personacore#30 の崩れ（1.1 で返答が早く終わって縮み、短い返答が履歴に入って次も短くなる）と同じく、入口は1回の悪い生成で、それを履歴が固定する。1.1 は縮む側の入口を広げ、1.0 は繰り返す側の入口を広げる。量子化を替えると 1.0 でも縮んだ（marukei/personacore#30 の追記）。**罰の値は上流プロファイル（エンジン＋モデル＋量子化）ごとに違い、どの値でも片側の入口が残る。**
- 長い会話の後半に出る冗長さ（句を組み替えて同じ内容を言い直す。marukei/personacore#38）とは別の現象である。暴走した返答は、まともに見える前半に、同じ文字列がそのまま何十回も続く後半が付く。

### 暴走は文字の並びだけで見分けられる

返答の空白を除いた文字列で、**周期 p（2〜64 文字）の単位がそのまま3回以上続く区間**の最長を数えた（`t[i] == t[i+p]` が `2p` 文字以上続く区間。長さは続いた文字数 ＋ p。したがって長さの下限は `3p`）。測定の置き場所に残っていた返答 868 本と、利用者の DB の返答 60 本、合わせて 928 本（空白を除いて 20 文字未満のものは除いた）に当てた。どれもその推論サーバの日本語の返答である。

| 区間の最長 | 本数 | 中身 |
|---|---|---|
| 64 文字以上 | 41 | 最短の 67 文字から 163 文字までの 12 本は全部読み、どれも同じ文か句を3回以上そのまま繰り返すループだった。それより長い 29 本は、背景の利用者の2返答と、その暴走の再現の腕と、強い念押しなどで崩れた過去の測定の腕のものだけ（最長 2524 文字） |
| 40〜63 文字 | 3 | 全部読んだ。4 文字の単位を13回繰り返して自然に止まった返答（52 文字）、同じ文の並びを3回続けた返答（60 文字）、2つの句を交互に言い直した返答（41 文字） |
| 40 文字未満 | 884 | 読んだのは利用者の DB の 58 本で、どれもまともな返答（最大 19 文字。冗長さの溜まった返答も 19 文字以下で、この判定には掛からない）。残りは数だけ |

- 区間は、暴走が続くかぎり伸び続ける（暴走の再現で当たったものは 112〜1908 文字）。
- **同じ文を2回言い直すのは、強調として書かれうる。** 3回で区切ると、測った範囲では言い直しを拾わずにループだけを拾えた。
- 数え方は文字だけで、トークナイザにも上流にもよらない。

### いまの仕組み

- 履歴の返答は `prompt::history_turn` が `message.raw_content` から漏れた思考を剥がし、`SafeText::sanitize` を通して載せる（ADR-0053 §決定4）。分解（`server::turn`）と記憶抽出（`character_message`）も剥がしてから読む。変容・試用・約束の提案は、記憶抽出と同じ `character_message` を読む。
- 中継（`server::relay`）は上流の本文の差分を、剥がさずにその場で利用者へ流す。空の本文の引き直しのために、本文が空のときだけ `finish_reason` 付きのチャンクと `[DONE]` を保留する（ADR-0059 §決定3）。**保存するのは上流が正常に終わった回だけ**で、途中で壊れた回や利用者が切った回は保存しない（中継のモジュール doc と `TurnSink::persist` の doc、英語のガイド）。
- 中継が上流のストリームを落とすと、上流への接続が閉じる（中継のモジュール doc の「切断時のキャンセル」。見張り番が固定しているのは接続が閉じるところまでで、上流が生成をやめるかは上流の振る舞いである）。

## 決定

### 1. 暴走の判定は `domain` の純粋関数1つに置く

ADR-0053 §決定1 と同じく、`domain` に純粋関数を置き、読み手は全部それを通る。返すのは、暴走の区間（位置・周期・長さ）の一覧と、それを畳んだ本文である。

- **区間:** 空白を除いた文字列で、周期 p（2〜64 文字）の単位がそのまま3回以上続き、長さが 64 文字以上のもの（長さの下限は `max(3p, 64)`）。区間が重なれば長いほうを採る。
- **畳み方:** 区間を単位1回分だけ残して落とす。区間の後ろに本文が続いていれば残す。空白（改行を含む）は、残す側では元の位置のまま保ち、落とす区間の中のものは一緒に落とす。
- **値の来歴を名乗る**（ADR-0033）。3回・64 文字・周期の上限 64 は、背景の 928 本から決めた（どれもその推論サーバの Qwen3.8-Flash-Next の日本語の返答。ほかのモデル・ほかの言語は測っていない）。定数の doc に、測った対象と、境目のすぐ下にあった3本の形（上の表）を書く。
- 同じ入力には同じ結果を返す（会話キャッシュのため。§決定3）。

### 2. どこで畳むか —— 分解・履歴・裏方（保存と画面と API の使い手を除く）

| 読み手 | 畳むか |
|---|---|
| `message.raw_content`（保存） | **畳まない**（絶対制約） |
| `parse_response` に渡す本文（保存する `dialogue` / `narration`、パース成功率のログ） | 畳む。漏れた思考を剥がした**後**に畳む |
| `prompt::history_turn`（次のターンのプロンプト） | 畳む。剥がした後、`SafeText::sanitize` の**前**に |
| 裏方のサブLLM（記憶抽出の `character_message` と、それを読む変容・試用・約束の提案） | 畳む |
| 画面 | **この決定では畳まない**（§決定6） |
| OpenAI 互換 API の使い手に返す本文 | 畳まない。中継は §決定4 で打ち切る |

- **既に保存された暴走も、次のターンから畳まれて履歴に載る。** 生の出力から毎回畳むので、移行は要らない。暴走が履歴に入った会話も、その次のターンから引き継ぎの入口が閉じる見込みである（§決定7 で測る）。
- 保存する `dialogue` / `narration` が畳まれるのは、この決定の後に書く行だけである（ADR-0053 の B-61 と同じ）。
- 畳んだ後が空になることは無い（単位1回分は残る）。

### 3. 会話キャッシュを崩さない

畳むのは生の出力から決まる純粋関数なので、同じ返答は毎ターン同じ綴りで履歴に載る。畳みで変わるのは、前のターンの要求の**後ろ**（生成された返答の部分）だけで、そこは思考を剥がしている今も生成の綴りと食い違っている位置である。ADR-0061 で戻した記憶の移動は、前のターンの要求の**中**（最新の発言）を変えたので再利用が切れた。畳みはそれと違い、新しい食い違いを増やさない。

- ただし、出した直後の最初のターンに限り、既に保存された暴走を含む会話では、履歴の綴りが前のターンの要求から変わるので、そのターンの再利用は1回だけ切れる。

### 4. 中継は、暴走が十分に長くなった時点で上流の生成を打ち切る

- **判定は、上流から受けた生の差分を積み上げたものに当てる**（剥がす前）。中継は差分を剥がさずに流しており、剥がした後の本文は、後から届く閉じタグで先頭まで遡って変わりうる（ADR-0053 §決定2・§決定6）。思考が本文の差分に漏れる上流では、思考の中のループも打ち切ることになるが、思考の中のループも `max_tokens` まで続く点は同じである（その推論サーバは思考を別欄で返すので、この形には当たらない見込み。ADR-0059 の背景）。打ち切った回の本文が閉じない思考だけだったなら、今と同じく空として保存される（引き直さない。ADR-0059 §決定3）。
- **打ち切るのは、畳む区間の長さの合計が 256 文字に達したとき**（§決定1 の区間を、届いた文字ごとに数え足す。積み上げた全体を毎回数え直さない）。数え足す側は §決定1 の純粋関数と別の実装になりうるので、同じ入力で両者の合計が一致することを見張り番で固定する（§決定7）。空の本文の引き直しで次の回へ移るときは、積み上げた本文を捨てるのに合わせて合計も捨てる。畳む基準（64 文字）より4倍高くするのは、誤って打ち切ったときの壊れ方が、誤って畳んだときより重いからである（下の「誤検出の壊れ方」）。
- 打ち切ったら、検出したチャンクまでを利用者へ流したうえで上流のストリームを落とし、`finish_reason: "length"` の終わりのチャンクと `[DONE]` を流して、その回を保存する。
  - `"length"` は、既にある閉じた値で、OpenAI 互換の使い手にとって「途中で切られた返答」の意味である。新しい値を足すと、知らない値で落ちる使い手が出る。
  - 保存する `raw_content` は、打ち切るまでに受けて流した生の出力と同じである。
  - **打ち切った回を保存するのは、「保存するのは上流が正常に終わった回だけ」という今の約束を改めることになる。** 打ち切った回は失敗した回ではなく、personacore が返答を終えた回である。暴走した後半は保存されても、読み手には §決定2 で畳んで渡るので、履歴は汚れない。中継のモジュール doc、`TurnSink::persist` の doc、英語のガイドを直す。
  - 引き直しの数え方（ADR-0059 の追記の決定1）では、打ち切った回は `finish_reason` が `length` で終わった回として扱う。本文がある回なので引き直しの対象にはならない。
- 打ち切った回は、上流から `usage` が届かない。答え合わせ（ADR-0013 第3層）は `usage` が無いと記録を残すだけで判定せず、封の清算（ADR-0052）は `server::seal` の `Unjudged` になる。上流が `usage` を返さなかった回と同じである。ログには、打ち切ったことと、区間（周期・長さ）と合計を1行で出す。
- **ADR-0035 とは別の話である。** ADR-0035 は時間の値で中継を打ち切らないと決めた（外から「遅い」と「死んだ」は区別できない）。この決定は、生成された中身を見て打ち切る。中身は観測できる。
- 非ストリーミングは、上流が返し切ってから受けるので打ち切れない。返す本文は変えず、保存と読み手の側で §決定2 のとおり畳む。

### 5. 引き直さない

暴走した回を引き直す（空の本文の引き直しと同じ形）ことはしない。

- 中継では、暴走が始まるまでの本文はもう利用者に流れている。引き直しの本文を続けて流すと、前半が2回出る。
- 打ち切って畳めば、その回の前半（多くはまともな本文）は残り、次のターンへの引き継ぎも閉じる。引き直して得られるのは「まともな後半」だけで、そのための待ち（もう1回分の生成）と仕組みの重さに見合わない。
- 非ストリーミングだけ引き直すと、経路で振る舞いが分かれる。

### 6. 画面は、この決定では畳まない

画面は返答の本文を生の出力から自前で剥がしている（ADR-0053 §決定4。規則は TS に写してある）。暴走を畳むには、判定も TS に写して両方で同じ表を読む必要がある。中継の打ち切り（§決定4）で、これから流れる暴走はおよそ数百文字に収まる。既に保存された暴走は、画面には全文が出たままになるが、モデルには畳んで渡る。画面の作業は別の作業単位にする（必要になったら Issue を開く）。

### 7. 見張り番と、出した後に測ること

- **単体（`domain`）:** 背景の境目の形を固定する。周期 2 で 64 文字ちょうどの区間（畳む）と 63 文字（畳まない）、周期 21 で3回ちょうどの 63 文字（畳まない）と周期 22 で3回ちょうどの 66 文字（畳む）、周期 64 で3回ちょうどの 192 文字（畳む）、周期 65 の3回（畳まない）、2回だけの言い直し（畳まない）、区間の後ろに本文が続く形（後ろは残る）、改行をまたぐループ、区間が2つある形。同じ入力に同じ結果を返すこと。打ち切りの合計は 255 文字と 256 文字の両側で見る。
- **読み手ごと:** 履歴・分解・記憶抽出の3つで、暴走を含む `raw_content` が畳まれて届き、保存の `raw_content` は畳まれないこと（同じフィクスチャで両方を見る）。漏れた思考との順序（剥がした後に畳む）。
- **中継:** 暴走を流す偽の上流で、合計が 256 文字に達したチャンクで上流への接続が閉じ、利用者へは検出したチャンクまでと `"length"` と `[DONE]` が届き、流したものと同じ生の出力が保存されること。暴走しない本文と、畳むが打ち切らない長さ（合計 64〜255 文字）の本文では打ち切らないこと（対照）。空の本文の引き直しの2回目・3回目で打ち切ったときも同じであること（前の回の合計を持ち越さないこと）。数え足した合計と、積み上げた全文に純粋関数を当てた合計が、チャンクの切れ目を変えても一致すること。
- **ログ:** 分解の行に、畳んだ区間の数と最長の区間の長さを欄として出す（0 の回も出す。ADR-0053 §決定5 と同じ理由）。中継の打ち切りは別の行で言う。
- **出した後に測ること:**
  - 暴走が履歴に入った後の要求（背景の 11/11）を、畳んだ履歴で送り直して、引き継ぎが止まるかを測る。
  - 打ち切った後に、上流が実際に生成をやめるか（次の要求の待ち時間か上流の記録で見る）。
  - 遊んだ記録のログの欄で、畳みと打ち切りの頻度を数える。誤って打ち切った回が出たら、この ADR の追記で値を見直す。

### 8. `repeat_penalty` の値は拒まない

`repeat_penalty 1.0` を書けないようにはしない。警告も出さない。

- 1.0 は marukei/personacore#30 で、1.1 だと返答が縮んで崩れるために選んだ値である。正しい値は上流プロファイルごとに違い、量子化を替えるだけでも変わる。値で拒むと、実測由来の値を「外したら壊れる場所」に置くことになる（ADR-0036 §決定1）。
- この ADR で、繰り返す側の「履歴が固定する」部分は値によらず閉じる。値の選び方は、縮む側と繰り返す側の釣り合いの問題として、上流プロファイルを書く人に残す（A-19 の校正で候補を示す話。marukei/personacore#37）。

### 9. API の版を `1.10` にする（小さい側）

ADR-0047 の互換の方針に当てはめると、次の3つはどれも小さい側とする。欄・口・`enum` の値は増減しない。2つ目（打ち切った回も保存する）は、英語のガイドの約束を改めるので、ADR-0047 の表の「意味の変更」（大きい側）との境目に当たる。それでも小さい側とする理由は、(a) 上流の `max_tokens` で `"length"` に終わった回は今までも保存されてきたので、使い手から見て「`"length"` で終わって `[DONE]` が届いた回は保存される」という規則は変わらない、(b) `"length"` は既に閉じた値として `enum` に入っている、(c) 使い手が切った回・上流が壊れた回を保存しないことは変わらない、の3つ（境目の扱いは、ADR-0047 の `1.3` → `1.4` の F-10a に倣う）。

- `GET …/messages` の `dialogue` / `narration` で、新しく書く行は暴走の区間が畳まれる（`raw_content` はそのまま）。ADR-0047 の `1.3` → `1.4` で、漏れた思考を外したのと同じ扱い。
- `/v1/chat/completions` のストリーミングは、personacore が打ち切ったときに `finish_reason: "length"` で終わる（値は既にある）。打ち切った回は保存される。
- 英語のガイドの「保存は上流が正常に終わった回だけ」「返す本文はモデルが生成したとおり」に、打ち切りの例外を足す。

## 理由

### 誤検出の壊れ方（ADR-0036 §決定1 の問い）

| 値が外れたとき | 畳む（64 文字） | 打ち切る（合計 256 文字） |
|---|---|---|
| 低い側（まともな返答に当たる） | 意図した繰り返しが、履歴と裏方で単位1回分に畳まれる。モデルに渡る文脈が少し欠けるが、遅くはならず、利用者の画面と `raw_content` には全文が残る。分解の行の欄で数えられる | **利用者に流れている返答が途中で切れる。** 壊れる側である。ただし `finish_reason: "length"` と打ち切りの行で必ず分かり、黙っては起きない。測った 928 本で当たらなかった 887 本の区間は、短いループを含めても最大 60 文字、ループでない返答では最大 41 文字（2つの句を交互に言い直した返答）で、合計 256 文字はそれぞれの4倍・6倍以上。当たった 41 本のうち読んだ 12 本はどれもループで、残りの 29 本は暴走した会話と腕のもの |
| 高い側（暴走を拾わない） | 今と同じ（暴走が引き継がれる） | 今と同じ（`max_tokens` まで流れる。遅くなるだけ） |

- 打ち切りの低い側の壊れ方は重いので、畳む基準とは分け、測った範囲のまともな返答から大きく離した。高い側に外れても、今より悪くはならない。
- **つまみにはしない**（ADR-0036 §決定3）。根拠となる計測がある（条件1を満たさない）。つまみにすると、利用者に測り直させることになる。誤って打ち切った回が出たら、ログで分かるので、ADR の追記で値を直す。

### 却下した選択肢

- **`repeat_penalty 1.0` を読み込みで止める／既定を 1.1 に戻す。** §決定8。marukei/personacore#30 で 1.1 を全上流に固定で送っていたことが、縮む崩れの原因の1つだった。
- **罰の値だけで解く**（1.05 など中間の値を探す）。1.05 は、別のキャラクターで冗長さの溜まった履歴から流した2腕で暴走 0/25 だった（旧式の判定の数で、読んで確かめていない。§決定1 の判定でも当たりは 0。背景の暴走が起きた要求では 1.05 を測っていない）。縮む側は上流プロファイルごとに測るしかなく、値は片側の入口の広さを変えるだけで、「1回の悪い生成を履歴が固定する」形は残る。
- **`dry_multiplier` などのサンプラで止める。** 暴走の再現で `dry_multiplier 0.8` は効かなかった（5/20。その推論サーバがこの欄を受け付けたかは確かめていない）。サンプラの名前と効き方は上流ごとに違い、全上流に送れない。
- **打ち切りを畳みと同じ 64 文字で行う。** 上の表のとおり、誤って打ち切ったときの壊れ方が重い。暴走は続けば区間が伸びるので、基準を上げても打ち切りが遅れるのは二百文字ほどである。
- **暴走した返答を履歴から往復ごと落とす。** 前半のまともな本文と、その往復の利用者の発言まで失う。畳めば前半は残る。
- **暴走の区間から後ろを全部切る**（区間の後ろに本文が続いていても捨てる）。測った暴走は、どれも区間が返答の終わりまで続いていた。それでも、ループが自然に止まって本文に戻った回で、戻った本文を捨てる理由が無い。
- **冗長さ（句を組み替えた言い直し）まで同じ仕組みで扱う。** 判定は文字の並びの完全な一致に頼る。言い直しは並びが毎回違うので、同じ判定では拾えない。拾える閾値まで下げると、強調の繰り返しまで畳む。冗長さは念押し（marukei/personacore#38）で扱う。
- **引き直す。** §決定5。

## 結果

### 得られるもの

- 1返答が暴走しても、次のターンへ引き継がれにくくなる（見込み。§決定7 で測る）。既に壊れた会話も、次のターンから畳まれた履歴で続けられる。
- 中継では、暴走が `max_tokens` まで流れ続けなくなる（背景の測定では、2048 トークンで切れた回は 1 回 62〜91 秒かかっていた）。上流が接続の切断で生成をやめるなら、その待ちと計算も使わずに済む（見込み。§決定7 で測る）。
- 裏方の読み手（記憶抽出ほか）にも、暴走した全文が渡らない。

### 諦めるもの・新しく負うもの

- **同じ文を3回以上そのまま繰り返す返答は、意図した表現でも履歴と裏方で畳まれる。** 中継で合計 256 文字に達すれば、その後ろは受け取らず流さない（`raw_content` にも残らない）。測った 928 本では、当たった 41 本のうち読んだ 12 本はどれもループで、残りは暴走した会話と腕のものだった。
- **3回以上続いたが 64 文字に届かずに止まった短いループ（背景の 52 文字・60 文字）は拾わない。**
- 打ち切った回は `usage` が届かないので、答え合わせと封の清算を飛ばす。
- 打ち切った回を保存するので、「保存するのは上流が正常に終わった回だけ」の約束が変わる（§決定4・§決定9）。
- 画面には、既に保存された暴走の全文が出たまま（§決定6）。

### この ADR が答えていないこと

- 縮む側（marukei/personacore#30）の入口を、同じように値によらず閉じる方法。
- 判定の値が、ほかの言語・ほかのモデルの返答でも境目を保つか。
