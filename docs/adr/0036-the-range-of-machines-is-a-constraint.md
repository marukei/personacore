# ADR-0036: 動く環境の幅を、設計の制約として宣言する

- 状態: **採用**
- 日付: 2026-08-26
- 関連: [ADR-0033](0033-measured-constants-name-what-they-were-measured-on.md)（**第3階層の機構**） /
  [ADR-0035](0035-the-watchdog-reports-the-human-decides.md)（**第2階層の最初の適用**） /
  [ADR-0020](0020-context-length-requery.md)（**第1階層の先例**） /
  [ADR-0029](0029-language-as-a-matched-bundle.md)（**継ぎ目だけ置く形の先例**）

## 背景

**測定はすべて1つのモデル・1つの機で行っている**
（`ministral-3-14b-instruct-2512` / RTX 4070 12GB / Ryzen 9 5900XT）。

[ADR-0033](0033-measured-constants-name-what-they-were-measured-on.md) は
**「実測由来の定数が、何で測ったかを名乗る」**までを決めた。
**名乗るだけで、埋め込むのをやめるとは決めていない。**

そして 2026-08-26 に、利用者から次の指摘があった:

> **RTX 4070 という固定された環境に特化しても良いことは無い。**
> **再起動で動きが変わることもあり得るし、GPU を載せ替えたらどうするのか。**
> **別環境でも試そうと M4 MBP や Windows ノートに持ち出したら。**

**そして同じ日に、司令塔がその誤りを2回続けて犯している** ——
**「行列の打ち手」として挙げた3案が3つとも 12GB VRAM とこの機の速さを前提にしており、**
**それを指摘している最中に「動き出した後に 30 秒黙ったら、どの機でも異常です」と書いた。**
**根拠は「この機のトークン間隔が数十ミリ秒」だった**
（[ADR-0035](0035-the-watchdog-reports-the-human-decides.md)）。

### ⚠ 幅は、目的そのものと結びついている

**低い環境で試せないものは、測り直せない。**
[ADR-0033](0033-measured-constants-name-what-they-were-measured-on.md) §4 の
「モデルを差し替えるときにやること」は、**別の環境で回せることを前提にしている。**
**幅を諦めると、差し替えの手順も同時に絵に描いた餅になる。**

## 決定

### 1. **「速い環境を要求してよい。遅い環境で壊れてはいけない」**

**遅いのは可。落ちる・ターンが消える・黙って劣化するのは不可。**

**判定の問い**は1つ:
**「この値を外したとき、遅くなるだけか、それとも壊れるか。」**

### 2. **実測由来の値を3階層に分ける**

| 階層 | 扱い | 例 |
|---|---|---|
| **1. 上流に引ける** | **引く。つまみにしない**（上流が権威） | コンテキスト長（[ADR-0020](0020-context-length-requery.md) が本文側で実施済み） |
| **2. 推測しかできない時間の値** | **外れても壊れない場所へ置く**（報告 / 緩い天井 / 人の中断） | [ADR-0035](0035-the-watchdog-reports-the-human-decides.md) |
| **3. トークナイザ由来** | **名乗る ＋ 器具で突き合わせる** | [ADR-0033](0033-measured-constants-name-what-they-were-measured-on.md) |

**第2階層が新しい。** **時間の値は「正しい定数も正しい適応も存在しない」**
（外から「遅い」と「死んだ」は原理的に区別できない）ので、
**値を正しくするのではなく、外れても壊れない場所へ移す。**

> ~~**⚠ `ASSUMED_SUB_CONTEXT_TOKENS`(16384) は第1階層なのに定数のままである。**~~
> ~~**`loaded_context_length()` を引く案は、その doc 自身が「13c-3 の宿題」と書いて先送りしている。**~~
> ~~**本文側は [ADR-0020](0020-context-length-requery.md) で引いている。抽出側だけが残っている。**~~
>
> **→ 解消した**（2026-08-27 / 作業単位 B-7）。**抽出も変容も、サブモデルの窓を上流に引く。**
> **定数は「まだ一度も引けていないときの落とし所」に役割が変わった。**
>
> **名前も変わっている**（古い ADR から grep したときのために）:
> `MAX_EXTRACTION_PROMPT_TOKENS` → **`SubContext::prompt_limit()`**（落とし所は `FALLBACK_EXTRACTION_PROMPT_TOKENS`）／
> `MAX_DRIFT_PROMPT_TOKENS` → **`drift_prompt_limit(SubContext)`**。
>
> **⚠ この第1階層で、いちばん高くついたのは「引いた値が全部の経路に届いているか」だった。**
> **門には届いていて、予算とログには届いていない状態が 1554 全緑を通った**
> （権威になるテストが落とし所で回っていたので、**2つの式が文字どおり同じ**になっていた）。
> **引くようにするのは半分で、残り半分は「引いた値で観測する」ほうにある。**

### 3. **つまみにする条件を絞る**

**設定可能にしてよいのは、次の3つが揃った値だけ:**

1. **根拠となる計測が無い**
2. **外すと破壊的**（遅くなるだけではない）
3. **こちらから導出も観測もできない**

**⚠ つまみは無料ではない。** 起動時に決めるものを増やすと、
**本番の入口を通るテストを足さない限り配線が観測対象から外れる。**
**実際に起きた** —— `App::bind_with_client`（モック注入用）を足した結果、
**本番の入口 `App::bind` だけを通るテストが無くなり、予算を丸ごと捨てる変異が2つとも緑を通った。**

**足すつまみ1つにつき、`App::bind` を通る見張り番を1本足すこと。**

> **1〜3 が揃わない値は、つまみではなく階層1か2で解くこと。**
> **つまみは「利用者に測り直させる」であって、解決ではない。**

### 4. **上流を1つに決めない。ただし2つ目を約束もしない**

**継ぎ目は `llm::LlmClient`**（`complete` / `stream` の2メソッド）。
**2026-08-26 時点で、上流固有の漏れは1箇所しかない:**

| 場所 | 何 |
|---|---|
| `server/context.rs` | **`LmStudioClient` 具体型に依存**（`loaded_context_length` はトレイトの外） |
| `server/mod.rs` | **構築点。当然であって漏れではない** |

**LM Studio 以外（Hugging Face から落として直に動かす等）を採るかは未決。**
**この ADR では約束しない。**
[ADR-0029](0029-language-as-a-matched-bundle.md) と同じ形 ——
**継ぎ目を置くだけで、2つ目の実装は約束しない。**

> **⚠ ただし「継ぎ目がある」を主張し続けるには、漏れを数え続ける必要がある。**
> ~~**いまは1箇所。増えたら、それは決定の変更である。**~~

>
> **上の表と「1箇所」は、書いた時点でも少なく数えていた。**

> **3つの数を同時に固定している**（**1つを保ったまま別のを動かす変更を通さないため**）:

> | 数え方 | 止める形 |

>

> **引き金を引いたかどうかは、テストが赤くなるかで決まる。**
>
> **⚠ そして、この帳簿が数えているのは「LM Studio への結合」ではなく

## 理由

### 却下した選択肢

- **全部を起動時に測る** ——
  **トークナイザの綴りの探索は上流への往復が要り、上流が落ちていると起動できなくなる**
  （[ADR-0033](0033-measured-constants-name-what-they-were-measured-on.md) が既に却下）。
  **時間の値については、そもそも「正しい測定」が存在しない**
  （[ADR-0035](0035-the-watchdog-reports-the-human-decides.md)）。
  > **⚠ 0033 の却下欄はトークナイザの話として書かれているのに、全体を却下したように読める。**
  > **範囲を訂正した**（あちらに追記）。
- **全部をつまみにする** —— **見張り番の費用**（決定3）。
  **そして既定が壊れているなら、大半の利用者にとって意味が薄い。**
- **低い環境を切り捨てて、この機に最適化する** ——
  **試せないものは測り直せない**（背景）。**差し替えの手順が成立しなくなる。**
- **抽象を厚くして上流を差し替え可能にしておく** ——
  **2つ目の実装が無いうちに作った抽象は、1つ目の形をなぞるだけになる。**
  **漏れを数えるほうが安く、正直である。**

## 結果

### 得られるもの

- **「壊れる」と「遅い」が分かれる。** 持ち出しても、遅いだけで動く。
- **判定の問いが1つになる**（決定1）。**値ごとに議論しなくてよい。**
- **上流を替える余地が、コストつきで見える**（決定4 の表が1行で済んでいる間は安い）。

### 諦めたもの / 前提

- **⚠ 遅い環境での体感は保証しない。** 動くこととしか言っていない。
- **⚠ 実測値の一覧（[ADR-0033](0033-measured-constants-name-what-they-were-measured-on.md)）は
  依然としてこの機・このモデルのもの。** **この ADR はそれを直さない。**
  **外れたときに壊れない形へ移すだけ。**
- **⚠ 別環境で実際に回したことは、まだ一度も無い。**
  **この ADR は「回せるようにする」であって「回した」ではない。**
