# ADR-0029: `language` は表示設定ではなく、**噛み合った3点セット**である

- 状態: **採用**（2026-08-25。§決定5 の保留は 16m の実測で畳んだ。**2つ目の束は約束しない**）
- 関連: [ADR-0007](0007-output-format-markup.md)（`「」` で台詞を切る）
  / [ADR-0015](0015-stat-scale-per-character.md)（**キャラクターごとの設定という形の先例**）
  / [ADR-0021](0021-memory-extraction-format.md)（抽出の書式。**測って決めた文面**）
  / [ADR-0024](0024-stat-drift.md) [ADR-0027](0027-drift-from-what-was-not-chosen.md)（変容の依頼。同上）

---

## 背景

利用者の指摘（2026-08-24）:

> **簡体字や `ー` の取り違えが発生している以上、マッチング測定の仕方もですが、**
> **同時に LM Studio に渡す要素に language 節がいるのではないか。**
> **CJK での漢字の取り違いが減ったり、逆に海外対応出来るならば検討価値はある。**

**⚠ 起こした当日に訂正が入っている。** きっかけになった崩れについて
**「この ADR では直らない」と書いたが、それを支える測定は1つも無かった**（§訂正）。
**測り直したら推論と逆を指したので、A/B を取ることにした。**
**`language` が要る理由は、それとは別にある。**

---

## 診断 —— **日本語は「文面」ではなく「閉じた輪」として焼き込まれている**

実測（2026-08-24 / 本番コードのみ・テストを除いて数えた）:

| 場所 | 何が日本語か | 本数 |
|---|---|---|
| `prompt::drift` | 依頼の文面・見出し・例・規則 | **23** |
| `prompt::extraction` | 同上 | **21** |
| `prompt::mod` | 節の見出し・注記 | **17** |
| `parse::mod` | **台詞の括弧** `「` `」` | 2 |
| `parse::extraction` | 区切り `：`、分類の括弧 `［］` `【】` | 数個 |
| `domain::memory` | **主語の語** `利用者` / `あなた` | 1 関数 |

**問題は本数ではない。3つが輪になっていることである:**

```
prompt が「利用者:」と書けと指示する
   → モデルが「利用者: 犬を二匹飼っている」と答える
      → parse が「利用者」を Subject::User に写す
```

**この3つは同時に同じ言語でなければ、1行も通らない。**
`prompt` だけ英語にすると、**抽出は全滅する**（`unknown subject` で全部捨てられる）。

> **したがって `language` は表示設定ではない。**
> **数の書式でも、日付の書式でもない。** **噛み合った3点セットの選択である。**

### **⚠ 保存されたデータは、すでに言語に依らない**

**これは幸運な事実で、設計を大きく楽にしている。**

- `memory.subject` は DB に **`'user'` / `'character'`**（ASCII）で入る（`store::memory::subject_to_db`）。
  **日本語の `利用者` は、プロンプトと突き合わせのときだけ存在する。**
- `stat_alloc.axis` / `character_attribute.key` / `value` / `base_persona` /
  `output_format_instruction` は**すべて運用者が書く自由文**で、最初から言語を問わない。

> **キャラクターの言語を変えても、保存済みの行は1つも壊れない。**
> **壊れるのは「読み書きの輪」だけである。**
>
> **⚠ ただし記憶の中身は前の言語のまま残る。**
> `ja` で貯めた記憶を持つキャラクターを `en` に変えると、
> **英語の本文プロンプトに日本語の記憶が載る。** 行は壊れないが、噛み合わない。

## 決定（提案）

### 1. **`language` は `character` の列にする**（[ADR-0015](0015-stat-scale-per-character.md) と同じ形）

**リクエストごとではない。キャラクターごと。**

- **輪が閉じていなければ何も通らない**ので、途中で切り替えられる場所に置いてはいけない。
- `stat_scale` が「キャラクターごとに1つ」なのと同じ理由
  ——**その値を前提に貯めたものがある。**
- **既定は `ja`。** マイグレーションの既定値で、**既存のキャラクターは何も変わらない。**

### 2. **型は「3点セット」を1つで持つ。ばらばらの設定にしない**

```
LanguagePack {
    prompt 定数一式        // 見出し・規則・例
    主語の語彙             // 利用者 / あなた（両方向）
    台詞の括弧             // 「」
    区切り・箇条書き・括弧  // ：［］【】
}
```

**`language` は、この束を1つ選ぶだけの値**にする。

> **⚠ 「運用者が個別に差し替えられる」形にしないこと。**
> 主語の語だけ英語にできる形を作ると、**輪が半分だけ壊れた状態**が作れる。
> **抽出が全滅するのに、起動もチャットも成功する。**
> **ADR-0024 §1 の許可リストと同じ立場** —— **表現できる形を減らす。**

> **⚠ 「型が守るから見張り番は要らない」とは書かない。**
> `0012b` で `enum { Readable, Unreadable }` を「無視できない形」と書いたが、
> **`filter_map` で捨てる実装はそのままコンパイルが通った。**
> **守るのは見張り番である**（§「見張り番」）。

### 3. **エラー文言（`#[error]` の 83 本）は範囲に入れない**

**すべて日本語だが、これは運用者向けであってモデル向けではない。**
**輪に入っていない**ので、言語を変えても何も壊れない。

**入れると、束の面積が倍になって、測る対象がぼやける。**
**必要になったら別の ADR で扱う**（そのときは HTTP の `Accept-Language` が正しい入口で、
`character.language` ではない —— **読者が違う**）。

### 4. **`ja` 以外を足すのは「翻訳」ではない。「測り直し」である**

**これがこの ADR でいちばん重要な一行である。**

**61 本のプロンプト定数は、文章ではなく測定の結果物である:**

- [ADR-0021](0021-memory-extraction-format.md) —— 抽出の書式は**主語の取り違え 6%** を測って決めた
- [ADR-0027](0027-drift-from-what-was-not-chosen.md) —— `NOTHING_RULE` は**2度失敗**し、
  依頼の形を `single` → `all` に変えて**上げ偏りが 94% → 69%** に下がった
- 同 16i —— **軸名を替えただけで上げ偏りが 68% → 49%**、`0` の率が **1〜7% → 78〜80%**

> **英語に訳した瞬間、これらの数は1つも引き継がれない。**
> **`en` の束を足すとは、`en` で同じ測定をやり直すということである。**

**したがって:**

- **束を足すこと自体は安い**（型と列だけ）。**足した束を信用してよくなるまでが高い。**
- **束ごとに「測ったか」の状態を持たせる。** 測っていない束は
  **記録専用モード（[ADR-0026](0026-drift-by-accumulation.md) §決定1）でしか使わせない。**

### 5. **`language` は書式であって、出力の言語の強制ではない**（**保留を畳んだ / 2026-08-25**）

> **⚠ 一度取り下げて保留にし、測ってから元の形で確定した。**
> **保留の理由**: 「指示は効かない」の根拠が `NOTHING_RULE` の失敗＝**判定**の指示の話で、
> **書き方**の指示とは別物だった。**別物を根拠にしていた。**
> **確定の理由**: **216 ターン × 3 腕で直接測った**（§「16m 第2弾」）。
> **複写の指示も言語の指示も、崩れを変えなかった**（14 / 12 / 20、すべて p ≥ 0.20）。

**束は「こちらがどう書き、どう読むか」だけを決める。**
**モデルに「日本語で答えよ」と命じる節は足さない。**

## ⚠ 訂正（2026-08-24 / 起こした当日）—— **「直らない」と書いたが、測っていなかった**

**この節はもともと「`language` 節ではこの崩れは直らない見込みが高い」と書いていた。**
**利用者の指摘で、それを支える測定が1つも無いことが分かった。**

> **`language` 節を入れた条件と入れない条件を、一度も比べていない。**
> **A/B が存在しない。** 書いたのは推論であって、実測ではなかった。

**そして指摘を受けて測り直したら、推論と逆を指した。**

### 実測（2026-08-24 / m20 ＋ m21 の 732 ターン）—— **崩れる場所は1箇所に集中している**

| どこ | `阳` の件数 |
|---|---|
| **本文の往復**（transcript） | **0**（m20 0 / m21 0） |
| **記憶の抽出** | **0**（m20 0 / m21 0） |
| **変容の採点**（`drift_raw`） | **18**（m20 6 / m21 12） |

**同じモデル・同じセッションが、本文と抽出では 732 ターン一度も崩さず、**
**変容の採点でだけ崩す。**

**3つのプロンプトの違いは、日本語の地の文の量である:**

| プロンプト | 日本語の文脈 |
|---|---|
| 本文 | ペルソナの散文・記憶・履歴。**多い** |
| 抽出 | 会話そのもの。**多い** |
| **変容** | **名前と `- 軸名: 5/10` の並びと規則。ほぼ帳票** |

> **崩れているのは、3つのうち日本語の文脈がいちばん薄いプロンプトである。**
> **しかも task は「上に書かれた軸名を写して返す」という、ほぼ複写の作業。**
> **これは `language` 節がいちばん効きそうな条件であって、効かなそうな条件ではない。**

**私の推論は向きが逆だった。**「モデルは言語を切り替えていない」から
「言語の指示は効かない」を導いたが、**言語の指示が要るのは、言語の手掛かりが薄い場所である。**

### 残っている事実（これは測ってある）

| 字 | 出現 | 崩れた回数 |
|---|---|---|
| **陽**（`陽気さ`） | 732 ターン | **`阳` に 18 回** |
| **強**（`強気`） | 366 ターン | **`强` に 0 回** |
| 誠・気・心・自・信・慎・共・感・皮・肉 | | **0 回** |

**「1文字しか崩れない」は事実。** **それが「言語の指示では直らない」を意味しないだけである。**

### ⚠ **軽視していた。実害の見積もりを訂正する**

**`unknown_axis` はそのターンの採点表を丸ごと捨てる。**
**1軸の綴りが崩れると、5軸ぶんのデータが消える**（m21 で 3.3% のターンが無寄与）。
**しかも必ず `陽気さ` が原因なので、系統誤差である。**

**そして、これは測定の都合の話に留まらない。**
**日本語のペルソナが日本語で喋っているキャラクターの内部処理から、中国語の字体が出ている。**
**本文で 0 件だったのは 732 ターンでの話であって、**
**別のモデル・別のペルソナ・長い文脈で出ない保証にはならない。**

### 決めたこと —— **測る**

**LM Studio が起動している間に A/B を取る**（作業単位 16m）。3つの腕を比べる:

| 腕 | 変容の依頼に足すもの |
|---|---|
| **X** | 何も足さない（いまのまま） |
| **Y** | **複写の指示** ——「軸名は上に書かれている字をそのまま写すこと」 |
| **Z** | **言語の指示** ——「日本語（常用漢字）で書くこと」 |

**Y と Z を分けるのは、「複写の指示」と「言語の指示」が別物だからである。**
**この ADR が問うているのは Z の側**だが、**Y の方が安く効く可能性がある。**
**測る前にどちらかを捨てない。**

> **⚠ 交絡を1つ記録しておく。** **台本は司令塔（私）が書いた日本語**である。
> **言い回しが日本語として自然でない箇所があれば、それ自体がモデルの字体の選択に効きうる。**
> **3腕とも同じ台本なので腕どうしの比較は成り立つ**が、
> **「日本語として自然な台本なら崩れない」という可能性は、この測定では否定できない。**

### 器具として置いたもの（作業単位 16m / 実装済み）

**`PERSONACORE_DRIFT_NOTE`。** 受けるのは**3つの綴りだけ**で、それ以外は**起動を止める**
（`ConfigError::DriftNote`。黙って腕 X へ落とすと、**測らずに §決定5 の保留を畳む**ことになる）。

| 綴り | 腕 | 依頼に足す文 |
|---|---|---|
| 未設定 / `none` / 空 | **X（既定）** | **なし** |
| `copy` | Y | **`prompt::drift` の `COPY_NOTE`**（軸名を上の記載どおり写すよう求める） |
| `language` | Z | **`prompt::drift` の `LANGUAGE_NOTE`**（日本語・常用漢字で書くよう求める） |

> **⚠ 文面をここに写さないこと。** コードには3箇所の直書きがあり、**互いを変異で守っている**
> （実装 / `prompt::drift` のテスト / `tests/server_stat_drift.rs`。定義ごと入れ替える変異で 8 本が赤くなる）。
> **ここに4つ目を置くと、その1つだけが誰とも突き合わされない。**
> **推敲したときコードの3箇所は赤くなって直り、この表だけが古いまま残る**
> **——「腕 Z を再現しよう」と読んだ人が別の文を送ることになる**（レビュー指摘 / 16m）。

**運用者の自由文は受けない**（§決定4 / 却下欄）。

**置き場所は `# 守ること` の最後の行**（＝指示メッセージの最終行）。理由は3つ:

1. **腕 X が1バイトも動かない。** 既存の4行の間に挿さないので、
   3本の腕の差が「**1行増えたかどうかだけ**」になる。
2. **直近性。** この基盤は「小型モデルは直近の指示に強く従う」を根拠に節の順序を決めている
   （ADR-0021 §14 / 13c-4）。**効かなかったときに「置き場所のせい」と言えると、保留を畳めない。**
3. **会話の面には置かない。** あちらに置いてよい定数は締めの2本だけで、本数の見張り番が立っている。

**費用**（5軸・尺度 7・短い1往復での実測 / `estimate_tokens` ＝ UTF-8 バイト数）:
**腕 X 1943 → 腕 Y 2046（+103）／腕 Z 1998（+55）。**

> **⚠ 割合は「増分」の話である。**
> **注記の増分は上限（`MAX_DRIFT_PROMPT_TOKENS` = 8192）の 1.26%（Y）と 0.67%（Z）。**
> **依頼そのものは上限の約 25%**（1943〜2046 / 8192）。
> **この表を「まだ 8000 近く空いている」と読むと 25 倍ずれる**（レビュー指摘 / 16m）。

**注記は削れない枠に載る**（変容の依頼は記憶も履歴も載せず、長すぎれば**丸ごと捨てる**）。

> **⚠ 腕 X の権威は写しではなくスナップショットである。**
> `the_request_without_a_note_is_byte_for_byte_the_measured_baseline` が
> **着手前のツリーで実際に組み上がった依頼を、行ごとに直書き**して持っている。
> **ここが赤くなったら「テストが古い」ではなく「腕 X が動いた」**——
> m20 / m21 と比べられなくなったという意味である。
>
> **⚠ この設定は測ったら消えるか、決定になる。**
> 3本の腕の差が読めたら、**片方に固定して `PERSONACORE_DRIFT_NOTE` ごと畳む**か、
> **§決定5 を「保留」から書き換えて残す**かのどちらかにする。
> **どっちつかずのまま設定だけ残さないこと**——
> 「測っていない文面が黙って選べる」状態が、§決定4 がいちばん避けたい形である。

## 見張り番（**実装するときに必ず置くもの**）

1. **輪が閉じること。束ごとに、両方向を1本で確かめる。**
   `prompt` が書いた主語の語を、そのまま `parse` に通して `Subject` に戻る
   ——**束を跨いで通すと落ちること**も同じテストで見る。
   > **⚠ `assert_ne!` では防げない。** 値は全部違っていて、**組み合わせだけが間違っている。**
   > **CLAUDE.md「抜けるのはいつも帰属」の5回目以降の形。**
2. **束が1つしか無いうちから、2つ目を植えて試すこと。**
   **`ja` だけで書いたテストは、束を選ぶ配線を一度も通らない**
   （既定値を期待値にしているのと同じ穴）。**偽の束をテスト内で作って通す。**
3. **束の数だけ `match` を使い、`_ =>` を書かないこと。**
   **束を足したときにコンパイルが落ちる**のが、いちばん安い見張り番である
   （`all_lists_every_reason_exactly_once` と同じ形）。
4. **予算の見張り番を束ごとに回すこと。**
   `every_field_at_its_limit_still_fits_the_default_budget` は**文面の長さに依存する。**
   **英語の束は日本語より長くなる**（同じ内容でトークンが増える向き）。
   **束を足したら、この見張り番を束ごとに通す。**

## 却下した選択肢

- **リクエストごとに言語を切り替える。** 輪が途中で割れる。貯めたものと噛み合わない。
- **プロンプトの文面を運用者が自由に差し替えられるようにする。**
  **測って決めた文面が、測っていない文面に黙って置き換わる。**
  `output_format_instruction` が自由文なのは**出力の形だけ**を扱うからで、
  **抽出と変容の依頼は別物**（ADR-0021 / 0027 の測定がぶら下がっている）。
- **エラー文言も束に入れる。** §決定3。読者が違う。
- **`ja` の文面を「言語中立」に書き直して1つで済ませる。**
  **英語で書いた依頼に日本語で答えさせる形**になり、
  **ADR-0021 / 0027 の測定が全部やり直しになる**のは同じ。**得が無い。**

**16m のレビューで見つかったもの。直していない。**

  **そのテストは注記を一度も通っていない**（フィクスチャが `DriftNote::None` 固定）。

  > **20.2 秒でタイムアウト**する。**「腕のデータが全部消える」形は赤になる。**

## 実測（2026-08-24 / **16m ＝ A/B の第1弾。72 ターン × 3 腕**）

**§訂正で「測る」と決めた A/B を実際に取った。** データは `scratchpad/m23`。
**台本・ペルソナ・尺度・初期値・バイナリ・軸はすべて同一。変えたのは注記だけ。**

### 1. **どちらの指示も、崩れを減らさなかった**

| 腕 | 注記 | ターン | 捨てられた | 率 |
|---|---|---|---|---|
| **X** | **なし** | 72 | **3** | **4.2%** |
| **Y** | **複写の指示** | 72 | **5** | **6.9%** |
| **Z** | **言語の指示** | 72 | **7** | **9.7%** |

**捨てられた原因は3腕とも `阳気さ` のみ。**（数はサーバの `drift_outcome=unknown_axis` と一致。）

> **⚠ 点推定は逆を向いているが、この数では何も言えない。**
> **X 対 Z の Fisher 両側 p = 0.326。X 対 Y は 0.719。**
> **「悪化した」とは書けない。書けるのは「減らなかった」だけである。**

### 2. **⚠ 崩れるのは、やはり `陽` だけだった**

**この腕は、崩れやすい字で軸を固めて機会を増やす設計にしていた:**

| 軸 | 簡体字 | 72×3 = 216 ターンでの崩れ |
|---|---|---|
| **陽気さ** | 陽 → 阳 | **15 件** |
| 読書欲 | 読 → 读 / 書 → 书 | **0** |
| 発想力 | 発 → 发 | **0** |
| 実直さ | 実 → 实 | **0** |
| 会話好き | 話 → 话 | **0** |

**機会を 1 文字から 6 文字へ増やしたのに、増えたのは `陽` の分だけだった。**

> **設計の狙いは外れた。そして外れ方が答えになっている。**
> **これは CJK 一般の問題でも、簡体字一般の問題でもない。** **`陽` に固有である。**
> **打ち手は軸名の側**（[ADR-0030](0030-choosing-the-axes.md) §決定3）。

### 3. **私（司令塔）の当初の主張について**

**結果は当初の推論と同じ向きに出た。それでも、あの書き方は誤りだった。**

- **測っていないことを、証拠表つきの節で「直らない」と書いた。**
- **根拠にした理屈**（「モデルは言語を切り替えていないから言語の指示は効かない」）**は、
  §訂正 の場所別の集計で否定されている**——崩れているのは**日本語の文脈がいちばん薄いプロンプト**で、
  **言語の指示がいちばん効きそうな条件**だった。
- **つまり結論が合っていたのは、理屈が正しかったからではない。**

> **測っていないことは書かない。** **合っていたかどうかは、後から見て分かることでしかない。**

### 4. **⚠ この節はまだ結論ではない。伸ばして測り直す**

**72 ターンでは検出力が足りない。** 同じ率のまま **216 ターン**まで伸ばせば、
**X 対 Z は p = 0.036** になる（見込み）。**腕ごとに 144 ターン足す。**

**そこまでやって初めて、§決定5（保留）を畳める。**

## 実測（2026-08-25 / **16m 第2弾 ＝ 216 ターン × 3 腕。これが結論**）

**各腕を 73→216 ターンまで伸ばした**（同じ DB の続きなので会話も続き）。

| 腕 | 注記 | `unknown_axis` | 率 |
|---|---|---|---|
| **X** | **なし** | **14** | 6.5% |
| **Y** | **複写の指示** | **12** | 5.6% |
| **Z** | **言語の指示** | **20** | 9.3% |

**Fisher 両側:** X 対 Y **p = 0.840** ／ X 対 Z **p = 0.372** ／ Y 対 Z **p = 0.198**
／ 注記あり(32/432) 対 なし(14/216) **p = 0.747**。

### 結論 —— **どちらの指示も、崩れを変えない**

**第1弾（72 ターン）で見えた 3 / 5 / 7 の並びは、雑音だった。**
**216 ターンでは `copy` が `none` を下回っている**（12 対 14）。
**「悪くなる」も「良くなる」も、どちらも支持されない。**

> **⚠ 検出できる大きさには限りがある。** この規模で見つけられるのは**倍以上の差**である。
> **2割の改善のような小さい効果は、この測定では否定できない。**
> **言えるのは「大きな効果は無い」までである。**

### §決定5 の保留を畳む —— **`language` は書式であって、出力の言語の強制ではない**

**保留にした理由は「根拠にした実測が別物だった」ことだった**（`NOTHING_RULE` の失敗は
**判定**の指示の話で、**書き方**の指示ではない）。**今回それを直接測った。**

**したがって §決定5 を元の形で確定する:**

> **束は「こちらがどう書き、どう読むか」だけを決める。**
> **モデルに「日本語で答えよ」と命じる節は足さない。**
> **足しても崩れは変わらないことを、216 ターン × 3 腕で確かめた。**

**そして器具（`PERSONACORE_DRIFT_NOTE`）の扱いも決まる:**

- **測り終えたので、この設定は役目を終えた。**
- **⚠ ただし「消す」判断はここではしない。**
  **`language` の束を実装する日には、同じ器具でもう一度測ることになる**
  （束が変われば依頼の文面も変わる）。**残すなら、注記の長さを押さえる見張り番を入れること**
  （§「器具の穴」）。**消すなら見張り番は要らない。**

### 崩れの側で分かったこと（**副産物だが、こちらのほうが実用的**）

| | |
|---|---|
| **崩れるのは `陽` だけ** | 648 ターン（3腕 × 216）を通して、`読` `書` `発` `実` `話` は**1件も崩れていない** |
| **率は台本の位置で変わる** | 腕 X の前半 72 ターンは 4.2%、後半 144 ターンは 8.3% |

**後者は交絡ではない**（3腕とも同じ台本の同じ位置を通る）**が、
「この軸名の崩れ率は N%」と言うときは、どの区間で測ったかが要る。**

**打ち手は [ADR-0030](0030-choosing-the-axes.md) §決定3 のまま** —— **軸名から `陽` を外す。**
