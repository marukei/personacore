# personacore（Windows 64 ビット版）

手元の PC で動かす言語モデルを相手に、キャラクターと会話するための道具です。
文章を作る部分は llama.cpp に任せます。personacore は llama.cpp を起こし、画面を出し、
会話と記憶を保存します。

この zip に入っているのは `personacore.exe` と、この `README.md` と、`THIRD-PARTY-NOTICES.txt` と、
名前が `LICENSE` で始まるライセンスの文書5つと、`NOTICE-AI-COLLABORATION.md` だけです。
`THIRD-PARTY-NOTICES.txt` には、`personacore.exe` が含んでいる第三者のソフトウェアの著作権表示とライセンスの全文が書いてあります。
personacore 自身のライセンスは `LICENSE` に書いてあります。3つのライセンスから1つを選んで使えます。
`NOTICE-AI-COLLABORATION.md` には、personacore を作るときに人間と AI がそれぞれ何を決め、何を書いたかが書いてあります。
その中のリンクは personacore のリポジトリの中の文書を指しています。`LICENSE` のほかは、この zip には入っていません。
好きな場所に展開してください。

やることは次の4つです。

## 1. llama.cpp を入れる

llama.cpp は公式の配布元から入れます。公式の案内（https://github.com/ggml-org/llama.cpp の README）は、
入れ方の筆頭に https://llama.app を挙げています。

**zip で入れる場合**は、https://github.com/ggml-org/llama.cpp の Releases から落とします。

- `Latest` の印が付いた版には、Windows 用の zip が付いていないことがあります。
  Windows 用の zip は、`b11175` のように **`b` で始まる版**に付いています。
- GPU を使わない PC では、名前に `win-cpu-x64` を含む zip（例: `llama-b11175-bin-win-cpu-x64.zip`）を選びます。
  ほかに GPU 用の zip もあります（名前に GPU の種類が入っています）。
- NVIDIA の GPU で CUDA 版を使う場合は、CUDA 版の zip に加えて、`cudart-` で始まる zip も要ります。
- winget を使う場合は、`winget search llama.cpp` でパッケージを探してください。

personacore は llama.cpp を次の形で起こします。

```text
llama serve -m <gguf のパス> --host <アドレス> --port <番号> <起動の引数>
```

入れたら、新しく開いた PowerShell で次を打ってください。

```powershell
where.exe llama
```

- **場所が表示されたら**、そのままで使えます。
- **何も表示されなかったら**（zip を展開しただけの場合など）、展開したフォルダにある llama.cpp の
  実行ファイル（`llama.exe`）の場所を控えておいてください。手順4で画面の「実行ファイル（command）」に書きます。
  （この `llama.exe` が `serve` を受け付けるかは、まだ確かめていません。）

> **入れた llama.cpp が `llama serve …` の形で起こせない場合**、personacore はそれを起こせません。
> そのときは llama.cpp を自分で立て、手順4で「gguf のパス（gguf）」を空にし、
> 「宛先（endpoint）」を自分で立てた llama.cpp のアドレスにしてください
> （ホストとポートまで。例 `http://127.0.0.1:8080`。末尾に `/v1` は付けません。personacore が足します）。
> gguf を書いていないプロファイルでは、personacore は何も起こさず、その宛先に依頼するだけです。

## 2. モデル（gguf）を落とす

Hugging Face から gguf 形式のモデルを1つ落とします。ここでは Hugging Face の `hf` コマンドを使います。
`hf` は Python のパッケージ `huggingface_hub` に入っています。

```powershell
pip install -U huggingface_hub
```

（uv を使っている場合は、入れずに `uvx --from huggingface_hub hf …` でも使えます。）

例として、Ministral 3 14B を `C:\models` に落とします。

```powershell
hf download mistralai/Ministral-3-14B-Instruct-2512-GGUF Ministral-3-14B-Instruct-2512-Q4_K_M.gguf --local-dir C:\models
```

落ちたファイルの場所（この例なら `C:\models\Ministral-3-14B-Instruct-2512-Q4_K_M.gguf`）を控えておいてください。
GPU のメモリが少ない PC では、もっと小さいモデルを選んでください。

## 3. personacore.exe を起こす

展開したフォルダで PowerShell を開き、次を打ちます。

```powershell
.\personacore.exe
```

しばらくすると、既定のブラウザで personacore の画面が開きます。
開かなかったときは、PowerShell に出ている `url=` の後ろの URL（`http://127.0.0.1:` で始まるもの）をブラウザで開いてください。
`url="http://127.0.0.1:…/"` のように引用符が付いていることも、付いていないこともあります。付いていれば引用符の中だけを使います。

初めて起動したとき、personacore は `%LOCALAPPDATA%\personacore\` に会話の保存先と、
上流の設定の見本（`upstreams.json`）を作ります。

**止めるときは、この PowerShell で Ctrl+C を押します。** personacore が起こした llama.cpp も一緒に止まります。
PowerShell の窓を閉じた場合も、personacore と llama.cpp の両方が同じように止まります。
それ以外の方法で終わらせた場合は llama.cpp が残ることがあるので、タスクマネージャーで止めてください。

## 4. 画面で gguf を選ぶ

1. 画面の上にある「上流モデル」を開きます。
2. 「upstreams.json に書いたプロファイル」に見本が並んでいます。例として `ministral-llama` の「直す」を押します。
3. 「本文生成」の「gguf のパス（gguf）」を、手順2で落としたファイルの場所に書き換えます。
   手順1で `where.exe llama` が何も表示しなかった場合は、「実行ファイル（command）」に llama.cpp の実行ファイルの場所を書きます。
4. 「保存する」を押します。
5. そのプロファイルの「このプロファイルに切り替える」を押します。
6. 上の表の「起こした上流の状態」が「載せています」から「準備完了」に変わったら使えます。
   大きなモデルは、載るまで数分かかります。

別のモデルを落とした場合も、「依頼するモデルの綴り（model）」はそのままで構いません
（llama.cpp はこの綴りを見ずに、載せたモデルで答えます）。
自分用の組を新しく作りたいときは「プロファイルを足す」を使います。

**2回目からは、personacore を起動するたびに、起こすボタンを1回押します。** personacore は前回選んだプロファイルを覚えていますが、
起動しただけでは llama.cpp を起こしません（ほかのソフトが GPU を使っているかもしれないためです）。
「上流モデル」と「会話」の画面に「まだ起こしていません（前回選んだプロファイルは、起動しただけでは起こしません）」と出て、
プロファイルの名前の付いた起こすボタンが出ます。
ほかの推論サーバが GPU を使っていないことを確かめてから押してください。モデルが載るまでは、会話の画面から送れません。
personacore の起動と同時に llama.cpp を起こしたいときは、`--upstream` でプロファイルを選んで起動します（下の [ほかの使い方](#ほかの使い方)）。

あとは「会話」の画面で話しかけます。キャラクターがまだ無ければ、「キャラクター」の画面の「新規作成」から作れます。

## 推論サーバが鍵（API キー）を求めるとき

鍵で守られた中継など、鍵を作った推論サーバに繋ぐときや、llama.cpp を鍵付きで起こすときは、その鍵をプロファイルに書きます。

1. 「上流モデル」の画面で、そのプロファイルの「直す」を押します。
2. その面の「鍵（api_key）」に鍵を貼り付けて、「保存する」を押します。

- 書いた鍵は、保存した後も画面に出ません。設定してあるかどうかと、末尾の4文字だけが出ます。
- 鍵を替えるときは、新しい鍵を書いて保存します。空のまま保存すれば、いまの鍵が残ります。消すときは「鍵を消す」を押してから保存します。
- 鍵を書いた面の宛先だけを変えて保存しようとすると、その鍵を新しい宛先へも送るかを聞きます。「送る」か「鍵を消す」を選んでください。
- 宛先が `http://` で、同じネットワークの別の機（家の中の別の PC など）なら、鍵が暗号化されずに送られることを画面が警告します。
- 宛先が `http://` で、それより外（インターネットの先など）のアドレスなら、保存の前に確認が出ます。
  鍵は暗号化されずに送られ、途中で記録されれば、その記録が残って悪用されることがあります。
  それでよければ「承認して保存する」を押します。「承認せずに保存する」を選ぶと、外へは鍵を送りません。
  `https://` で繋げるなら、そちらを使ってください。
- `http://relay.example:…` のように宛先を名前で書いたときは、保存を止めません。送るたびに名前からアドレスを調べて、
  同じネットワークの外だったら、承認が無ければ鍵を送りません。外へも送ってよければ、鍵の欄の隣の「承認する」を押し、
  同じ確認を読んでから承認して、保存します。
- 「裏方（抽出・変容）を別の上流にする」のチェックを外して保存すると、裏方に書いた鍵も消えます。
- 推論サーバが鍵を受け付けなかったときと、承認が無いので鍵を送らなかったときは、会話の画面と「上流モデル」の画面が、それぞれそう言います。

**`upstreams.json` には、鍵がそのまま（暗号化されずに）書かれます。**
このファイルを人に渡すときは、`"api_key": …` の行と `"allow_key_over_plain_http": true` の行を消してから渡してください。

## キャラクターに覚えていてほしいこと

personacore は会話から記憶を取り出して保存し、その後の会話に使います。

- 会話の返事を作るときに使う記憶は、**あなた（話しかける側）についての記憶だけ**です。
  キャラクター自身についての記憶（キャラクターが言ったことや決めたこと）も保存はしますが、返事を作るときには使いません。
  使うと、キャラクターが同じ言い回しを繰り返すようになったためです。
- そのため、**会話をまたいで覚えていてほしい約束や決まり**は、「約束・決まり」の画面に書いてください。
  「キャラクター」の画面で、そのキャラクターの行の「約束・決まり」を開いて書きます。
  書いた約束・決まりは、終わらせるまで毎回の会話に使われます。
- 1件は60字まで、有効なものは1キャラクターあたり16件までです。
  誰が何をするのかが分かる短い文で書き、守る側（あなた・キャラクター・両方）を選びます。
- 約束や決まりが終わったら、「果たした」「破った」「取り消した」のどれかで終わらせてください。終わらせたものは会話に使われなくなります。一覧と記録には残りますが、終わらせたものは戻せません。
- 約束・決まりが会話に入りきらないときは、古いものから使われなくなります。そのときは「約束・決まり」の画面でお知らせします。
- 会話の画面には、会話の中で生まれた約束や決まりの候補が「今こんな約束した？」と小さく出ることがあります。
  候補は会話の裏で作られるので、1〜2回やり取りした後に、少し遅れて出ます。
  合っていれば「採る」、中身や守る側を直したいときは「直して採る」、外れていたら「違う」を押してください。「違う」を押した候補は消えます。
  候補が約束か決まりかは判定していません。そのまま採ると「決まり」になるので、約束にしたいときは「直して採る」で約束を選んでください。
  同じ候補は「約束・決まり」の画面の「提案」にも出ます。採るまでは会話に使われません。
- 前の版で約束や決まりを「属性」に書いていた場合、自動では移りません。「約束・決まり」の画面に書き直して、属性からは外してください。

## うまくいかないとき

- **「起こした上流の状態」が `失敗しました: …` になった**
  - 後ろに `（ログ: upstream-logs の …）` とファイル名が付いているとき —— llama.cpp は起きましたが、その後うまくいきませんでした。
    `%LOCALAPPDATA%\personacore\upstream-logs\` の中のそのファイルを開いてください。llama.cpp が自分で言った理由が書いてあります。
  - `失敗しました: 上流を起こせませんでした（プロファイルの command と、personacore のログを確かめてください）`
    と出て、ログのファイル名が付いていないとき —— llama.cpp を起こすこと自体ができていません
    （`llama` が見つからない、実行ファイルの場所の書き間違いなど）。
    そのプロファイルの「直す」で「実行ファイル（command）」の欄を確かめ（空なら `llama` という名前で探します）、
    personacore を起こした PowerShell に出ている表示も確かめてください。
- **画面が開かない** —— 上の手順3のとおり、PowerShell に出ている URL を自分で開いてください。

## ほかの使い方

| やりたいこと | 打つもの |
|---|---|
| 版を確かめる | `.\personacore.exe --version` |
| ブラウザを開かずに起こす | `.\personacore.exe --no-browser` |
| 画面を出さずに、ほかのソフトから使う（ブラウザも開きません） | `.\personacore.exe --no-ui` |
| 起こすと同時にプロファイルを選ぶ | `.\personacore.exe --upstream ministral-llama` |
| まっさらからやり直す（今の保存先は消さずに、名前を変えて残します） | `.\personacore.exe --fresh` |

`--no-ui` で起こしても、動いている personacore は `GET /openapi.json` で API の仕様書（OpenAPI の形式）を返します。
ほかのソフトから使うときは、これを読ませてください。

## 保存される場所

すべて `%LOCALAPPDATA%\personacore\` の下です。

| もの | 名前 |
|---|---|
| 会話・キャラクター・記憶 | `personacore.sqlite` |
| 上流の設定（画面の「上流モデル」で直せます） | `upstreams.json` |
| personacore が起こした llama.cpp のログ | `upstream-logs\` |

personacore は `127.0.0.1` でだけ待ち受けます。ほかの PC からは繋がりません。
