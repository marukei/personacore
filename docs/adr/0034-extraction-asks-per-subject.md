## 背景 —— **2つの欠陥が、同じ1つの空欄から出ている**

**依頼は `- 主語: 事実` の1つの形で、主語（`利用者` / `あなた`）はモデルが選ぶ。**
**その結果、利用者について書く欄が常に1つ空いている。**

22b の実測（[ADR-0021](0021-memory-extraction-format.md) §16）:

| | 利用者の行 / ターン | 0行のターン |
|---|---|---|
| 利用者が**問いしかしていない** | **1.02** | 19% |
| 利用者が事実を述べた | 1.28 | 6% |
| （参考）あなたの行 | 3.34 | — |

**「あなた」は3行以上出るのに「利用者」だけがちょうど1に張り付く。**
**その利用者の行を 50 行読んだ結果:**

| | 件数 |
|---|---|
| **問い由来の捏造**（「〜に関心がある」） | **28（56%）** |
| **主語の取り違え**（キャラクターの事実が「利用者」の下に入る） | **~20（40%）** |

```text
利用者 | エスプレッソマシンの不調時にパニックになる
利用者 | 黒猫（コーヒー）が朝になるとまだ寝ている
```

**逆向きはほぼ無い**（あなたの行 847 のうち「利用者」を含むのは5行）。
**利用者が自分について何も言っていないターンで、モデルは
「関心を捏造する」か「キャラクターの事実を誤って入れる」かのどちらかをする。**

### プロンプト層は4回失敗している

| | 打ち手 | 失敗の形 |
|---|---|---|
| 13c-2 | `# 守ること` に指示を4つ | **読まれない** |
| — | `NO_GUESSING` | **読まれない** |
| 21b | 締めを類型で言う（§15） | **禁止の範囲に入っていないと解釈される** |
| 22b | 手本の主語を変える | **そもそも原因ではなかった** |

**4回とも失敗の形が違う。「言い方が悪い」で説明できるものは残っていない。**

## 決定

### 1. **依頼を2本に分ける。主語は「どちらの依頼か」で決まる**

**「利用者について」と「あなたについて」を、別々の依頼として尋ねる。**
**主語はモデルの出力から来ない。**

**[ADR-0006](0006-slot-based-tag-compilation.md) の `ValidTag` と同じ形** ——
**防ぐのではなく、取り違えを表現できなくする。**

**そして利用者について尋ねた回が 0 件を返すのは自然になる。空欄を埋める圧力が消える。**

### 2. **出力の行から主語を消す**

**`- 事実` / `- [分類] 事実`。**

**残して依頼側で上書きする道は採らない。** 上書きするなら、**モデルは書き続けられる** ——
**取り違えが「表現できる」まま残り、この変更の理由が消える。**

> **⚠ 測定器が1つ消える。** `DiscardReason::MissingSubject` は**原理的に発生しなくなる**。
> **良くなったかは「利用者の行を読む」でしか言えない。**
> **基準値は 22b が持っている（50 行中 40%）。** 変更後に同じ読み方で 50 行読む。

### 3. **1ターンの上限は依頼ごとに 5 件**

`NewMemory::MAX_PER_TURN` は**依頼ごと**に効く。合計は最大 10。

> **⚠ 書き込み量が実質増える。** いまは「あなた」の 3.34 行が
> 利用者の行と**同じ 5 件の枠を分け合っている。**
> **分けると「あなた」だけで 5 件書ける。**
> **合計 5 にする道もあるが、2本目の依頼は1本目が何件返したかを知らない**ので、
> **知らせる配線が要る。増えることを受け入れて、単純な側を採る。**

### 4. **「すでに知っていること」は、その主語のぶんだけ載せる**

重複抑止（§13）は主語ごとに閉じている。**もう一方の主語の記憶は雑音**でしかない。
**枠も空く。**

### 5. **入れる前に測る。予言を先に書く**

**器具は 21b / 22b のものを使う**（腕を `Combined` / `Split` の2本にする）。
**16l 以降の作法どおり、回す前に予言を書き残す** ——
**21b と 22b は予言が両方とも外れている。**

#### 予言（**2026-08-27 / 回す前に司令塔が書いた。実装より前**）

**基準は 22b の `Balanced` 腕**（本番の形）。**問いだけのターン**について:

| | 22b（基準） | 予言（`Split`） |
|---|---|---|
| **利用者の依頼が 0 件を返す率** | **19%** | **55〜75%** |
| 利用者の行 / ターン | **1.03** | **0.35〜0.60** |
| あなたの行 / ターン（参考・全ターン） | **3.34** | **3.2〜4.2**（変わらないか、やや増える） |
| **利用者の行 50 行のうち、取り違え** | **40%** | **10〜25%** |

**筋道**: §16 の仮説は「**利用者の行を1本作らなければならない**」という圧力である。
**分ければ「利用者について」の依頼には 0 件という自然な答えができる**ので、圧力が落ちる。
**捏造（56%）と取り違え（40%）は同じ空欄から出ているので、両方が一緒に下がるはず。**

**⚠ 取り違えが 0 にならないと予言する理由。**
**構造が消すのは「主語を選び間違えること」であって「事実を取り違えること」ではない。**
**キャラクターの事実を「利用者について」の依頼で書いてしまえば、
それは主語の誤りとしては表現できず、内容の誤りとしてそのまま残る。**
**むしろ `MissingSubject` という数える手段が消えるぶん、見えにくくなる。**

**⚠ あなたの行が増える向きに賭けている理由**（§決定3 の代償）——
**いままで利用者の行と 5 件の枠を分け合っていたのが、単独で 5 件書けるようになる。**

**外れ方の予告:**

- **0 件率が動かなければ**、圧力の仮説そのものが誤り
  （＝ **21b・22b・A-1 で4回目の失敗**。プロンプトでも構造でもないことになる）。
- **0 件率は上がったのに取り違えの率が下がらなければ**、
  **「書く回が減っただけで、書く回の質は同じ」** ——**A-1 は量にしか効いていない。**
  **13c-3 で一度出た形**（「効いたのは量で、質ではない」）の再来。
- **あなたの行が 4.2 を超えたら**、§決定3 の代償が予想より重い。

#### レビュアーの予言（**同じく回す前。§決定5 の司令塔の表を読む前に数を確定**）

| | 22b（基準） | **レビュアー** | 司令塔 |
|---|---|---|---|
| **0 件率** | 19% | **38%** | 55〜75% |
| 利用者の行 / ターン | 1.03 | **0.95** | 0.35〜0.60 |
| あなたの行 / ターン | 3.34 | **4.4** | 3.2〜4.2 |
| **取り違え（50 行）** | 40% | **18%** | 10〜25% |

**筋道の違いが1点に集約されている** —— **「直接尋ねられたモデルが『なし』と答える」ほど、
レビュアーは司令塔より弱く見積もった。**

> **16i の実測**（軸名を入れ替えたら `0` の率が 1〜7% → 78〜80%）は
> 「**モデルは『なし』を言える**」を示すが、**あれは採点で、こちらは列挙である。**
> **列挙の依頼に空で答えるのは別の振る舞い**だ、という読み。

**そして「あなたの行」は、司令塔の上限 4.2 を超える側に賭けている**
（＝ 司令塔自身が書いた「外れ方の予告」の3つ目に当たる向き）。

**⚠ 2人の予言が食い違っているのは良いこと。** どちらが外れても、外れ方が何を意味するかは書いてある。

#### ⚠ 数え方（**回す前に決めておく**）

**`Split` の枠 ≤ `Combined` の枠**である（`a_split_ask_never_takes_more_room_than_the_combined_ask`）。
したがって **`Combined` が §8 の門で捨てたターンを、`Split` は処理しうる**（逆は起きない）。

**そのまま数えると分母が揃わない。**
**「両腕とも `SKIP` が出なかったターン」の共通集合に絞って数える**こと。
**22b の 1.03 / 19% と比べられるのは、その集合の上でだけ。**

> **器具は `ask=` 付きで `SKIP` を出すので、観測はできる。集計側の作法の問題である。**

#### ⚠ `NO_GUESSING` は `Split` では前提を失っている（**回す前に記録**）

> **どちらの事実か決められないものは書かないでください。**
> 会話に書かれていないことを推測して補わないでください。

**前半は「2つのうちどちら」という選択の存在を前提にした文**で、**§決定1 はその選択を消した。**

**両腕に同一文が載るので A/B は交絡しない。**
**が、同じ文が腕ごとに違う意味を持つ**ので「まったく同じ処置」とは言い切れない。
**`Split` が伸びなかったとき、この行が候補原因として残る。**

**後半（推測して補うな）は 0 件率に直結するので、動かさない。**

## 理由

### 却下した選択肢

- **1本のまま、応答を `## 利用者について` / `## あなたについて` の2節に強制する** ——
  **主語は位置から来るので取り違えは減りうるが、空欄を埋める圧力は残る。**
  **両方の節が同じ1回の応答にあるので、片方を空にするのは「答えていない」ように見える。**
  **22b が潰したのは、まさにこの圧力の側だった。**
- **利用者が事実を述べたターンだけ、利用者の依頼を投げる** ——
  **その判定こそがモデルにできないこと。** こちらが代わりにやれば、同じ誤りを別の場所で犯す。
- **主語を残したまま、`# 守ること` にもう1文足す** —— **4回失敗している経路。**

## 結果

### 得られるもの

- **主語の取り違えが表現できなくなる**（40% の行き先が構造的に消える）。
- **0 件が自然な答えになる** —— 捏造の圧力が消える。
- **依頼が小さくなる**（会話は同じだが、記憶の節が主語ぶんに減る）。

### 諦めたもの / 前提

- **⚠ サブLLM の呼び出しが毎ターン2倍。**
  `Max Concurrent Predictions = 1`（[ADR-0032](0032-upstream-frame-is-a-precondition.md)）なので
  **落ちはしないが、行列が伸びる。**
  **⚠ この危険は [ADR-0035](0035-the-watchdog-reports-the-human-decides.md) が引き取る** ——
  **中継が固定の秒数で打ち切らなくなるので、行列は「遅い」であって「壊れる」ではなくなる。**
  **0035 を先に入れること。**
- **⚠ `MissingSubject` が消える**（決定2）。**取り違えを数える手段が無くなる。**
- **⚠ 書き込み量が増えうる**（決定3）。
- **⚠ 会話は2本の依頼に重複して載る。** トークンの総量は約2倍。
  **枠は依頼ごとに独立に効くので、1本あたりの上限は変えない。**

## 測定（2026-08-27 / `scratchpad/m28`）

**台本・既知の記憶・モデル・温度・繰り返しは 21b / 22b と同一**
（32 ターン / 146 件 / `ministral-3-14b-instruct-2512` / 繰り返し 8 / 同一プロセスで交互 / 直列）。
**変えたのは依頼の形1つだけ。** `SKIP` は 0 件（共通集合は全ターン）。

### 対照腕が基準を再現している（**測定器は健全**）

| 問いだけ | 21b | 22b | **今回の `Combined`** |
|---|---|---|---|
| 利用者の行 / 回 | 1.05 | 1.03 | **1.04** |
| 利用者が0行 | 18% | 19% | **18%** |

### 結果

**（`0件` などの空宣言を除いた値。除かないと `Split` の 0 件率は 0% と出る）**

| 問いだけ | `Combined` | `Split` |
|---|---|---|
| **利用者の行 / 回** | **1.04** | **2.75** |
| **利用者が0行** | **18%** | **13%** |
| あなたの行 / 回 | 3.13 | 3.41 |
| （述べたターンの利用者の行 / 回） | 1.21 | 2.75 |

**符号検定（問いだけ 22 ターン / 対）: `Split` が多い 22・少ない 0・同点 0。両側 p ≈ 4.8e-7。**

### 予言は2つとも、**同じ向きに**外れた

| | 司令塔 | レビュアー | **実測** |
|---|---|---|---|
| 0 件率 | 55〜75% | 38% | **13%（基準 18% より低い）** |
| 利用者の行 / 回 | 0.35〜0.60 | 0.95 | **2.75** |
| あなたの行 / 回 | 3.2〜4.2 | 4.4 | **3.49** |

**2人とも「分ければ利用者の行が減る」と読んだ。ほぼ3倍に増えた。**

### 中身 —— **同じ回・同じ読み手で 50 行ずつ読んだ**

**⚠ 最初の報告では `Split` の 63% を 22b の 40% と比べたが、物差しが揃っていない**
（40% は別の回の別の読み）。**同じ回の `Combined` を同じ読み方で読み直した。**

| 50 行 | `Combined` | `Split`（空宣言7を除く43） |
|---|---|---|
| **実際に利用者について言えること** | **2（4%）** | **4（9%）** |
| **キャラクター側の事実の取り違え** | **24（48%）** | **27（63%）** |
| 問い由来の捏造 | **24（48%）** | 12（28%） |

**1行あたりの質は、むしろ少し良くなっている。捏造が減り、取り違えが増えた。**
**1ターンあたりに直すと逆転する:**

| 問いだけ 1ターンあたり | `Combined` | `Split` | |
|---|---|---|---|
| 本物 | 0.04 | **0.25** | 6倍 |
| **取り違え** | 0.50 | **1.73** | **3.5倍** |
| 捏造 | 0.50 | 0.77 | 1.5倍 |

**信号は増えた。雑音はもっと増えた。`memory` の行は消せないので、効くのは絶対量である。**

### ⚠ `Split` だけが作る新しい壊れ方 —— **空を宣言した文が「事実」になる**

**`0件` / `--` / `0/5件` が `Split` の応答に出る。`Combined` には1件も無い。**
**利用者の行 711 のうち 32 行（5%）が `0件` そのもの。** あなたの行にも 11 件。

**パーサは崩れていない。** モデルが「該当なし」を**箇条書きの1項目として**書き、本文として通る。

> **⚠ これがこの測定でいちばん使える手がかり。**
> **列挙の依頼に「なし」と答えることが、モデルにはできない。**
> **一方 `16i` は、採点なら言えることを実測している**（軸名を入れ替えただけで `0` の率が 1〜7% → 78〜80%）。
> **レビュアーの予言の筋道がここを突いていた** ——「あれは採点で、こちらは列挙。別の振る舞いだ」。
> **予言は外れたが、外れ方が示唆を残した。**

### 測っていないこと

- **候補外の見落とし**（21b の作法）。**結論の向きが変わりようがないので省いた。**
- **増えた行が既知の記憶の重複かどうか**（`SplitU` は `known_dropped=0`＝全件載っていた）。
- **分類は司令塔1人の読み。** 再現できるよう `m28/sample50.txt` と `sample50_comb.txt` を残してある。
