# ADR-0064: 抽出で増えた記憶は、10 往復ごとの区切りのターンでまとめて本文に載せる

## 背景

### 先頭の system が変わったターンは、会話キャッシュが 0 になる

接頭辞で会話キャッシュを再利用する上流では、先頭の system が前のターンと1文字でも違うと、その後ろの履歴まで全部を読み直す（ADR-0061 の背景）。ADR-0063 で履歴の窓は 10 往復ごとにしか動かなくなったので、残る読み直しの原因は「先頭の system が変わったターン」になった。

### 記憶の節が変わるのは、抽出で記憶が増えたときだけだった

2026-11-14 の測定（ローカルの推論サーバ、ADR-0063 を出した後の exe、念押しなし、罰 1.1）で、先頭の system を見出しごとの節に割り、1つ前のターンと比べた。

| 会話 | 比べたターン | system が変わった | 変わった節 |
|---|---|---|---|
| 長い会話の続き 12 ターン | 11 | 2 | 性格ステータス ×2（変容で軸の値が1つ変わった） |
| 新しいセッション 10 ターン | 8 | 1 | 記憶 ×1（利用者の記憶が 10 件から 12 件に増えた） |

- このキャラクターの利用者の記憶は 7〜12 件で、記憶の枠に全件が入っていた（想起の関連の層は 0 件、省いた記憶も 0 件）。だから記憶の節は「有効な利用者の記憶の全件を作成順に並べたもの」になり、今回の発言（検索語）には依らない。
- marukei/personacore#29 が前提にしていた「今回の発言で選ぶ記憶が毎ターン変わる」は、いまのデータでは起きていない。節が変わるのは、裏方の抽出で記憶が増えたときと、訂正で記憶が外れたときだけである。
- 変容（性格ステータスの値）は、利用者の決定ですぐ反映のままにする（下の「決めなかったこと」）。

### 記憶を書く口は2本しかない

- **抽出**（`Store::add_memory_in_session`）: 往復の保存がコミットされた後に、裏方が書く（`TurnSink::persist`）。
- **訂正**（`POST /admin/characters/{handle}/memories/{memory_id}/corrections` → `Store::supersede_memory`）: 新しい行を足し、古い行の `superseded_by` に新しい行の id を入れる（ADR-0022）。

管理画面から記憶を新しく足す口は、本番には無い（`Store::add_memory` はテスト専用）。`memory.created_at` と `message.created_at` は同じ綴り（`strftime('%Y-%m-%dT%H:%M:%fZ','now')`、UTC・ミリ秒）で、文字列のまま比べると時刻順になる。

## 決定

### 1. 本文の想起の候補を「最後の区切りの往復の終わり以前に作られた記憶」に絞る

- **区切りのターン**: そのセッションの往復の数 N（今回の発言を含めない。ADR-0063 §決定2 の数え方）が 5, 15, 25, 35, …（N ≡ 5 (mod 10)）になったターン（たとえば N = 5 なら、6 回目の発言を送るターン）。件数で窓が決まる構成では、窓が動くターン（N = 35, 45, …）と重なる。どちらも、そのターンに全部を読み直すことになるので、読み直しの回数が増えない。
- **境の時刻**: N 以下で最大の区切り r について、そのセッションの r 番目の往復の最後のメッセージの `created_at`。r が無い（N < 5）ときは、セッションの `created_at`。区切りの往復の行が見つからないのは、数えている間にセッションが消えたときだけで、そのときは `UnknownSession` を返す。
- **候補**: 有効な利用者の記憶（今までどおり）のうち、`created_at` が境の時刻以前（`<=`）のもの。r 番目の往復の抽出で書かれた記憶は境の時刻より後なので、次の区切りまで載らない。
- 絞りは採点（df）の前に掛ける。df も区切りの間は動かない。絞りは store の照会（`recall_memories` の `RecallScope::AsOf`）で掛けるので、prompt 層は絞った後の集合しか受け取れない（採点の順番は構造で守る）。
- **状態を持たない。** 境の時刻は DB から毎回求める。exe を再起動しても同じ節になる。

### 2. 訂正で入った記憶は、絞りを素通りさせる

- 訂正は利用者が管理画面で行う操作なので、すぐ反映する。訂正すると古い行は想起から外れる（`superseded_by IS NULL` の条件）。新しい行を絞りで落とすと、区切りまで古い行も新しい行も載らない。
- 訂正で入った行は「ほかの行の `superseded_by` に指されている」ことで見分ける。訂正を重ねても、最新の行は1つ前の行から指される。**列は足さない**（マイグレーションなし）。
- 訂正したターンは先頭の system が変わる（会話キャッシュは 0）。利用者が自分で起こした変化なので受け入れる。

### 3. 裏方の要求は絞らない

記憶を読む裏方の要求（抽出と軸の候補）は、今までどおり有効な記憶の全件を読む（変容は記憶を読まない）。絞るのは本文の想起だけ。想起の入口は1つのまま（ADR-0003）で、呼び手は `RecallScope::Everything` か `RecallScope::AsOf` を必ず名指しする（既定値は持たない）。`AsOf` を渡すのは本文の経路だけで、境（`RecallBoundary`）は `Store::recall_boundary` からしか作れない。

境で外した記憶の件数は数えない（数えるには照会がもう1本要る）。区切りを待っている記憶を測るときは、DB を直接見る。

### 4. 見張り番

- 本文の経路（`chat.rs`）を通るテストで、区切りの間に足された記憶が区切りのターンまで本文に載らず、区切りのターンで載ることを確かめる。本番の書き手（抽出）が書いた記憶が、本文の依頼には載らず抽出の依頼には載ることも確かめる。
- 同じく、訂正した記憶が次のターンですぐ入れ替わることを確かめる。
- 境の時刻を渡さない変異で、前者が赤くなること。

## 反映の遅れ

- 抽出で増えた記憶は、本文に載るのが最大で 10 ターン（と抽出にかかる時間）遅れる。
- 同じセッションで、件数で窓が決まる構成なら、遅れても記憶のもとになった往復は履歴の窓（25 往復以上。ADR-0063）の中にまだ残っている。モデルが知っている中身は、遅れの間も変わらない。
- それ以外では、遅れの間はもとの往復が窓に無いことがある。予算で窓が決まる構成では窓が 25 往復より短くなりうる（ADR-0063 §決定3）。また、境はセッションごとだが記憶はキャラクターごとなので、別のセッションで抽出された記憶もこのセッションの区切りまで待つ（新しいセッションでは、セッションを始めた後に書かれた記憶が N = 5 まで待つ）。

## 決めなかったこと

- **変容（性格ステータスの値）は、すぐ反映のまま。** 長い会話では 12 ターンで2回、先頭の system を変えていた（ADR-0061 は「まれなので受け入れる」と書いたが、それより多い）。利用者の選択で、今回は記憶だけまとめた。
- **記憶が枠からあふれる規模になったとき。** そのときは今回の発言で選ぶ記憶が毎ターン変わり、先頭の system も毎ターン変わる。marukei/personacore#29 の元の問いで、今回は扱っていない。

## 守れないもの

- 予算で窓が決まる構成では、窓が動くターンと区切りのターンが重ならない。区切りの間に記憶が増えていれば、区切りのターンで読み直しが1回増える。
- 抽出が境の時刻をまたいで書いた記憶（境の時刻より前に INSERT したがコミットが遅れたもの）は、ターンによって見え方が変わりうる。抽出の INSERT は1文で、INSERT からコミットまでの間はごく短い。
- 将来、裏方が `superseded_by` を書くようになると、その書き込みで入った行も素通りになる。そのときは、この ADR を見直す。
