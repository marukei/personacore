# ADR-0017: 識別子は制限された文字集合にする。生成識別子は FE ができてから

- 状態: **採用**
- 日付: 2026-08-15
- 関連: [ADR-0004](0004-session-identification.md)（正規化キーとゴースト行） /
  [ADR-0011](0011-character-handle-and-display-name.md)（識別子と呼び名の分離） /
  [ADR-0016](0016-character-update-and-delete.md)（識別子は不変）

## 背景

**識別子が担っていた「意味」は、もう残っていない。**

- [ADR-0011](0011-character-handle-and-display-name.md) が**呼び名を別の列に分けた。**
  プロンプトに載るのは表示名で、識別子は載らない。
- [ADR-0016](0016-character-update-and-delete.md) が**識別子を不変にした。**
  「付け間違えたら直す」も無くなった。

**識別子に残った仕事は、安定した鍵であることだけである。**

にもかかわらず、いまの `CharacterName` は**ほとんど自由文**を受け付ける
（弾くのは `@` と制御文字と行区切りと「不可視だけ」と 50 文字超のみ）。
日本語も、途中の空白も、`aoi\u{200B}` も通る。

**その自由が機構を要求している。**

- [ADR-0004](0004-session-identification.md) の**正規化キー索引**（`character_name_key_idx`）と
  `SELECT_BY_NORMALIZED_KEY`、`StoreError::ConflictingUnnormalizedName`。
  すべて「`aoi` と `" aoi "` を同一視する」ために存在する。
- `TRIMMABLE` の写しのうち、識別子に関わる分。
  > **写しの数をここに書かない。** 執筆時に「5箇所」と書いたが、
  > **当時すでに台帳は8箇所、実際は11箇所**だった（0004b-2 で判明）。
  > **数は `src/domain/text.rs` の台帳が正**で、そちらは
  > 「いま効いている写し」と「役目を終えた写し」に分けてある。
- **`aoi` と `aoi\u{200B}` が別のキャラクターとして併存できる**（0009 の残余）。

## 決定

**識別子の文字集合を、打てる範囲まで絞る。**

- 使えるのは **ASCII の小文字英字・数字・`-`・`_`** だけとする。
- **正規化をしない。** 前後の空白は**そもそも表現できない**ので、trim も大文字小文字の畳み込みも要らない。
- **比較は `=` で足りる。** 正規化キー索引と `SELECT_BY_NORMALIZED_KEY` は**役目を終える。**

**生成識別子（UUIDv7 等）は採らない——いまは。**

## 理由

### なぜ生成識別子を「いま」採らないか

**手打ちができなくなる。** FE がまだ無いので、測定も検証も
`model: "aoi@new"` を直接叩いている。生成識別子にすると全部が lookup 経由になる。

**そして「手打ち用のエイリアス」を足すと、振り出しに戻る。**
エイリアスも `model` で引く以上は一意でなければならず、**人が打つ自由文**になる。
**いま消したはずの正規化機構が、そっくりエイリアスの側で必要になる。**

**生成識別子が本当に効くのは「FE の一覧から選ぶので手打ちが要らない」が成立してからである。**
それより前に決め打つと、FE の形（一覧から選ぶのか、URL でキャラを指すのか）が
決まらないうちに不可逆な選択をすることになる。

### なぜ文字集合を絞るだけで足りるか

**ゴースト行は「前後に空白を付けた別の行」から生まれる。**
空白を表現できなくすれば、**その行が作れない。**
[ADR-0004](0004-session-identification.md) が「最も危険」とした
「照合では一致するのに完全一致では引けない行」は、**原理的に存在しなくなる。**

同じ理由で、0009 の残余（`aoi` と `aoi\u{200B}` の併存）も消える。
**不可視文字を弾くのではなく、可視の ASCII だけを許す**——
「防ぐ」ではなく「**表現できなくする**」側に寄せる。

### 却下: 大文字を小文字へ畳み込む

**畳み込みは正規化であり、正規化がある限り「畳み込む前の行」が存在しうる。**
`Aoi` を受理して `aoi` に直すと、**直す前に入った行**の問題が残る。
**大文字を拒否すれば、その経路が無くなる。** 打ち手には少し不便だが、
識別子は**作るときに一度書くだけ**の値である。

## 結果

- **正規化キーの機構を捨てられる。** 索引・専用 SELECT・専用エラー・`TRIMMABLE` の写しが減る。
  **ADR-0004 の「ゴースト行」の節は、ここで役目を終える。**
- **日本語の識別子が使えなくなる。** 呼び名は表示名が持つので実害は無い
  （現に運用中の識別子は `aoi` / `s10` / `s100` / `nar` / `nost` ですべて ASCII）。
- **既存の DB に、新しい規則を満たさない行があると移行できない。**
  識別子は不変（ADR-0016）なので**API では直せない。**
  マイグレーションは**黙って変換せず、落ちること**（識別子を勝手に変えるのは、
  FE 側の `model` 設定が指さなくなるのと同じ壊れ方になる）。
- **生成識別子への道は閉じない。** 文字集合を絞った識別子は、
  生成識別子の**部分集合として表現できる**（`01hq3k...` は今回の規則を満たす）。
  FE ができた時点で、**運用者が打つのをやめるだけ**で移行できる。

## 追記: 画面が使える文字を言う（2026-09-25 / Issue origin#30・D-14）

**「日本語の識別子が使えなくなる。実害は無い」は、打つ前に規則が見えるときに限って成り立つ。**
キャラクターの新規作成の画面は規則を言っておらず、日本語を打つと「使えない文字が含まれています」とだけ断られて、
何を直せばよいかが分からなかった（利用者の指摘）。エラーの文面に文字を列挙しないのは写しを増やさないための作りで、
それ自体は変えない。

- **画面の識別子の説明に、使える文字を一度だけ書く**（英小文字・数字・`-`・`_`。日本語の名前は表示名へ）。
  これは文字集合の**3箇所目の写し**になる（1: `Handle::ALLOWED_CHARACTERS`、2: `migrations/0005` の CHECK）。
- **写しを認める条件は見張り番**: 画面のテスト（`web/tests/character-form-examples.test.ts`）が、
  描かれた説明から文字の集合を読み取り、`src/domain/character.rs` の `ALLOWED_CHARACTERS` と突き合わせる。
  どちらかだけを変えると赤になる。**読み取れない書き方に変えた場合も赤の側に倒れる**が、
  読み取れない綴りで文字を**足す**変更は素通りする（走査の限界。レビューの R04）。
- **4箇所目は作らない。**
