## 背景

### 目安を最初から入れても縮んだ

ADR-0065 の目安を入れた exe で、利用者が遊んだ（2026-11-16 未明、目安 300〜600 字を最初から）。返答は往復1〜5 が 348〜475 字で、往復6 で 258 字、往復10 で 100 字まで縮み、以後 59 往復まで戻らなかった。途中で目安を 500〜800 字に上げても戻らなかった。

ADR-0065 は「目安は新しいセッションで縮みを防ぐ」と書いたが、その測定では目安なしの対照も縮んでいなかった。示せていたのは「数字の方向に長さが付いてくる」ことだけである（ADR-0065 の追記 2026-11-19）。

### 測ったこと（2026-11-18〜19。手続きと数は marukei/personacore#72 のコメント）

利用者の会話（以下、会話 A）の写しを、往復12 の後（返答が 96 字まで縮んだ後）で切った土台から、利用者の実際の発言 11 本を流した。各腕2回。

| 腕 | 末尾6本の平均（字） | 末尾6本の 100 字未満 |
|---|---|---|
| 目安だけ | 82 / 90 | 3 / 4 |
| 終わりのトークンに毎回 -1.5 | 222 / 229 | 1 / 2 |
| **終わりのトークンに毎回 -3** | **538 / 534** | **0 / 0** |
| 終わりのトークンに毎回 -5 | 768 / 626 | 0 / 0 |
| 直前の返答が 300 字未満のときだけ -3 | 216 / 198 | 1 / 2 |

- 目安だけの腕は、会話 A の同じ往復（往復 18〜23、平均 89 字）をそのまま再現した。縮んだ状態は、会話の状態（履歴と記憶）が持ち越している（縮み始める入口は分かっていない。末尾の「残したこと」）。
- **-3 は2回とも、目安の下限（300）を超えて戻した。** 打ち切り（`finish=length`）は0本で、末尾の返答はすべて文として終わっていた。
- -5 はさらに長くなったが、1本がキャラクターの外の、案内役の口調の一文で終わった。採らない。
- **「直前が短いときだけ」は振動した。** 掛けた回は 12 回中 10 回が 300 字以上に戻り、掛けなかった次の回は毎回 300 字未満に落ちた（2回で計 10 回）。下げる効き目はその回の要求だけのもので、戻った返答が履歴に入っても次の回の縮みは止まらない。
- 新しいセッションで毎回 -3 を掛けると、23 往復の平均は 573 / 667 字（目安だけでは 406 / 485 字）で、目安の上端（600）を超える往復が多かった。打ち切りは0本、最大 1073 字。
- 終わりのトークンの番号（248046）は、測ったモデル（Qwen3.8-Flash-Next）のもの。その推論サーバは `/props` に終わりのトークンを載せず（`eos_token` が無い）、`/tokenize` と `/detokenize` は 404 を返した（2026-11-19 に確かめた。記録は測定の置き場所の結果の文書）。上流から引けない。
- 表の字数は、利用者に届いた最終の返答の文字数。「直前が短いとき」の判定では、中継が本文の要求の履歴の最後の返答を数えた（personacore が履歴に載せる形。保存した `raw_content` と、上流が本文に漏らした思考の分だけ違いうる）。

## 決定

### 1. 面の `sampling` に `end_token_bias` を足す

```json
"main": {
  "endpoint": "…",
  "model": "…",
  "sampling": { "repeat_penalty": 1.1, "end_token_bias": { "token": 248046, "bias": -3.0 } }
}
```

- `token` は終わりのトークンの番号、`bias` は足す値。**どちらも書いた人が決め、personacore は既定を持たない**（番号はモデルごとに違い、上流から引けない。ADR-0033 の「名乗る」にあたるのは、書いた人がその番号をどのモデルで確かめたかである。例は利用者向けの文書で、測ったモデルの名前と並べて示す）。
- `bias` は有限で、負の値だけを受ける（範囲は実装で決め、読み込みで止める）。正の値は終わりを早める向きで、この欄の目的と逆である。→ 範囲は **-10 以上 0 未満**にした（末尾の追記）。
- **`main` 面にだけ書ける。** `sub` 面に書いたら、鍵の名前を挙げて読み込みで止める。裏方（抽出・変容・約束・軸）の出力は JSON で、終わりを遅らせる理由が無い。
- **`sub` 面が無いときも、裏方には送らない。** ADR-0058 §決定1 の「`sub` 面が無ければ `main` の値を裏方にも使う」の例外にする。
- 書かない面の要求のバイト列は、今と1バイトも変えない（ADR-0058 §決定1 と同じ）。

### 2. 掛けるのは「その会話で、一度でも返答が目安の下限を割った」とき

本文の要求ごとに、次の3つが揃ったときだけ `logit_bias`（`{"<token>": <bias>}`）を載せる。

1. 面に `end_token_bias` がある。
2. キャラクターに目安（ADR-0065）がある。
3. **その会話（セッション）の保存済みの返答のうち、どれか1つでも字数が目安の下限より少ない。**

- 字数は保存している `raw_content` の文字数（Unicode のスカラー値の数）で数える。下限ちょうどは割っていない（`<` で比べる）。
  - 引き直しの後も空のまま保存された返答（ADR-0059）は 0 字と数えるので、その会話は以後掛かり続ける。空で終わるのも縮みの一つの形として、そのまま扱う。
  - 上流が思考を本文に漏らした回は、漏れた分だけ長く数え、短い返答を隠しうる。漏らす上流では掛かりにくい。
- **一度割ったら、その会話の間は掛け続ける。** 直前の返答だけで決めると、測ったとおり振動する。
- 状態は新しい列に持たない。毎回、その会話の保存済みの返答から決める。だから途中で目安の下限を上げれば、それより短かった過去の返答で掛かり始める（その会話は目安より短い返答を出している）。
- 別の会話（同じキャラクターの別のセッション）の短い返答では掛からない。
- 新しい会話の最初の往復は返答が無いので掛からない。
- 空の本文の引き直し（ADR-0059）は、元の要求と同じ値で送る。
- 掛けた往復では、`info` で1行出す（会話の識別子、下限、その会話の最短の返答の字数、送った値）。何に効いているかを観測できるようにする（ADR-0058 §決定3 と同じ目的）。

### 3. 画面でも書ける

ADR-0060 の面の編集に、`token` と `bias` の2つの欄を足す。省けば残す・`null` で消す・値で置き換える、の扱いは ADR-0060 §決定2 に揃える。**画面から `repeat_penalty` だけを直しても、手で書いた `end_token_bias` が消えないこと**を見張り番で固定する（ADR-0058 §決定6 の形）。

### 4. ADR-0036 §決定3 の条件に当てはめる

| 条件 | この値 |
|---|---|
| 根拠が無い | 番号はモデル（トークナイザ）ごと、強さはモデルとキャラクターで変わる（同じ -1.5 で、縮んだ会話の末尾6本の平均は ruby で 371 / 208 字、tsubaki で 222 / 229 字だった）。personacore の中に根拠は無い |
| 外すと破壊的 | 遅くなるのではなく、会話が縮んで戻らない（会話 A は 59 往復まで戻らなかった） |
| 導出も観測もできない | 測った推論サーバは終わりのトークンを答えない（`/props` に無く、`/tokenize` も無い） |

見張り番は `App::bind` を通して次の腕を置く。

| 腕 | 観測すること |
|---|---|
| 1 | 面に値があり、目安があり、その会話に下限未満の返答がある → 本文の要求に `logit_bias` が載る |
| 2 | 同じで、その会話の返答がすべて下限以上 → 載らない（要求のバイト列が欄の無い面と同じ） |
| 3 | 下限未満の返答の後に下限以上の返答が来ても、次の往復に載り続ける（「直前だけを見る」実装を赤にする） |
| 4 | 目安が無いキャラクターでは、短い返答があっても載らない |
| 5 | 裏方の要求には載らない（`sub` 面が無い構成で見る） |
| 6 | 同じキャラクターの別の会話の短い返答では載らない |
| 7 | 下限ちょうどの返答だけなら載らない（`<=` と取り違える実装を赤にする） |
| 8 | 切り替えで追従する。宛先とモデルが同じで `end_token_bias` だけが違うプロファイルの間でも効く（ADR-0058 §決定2） |

## 却下した選択肢

- **毎回掛ける。** 縮んだ会話は戻すが、新しい会話で目安の上端を超えて伸びる（平均 573 / 667 字）。
- **直前の返答が短いときだけ掛ける。** 振動して戻らない（上の表）。
- **目安の上限を超えたら外す（上下で切り替える）。** 測っていない。外した回に縮む形は「直前だけ」と同じになりうる。
- **-5 にする。** キャラクターの外の口調が1本出た。
- **短い返答を履歴から外す。** 2回のうち1回は下限に届かなかった（318 / 293）。履歴と以後の発言が噛み合わなくなる。
- **下限に届くまで終わりを禁じて、二段で生成する。** 推論サーバに最小のトークン数の指定が無く、続きを書かせるには OpenAI 互換の chat の外の口が要る（ADR-0038）。
- **personacore が既定の番号と強さを持つ。** 番号はモデルごとに違い、外れた番号を下げると、別のトークンを下げることになる。

## 結果

- 縮んだ会話を戻す手を、上流プロファイルを書く人が使えるようになる。
- 一度掛かった会話は、目安の上端を超えて伸びうる（毎回掛けた新しい会話では最大 1073 字）。目安の上端は天井ではない（ADR-0065 §決定4）。
- **「一度割ったら掛け続ける」の組み合わせそのものは測っていない。** 縮んだ会話では毎回掛ける形と同じになり、新しい会話では最初に割るまで掛からない、という推論である。遊んで確かめる。
- 測ったのは1つのモデル・1つのキャラクター（tsubaki）・1つの会話の続きだけである。

## 残したこと

- 縮みの入口。会話 A の往復5〜6 の手前で切った土台からは、再生でも4回中3回が縮んだ。新しい会話からの再生では8回とも縮まなかった。入口は往復1〜5 の間の状態にある見込みだが、何かは分かっていない。
- 番号を上流から引く方法（推論サーバが答えるなら引く。ADR-0036 §決定2 の第1階層）。
- 思考なしでの効き。

## 追記（2026-11-19 / A-22b の実装で決めたこと）

- **`bias` の範囲は -10 以上 0 未満**（`llm::END_TOKEN_BIAS_MIN`）。0 は書いたのに効かない値、正は目的と逆なので止める。-10 より下は、終わりのトークンの確率を約 2 万分の 1 より小さくする値で、実質「終わらせない」（返答の上限まで書いて切れる）。`-3.0` を `-30` と打ち損じた値もここで止まる。**測って決めた範囲ではなく、柵である**（`repeat_penalty` の 0.5〜2.0 と同じ立場）。`f64` では負でも `f32` に落とすと `-0.0` になる値（`-1e-50` など）も止める（送る値は `f32`）。`token` は `u32` に収まる 0 以上の整数なら通す（語彙の中かは上流でなければ分からない）。
- **読み込みの止め方**: `end_token_bias` がオブジェクトでない・`token` か `bias` が無い・範囲の外は `sampling_unusable`、中に知らない鍵（`token` / `bias` の外）があれば `unknown_sampling_key`、`sub` 面に書けば `main_face_only`。どれも鍵は `sampling` で、文面は止めた鍵の名前を挙げる。
- **字数の数え方**: その会話の応答のうち、`raw_content` のバイト数が下限の4倍より少ないものだけを DB から読み、字数（Unicode のスカラー値の数）は Rust で数える。SQLite の `length()` は最初の NUL までしか数えない（`sqlite3` で確かめた）ので、`length()` の最小を字数にすると、NUL を含む返答を短く読む。UTF-8 の1字は4バイト以下なので、下限より少ない字数の返答はこの絞り込みで落ちない。読みは要求を組む前に1回だけで、トランザクションは取らない。
- **ログ**: 掛けた往復の `info` は `character`・`session_id`・`response_length_min`・`shortest_reply_chars`・`logit_bias`（線の綴り）。起動時と切り替え時の「送るサンプラ」の行は、本文の面にだけ `end_token_bias`（線の綴り。書いていなければ `none`）を出し、書いた値は `overridden` にも並ぶ。この行が言うのは「掛けうる値」で、毎回送るわけではない。
- **画面**: 本文の面の「詳細」に番号と値の2つの欄を置く（番号はモデルごとに確かめる値なので畳む）。依頼の `sampling` は丸ごと置き換えなので、画面は一覧で読んだ値を下書きに入れ、繰り返しの罰だけを直した保存にも載せる。片方だけ書いた・範囲の外は、保存の前にその欄で言う（権威はサーバの 422）。一覧の本文の面には「終わりのトークン（縮んだ会話だけ）」を出し、書いていなければ既定の印「下げない」を添える。
- **欄の説明に、測った番号と値を出す**（利用者の要望 2026-11-19。番号の欄は何を書くものか、説明が無いと分からない）。番号の欄は「モデルの終わりの印の番号で、大小に意味は無く、モデルごとに1つ」「Qwen3.8-Flash-Next で確かめた番号は 248046」、値の欄は「マイナスに大きいほど長くなる」「-1.5 では足りず、-3 で戻り、-5 ではキャラクターらしくない一文が出た」と、掛かる条件を書く。ADR-0060 は実測の数を画面に置かない（ADR-0033・ADR-0036）が、ここでは**欄の値にも既定にもせず、どのモデルで測った数かを名乗った説明の文として出す**ので、その例外にする。モデルを替えた利用者には、番号を書き直すよう説明で促す。
- **保存の後の読み直しの照合**は、`sampling` の中のオブジェクトの中の数も 4 ULP 以内を同じとみなす（ADR-0060 の追記と同じ穴が、入れ子の `bias` にもあった）。
- API の版は `1.12`（応答の `sampling` と依頼の `sampling` に任意の鍵 `end_token_bias` が入った。小さい側）。
