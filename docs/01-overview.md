# 01. 概要

## 何を作るのか

ローカルLLMを使ったキャラクター会話システムの**オーケストレーション層**を Rust で実装する。

推論そのものは上流の推論サーバ（llama.cpp の `llama serve` や LM Studio など）に委譲する。本プロジェクトが担うのは以下:

- キャラクター定義（ペルソナ）と性格ステータスのプロンプト組立
- 会話記憶の抽出・保持・矛盾解消・想起
- 直近会話のコンテキスト管理と要約
- 台詞と地の文の構造化出力パース
- （フェーズ3）ComfyUI 連携による挿絵生成

**推論エンジンそのものは作らない。プロンプトと記憶の管理だけを作る。**


> **⚠ ここは「何を作るのか」であって「どこまで出来ているか」ではない**（2026-08-22 に注記）。
> **現在地は GitHub の Releases（出した版）と `gh issue list`（開いている作業単位 / [ADR-0043](adr/0043-work-units-open-and-close-as-issues.md)）が正**（順番とその理由は [06-roadmap.md](06-roadmap.md)）。
>
> | 上の箇条書き | いま |
> |---|---|
> | ペルソナ・性格ステータスの組立 | **動く**（属性・尺度・軸名の漏れ検出まで） |
> | 記憶の**抽出・保持・想起** | **動く**（[ADR-0021](adr/0021-memory-extraction-format.md)） |
> | 記憶の**矛盾解消** | **未着手**（フェーズ2。入口の設計は [ADR-0022](adr/0022-repairing-memories-without-deleting.md)） |
> | 直近会話の**コンテキスト管理** | **動く**（予算配分は `prompt::budget`） |
> | 会話の**要約** | **未着手**（**⚠ `summary` テーブルは `0001_initial.sql` から在る。** 読み書きする実装が無い） |
> | 台詞 / 地の文のパース | **動く**（[ADR-0007](adr/0007-output-format-markup.md) / [ADR-0014](adr/0014-nested-quotes-are-not-a-breakage.md)） |
> | ComfyUI 連携 | **未着手**（フェーズ3） |
>
> **記憶はベクトル検索していない。** 本文に載るのは、**利用者についての記憶のうち、想起が選んだ分**
> （[ADR-0023](adr/0023-three-layer-recall.md) の3層想起 / [ADR-0050](adr/0050-consolidating-memories-into-experience.md) §決め直し 1）。

> （[02-architecture.md](02-architecture.md)「記憶を検索に切り替える引き金」）。

## なぜローカルで作るのか

長期的な参照先は、商用サービス（DLsite にじGAME 等）で実装されている会話機能群。
それをローカル環境で再現し、**商用が原価の都合で妥協した部分を作り込む**ことが主眼。

| 商用の実装 | 妥協の理由 | 本プロジェクトの方針 |
|---|---|---|
| 直近N件スライディングウィンドウのみ | コンテキスト長 = 原価 | **要約チェーンで長期セッション対応** |
| メモリ20件 FIFO ＋ ユーザー手動ロック | 自動判定は追加推論が必要 | **自動的な重要度判定・矛盾解消** |
| 1メッセージ1推論 | 推論回数 = 原価 | **サブLLM並列呼び出しで裏方処理** |
| プロンプト枠を課金販売 | 収益モデル | 制約なし |

ローカル実行のため推論コストがゼロに近い。**「推論を余分に回してよい」という前提が、
設計上の最大の自由度**であり、商用との差別化点はすべてここから出てくる。

## 中核となる設計判断

**本サービス自体を OpenAI 互換 API サーバとして実装する。**

```
FE層（既存クライアントで可）
    ↓ POST /v1/chat/completions（OpenAI互換）
personacore（Rust）  ←→ SQLite
    ↓ POST /v1/chat/completions（OpenAI互換）
上流の推論サーバ（personacore が起こす llama.cpp / 既に動いているサーバ）
```

両側で同じ規格を話すことで、次の3つが同時に得られる:

1. **フェーズ1ではフロントエンドを一切書かずにコア機能を検証できる。**
   既存の OpenAI 互換チャットクライアントをそのまま FE として使う。
2. 推論バックエンドを差し替えられる（実際に LM Studio から llama.cpp の `llama serve` へ移った。
   上流に求める能力は [ADR-0038](adr/0038-what-personacore-requires-of-an-upstream.md)）。
3. フェーズ2で自作 FE を載せる際も、本サービス側は変更不要。

詳細は [ADR-0001](adr/0001-openai-compatible-boundary.md)。

## スコープ外（やらないこと）

個人利用のローカルツールであることを前提に、以下は明示的に作らない。

- コンテンツフィルタリング
- 認証・認可（`127.0.0.1` バインドのみ。**外部公開しない**）
- モデルのファインチューニング / LoRA 学習
- TTS 連携
- マルチユーザー対応
