# ADR-0027: 上がった軸だけをモデルに尋ね、下がる側は構造で作る

- 状態: **採用**
- 日付: 2026-08-23
- 関連: [ADR-0026](0026-drift-by-accumulation.md) の **§決定2（一律 ±1 の閾値）を置き換える**。
  §決定1（記録専用モード）と §決定3（票の表）はそのまま。
  [ADR-0024](0024-stat-drift.md) の **§4（値 0 の軸は対象外）と §5（下端は 1）も置き換える**。
  判定の依頼の形・許可リスト・1ターン1軸・既定 off は変わらない。

## 背景 —— **閾値だけでは決められなかった**

[ADR-0026](0026-drift-by-accumulation.md) の実測（16d / 72ターン / 記録専用モード）:

| | m12（30ターン） | **m13（72ターン）** |
|---|---|---|
| 提案率 | 100% | **100%** |
| `+1` : `-1` | 70% 上げ | **68 : 4（94% 上げ）** |
| 目で読んだ噛み合い | 47% | **36%** |
| 票の集中 | — | **共感 57/72（79%）／陽気さ 0** |

**そして当て直しても `K` が決まらなかった** —— どの `K` でも同じ軸が上端に着き、
**72ターンのうち 38〜53 ターンは貼り付いたまま**になる。

**下がった軸は、m12・m13 のどの規則でも1つも無い。**

## 診断 —— ~~**測定器そのものが偏っている**~~ **軸が偏っていた**

> **⚠ 2026-08-24 / 16i で覆した。この節を読む前に「実測（16i）」節を読むこと。**
> **偏っていたのは軸である。** `共感` `自信` `慎重さ` は**「良い助手の振る舞い」の名前**なので
> 常に `+` が返る。**`皮肉` `ユーモア` `強気` に替えると、上げ偏りは 68% → 49% に消え、**
> **`0` の率は 1〜7% から 78〜80% に上がった**（＝**モデルは「なし」を言える**）。
> **この節の観測そのものは正しい。原因の帰属だけが違っていた。**

利用者の指摘（2026-08-23）が、3つの観測を1つに繋いだ:

> **人間の好感度のイメージを持って貰ったらわかりやすい。**
> **＋の言動は率直に現れやすい。−の言動ははぐらかしやすい（測定しにくい）。**
> **特に LLM は利用者に対して共感的・好意的に振る舞うよう作られているので、その傾向は顕著。**

**判定に使っているのは RLHF を通ったモデルである。**

- **共感が票の 79% を取る** —— 共感は**モデルの既定のモード**で、社交的なやり取りを見せれば必ず候補に挙がる。**判別の結果ではなく初期値。**
- **下げが 4/72 しか出ない** —— 「この人物の自信は下がった」は**否定的な判定**であり、避けられる。
- **指示が効かない**（`NOTHING_RULE` / `NO_GUESSING`）—— **指示の書き方の問題ではなく、気質に触れていた。**
  2度の失敗が、同じ原因で説明できる。

> **下向きは「起きていない」のではなく「測れない」。**
> **会話の中では起きているが、判定器が見せてくれない。**

## 決定

**モデルに尋ねるのは「上がった軸」だけ。下がる側・天井・育ちは、すべて構造から作る。**

### 1. 票は float。重みは**軸の希少度**

**選ばれた軸の1票の重みを `1 / その軸のそれまでの提案回数` にする。**

**モデルに強度を尋ねない**（[ADR-0024](0024-stat-drift.md) で却下済み。小型モデルは程度の判断で崩れる）。
**重みは「その軸が何回選ばれたか」だけから決まる。**

`prompt::relevance` の希少度（`RARITY_SCALE / df`）と**同じ考え方**である ——
**珍しい提案ほど情報量が大きい。**

**実測**（m13 の 72 票に当て直し。`scratchpad/m13/replay/RULES.md`）:

| | 一律 ±1 | **軸の希少度** |
|---|---|---|
| 共感 | **上端に貼り付く**（飽和 22 / t19 到達） | **止まる**（**飽和 0** / 5→7〜9） |

> **代償: 早い票が重い。** 自信の票列は `+ + − + − −`（上げ3・下げ3）で **net 0** だが、
> 早い上げが重いので **+1 動く**（一律なら動かない）。**これは残る歪みである。**

### 2. **選ばれなかった軸は薄れる**

**毎ターン、モデルは1軸を選ぶ。選ばれなかった N−1 軸の情報を、いままで捨てていた。**

**選ばれなかった軸は、向きに依らず減る**（減る量は **§3** が決める。`w` は §1 の重み）。

- **モデルに「下げろ」と言わせない。** 下向きは**選択の補集合**から来る。
- **向きに依らない。** 好感度の喩えのとおり ——
  **言及されなかったことは、その言及が良くても悪くても等しく薄れる。**
  （「A が下がったぶん B が上がる」は筋が通らない）

**これは「差分・流れから拾う」という利用者の要求への回答である** ——
**増幅ではなく、相対的な選択そのものを信号として使う。**

### 3. **薄れる量は、その軸の現在値に比例させる**

**選ばれなかった軸 `b` が失う量は `λ × (v_b / 尺度) × w / (N−1)`。**

**総和保存（奪った量＝与えた量）は採らない。** 利用者の反例が決定的だった:

> **全てのパラメーターをゼロから始めて感情を育てるロールプレイ。**

**総和が 0 なら何も育たない。** 上げは必ず誰かから奪うので、**全員 0 は動かない床になる。**
**実測**（m13 / K=1 / 総和保存）: **ゼロ始まりで飽和 4** —— 奪う先が床に当たり続け、**育つ前に止まる。**

**では奪う量を減らせばよいか（`λ < 1` の一律）——それも違った。**
**実測**（腕C / 票が均等 / K=1）: `λ=0` で総和 20→30、**`λ=0.5` でも 20→25。**
**票が均等になると、一律の `λ < 1` はインフレを止めない。遅くするだけである。**

**現在値に比例させると両立する**（実測 / K=1）:

| | 初期 5 から | **ゼロから育てる** |
|---|---|---|
| **λ=1** | 上げ6 下げ2 / 総和 20→**24** | **上げ9 下げ0 / 総和 0→9（飽和 0）** |
| λ=2 | 上げ6 **下げ7** / 総和 20→**19** | 上げ9 下げ1 / 総和 0→8 |

- **値が低い軸はほとんど薄れない** → **ゼロから育つのを一切邪魔しない。**
- **値が高い軸ほど強く薄れる** → **上端の手前で自然に釣り合う。**
- **`λ` は「どこで釣り合うか」を選ぶつまみになる。**

> **総和保存との違いは制約の種類である。**
> **総和保存は「誰かが上がるには誰かが下がる」。これは「高く保つのは元手がかかる」。**
> **前者はゼロを動かない床にするが、後者は床を作らない。**

> **⚠ ここは一度「一律の `λ < 1`」で書いていた**（2026-08-23 / 腕C の測定で訂正）。
> **当初の実測（m13 / 受け皿のある提案列）では `λ=0.5` で総和 25→29 と収まって見えた**が、
> **票が均等な提案列（腕C）で測り直すと `λ=0.5` でも総和 20→25 で増え続けた。**
> **偏った提案列だけで釣り合いを見ると、釣り合っているように誤って見える。**

### 4. **値 0 の軸も、変容の依頼には載せる**（[ADR-0024](0024-stat-drift.md) §4 を置換）

**本文プロンプトには載せない**（CLAUDE.md 絶対制約はそのまま）。**変容の依頼にだけ載せる。**

**絶対制約の理由は「演技する側」の問題である** ——
「パッション: 0/5」と書くとモデルが**情熱の欠如を過剰演技して無感情になる**。
**変容のサブLLM は演技していない。判定しているだけである。**

そして [ADR-0024](0024-stat-drift.md) §4 が挙げた理由
「**モデルが読んでいない軸を、モデルの判断で動かさない**」は、
**載せることで満たされる。**

### 5. **下端は 0**（[ADR-0024](0024-stat-drift.md) §5 を置換）

**§4 により 0 は片道ではなくなった。** 落ちても戻れるので、
「変容が軸をプロンプトから消す」ことを塞ぐ必要が無い。

**飽和は上端 `尺度` と下端 `0` で数える**（クランプしない、は変わらない）。

### 6. **依頼を組み立てる門を変える**

いまは「**プロンプトに載る軸が1つも無ければ依頼を作らない**」
（`a_character_with_nothing_to_show_gets_no_request`）。

**全部ゼロのキャラクターはこの門で止まる —— 育て始めることが原理的にできない。**

**条件を「軸が1本でも定義されているか」に変える。**

> **§4 と §6 は必ず一緒に入れること。**
> **片方だけだと、ゼロ始まりが黙って動かないキャラクターになる。**

### 7. **「なし」は、モデルではなく閾値が出す**

> **⚠ この節に載っている `K` の表は `1/n` 時代の数である**（訂正 3 で重みが変わった）。
> **決定そのもの（閾値が「なし」を出す）は生きている。数だけ訂正 5 を見ること。**

**`NOTHING_RULE` は2度失敗した。閾値はその失敗を無意味にする。**

**モデルは毎ターン何かを答える。それは変わらない**（3本の腕・216ターンで「なし」ゼロ）。
**変わるのは、キャラクターの数値が動くかどうかである。**

**実測**（腕C の提案列 / λ=1 / 現在値に比例する減り方）:

| `K` | **数値が動かなかったターン** | 上げ | 下げ |
|---|---|---|---|
| 0.75 | 58/72（**81%**） | 10 | **6** |
| **1** | **64/72（89%）** | 6 | **2** |
| 1.5 | 69/72（96%） | 3 | **0** |
| 2 | 71/72（99%） | 1 | **0** |

**ゼロから育てる場合も同じ**（K=1 で 63/72 = 88% が「なし」、総和 0→9）。

> **`K` は2つのことを同時に決める。** **静かにするほど下向きが消える** ——
> 減衰はじわじわ効く滴なので、`K` が大きいと**溜まりきる前に次の票が来て流される。**
> **「落ち着かせる」と「下がれるようにする」は同じつまみの両端にある。**

### 8. ~~**`λ` と `K` の当面の値**~~ **16j が置き換えた**

> **⚠ 2026-08-25 に更新。** **`λ = 0.5` / `K = 0.3` / 依頼の形 `all`**（作業単位 19 で製品の既定へ）。
> **出どころは末尾の「16j」節** —— 実データ2本に 16 通り当てて、5つの条件で採点した。
> **`stat_drift` の既定は `off` のまま。** これは**有効にしたときの既定**である。
> **下の `λ = 1` / `K = 1` は、合成した提案列で釣り合わせた出発点**で、
> **実データでは 359 ターンで 3 段・下げ 0 だった**（16h）。


**`λ = 1`・`K = 1`** を出発点とする（腕C の提案列で **89% が「なし」・両方向が出る・ゼロからも育つ**）。

> **⚠ これは「決めた」ではなく「出発点」である。**
> **判定の噛み合いが 32〜36% の入力で釣り合わせた値**でしかない。
> **入力の質が変われば釣り合いも動く。** 実装する側は**定数にして、設定で振れる形**にすること。

## 理由 / 却下した選択肢

- **下げの票を「向きの希少度」で重くする** —— **実測で却下。**
  雑音の軸（自信 / net 0）は正しく動かなくなったが、
  **本物の信号（好奇心 net +5・慎重さ net +4）まで黙った。**
  4件しかない下げを重くすると、**たまたま出た4件が全体を支配する。**
  > **判定器が隠しているものを、増幅して取り戻すことはできない。**
  > **はぐらかされた分は最初からデータに入っていない。**

- **総和保存（奪った量＝与えた量）** —— §3。**ゼロから育てられない**（実測で飽和 4）。
  **`λ = 1` と混同しないこと。** §3 の `λ` は**現在値に比例する減り方**の強さで、
  `λ = 1` でも**総和は保存されない**（ゼロ始まりで 0→9 に育つ）。
- **一律の `λ < 1`** —— **票が均等になるとインフレを止めない**（腕C で `λ=0.5` でも 20→25）。

- **下げを促す指示を書く** —— **2度実測で失敗している**
  （[ADR-0021](0021-memory-extraction-format.md) 13c-2 と [ADR-0024](0024-stat-drift.md) の `NOTHING_RULE`）。
  **気質に触れる指示は効かない。**

- **モデルに強度（float）を出させる** —— [ADR-0024](0024-stat-drift.md) で却下済み。

- **票を整数のまま、閾値を軸の提案回数で膨らませる** —— **実測で悪化**
  （共感が t6 で上端。閾値が伸びるより net が速く伸びる）。

## 結果

### できるようになること

- **下向きが出る。** モデルに一度も「下げろ」と言わせずに。
- **ゼロから育てられる。** 総和に天井が無い。
- **減衰率が自由なつまみでなくなる** —— **選ばれた量から決まる。**

### **測れていないこと（重要）**

- **下向きは、実データで一度も観測していない。**
  いま出ている下げは**すべて当て直しの計算上のもの**である。
  **実機で下がる姿は、上端から始める軸（下向きの probe）で初めて見える。**
- **「選ばれなかった」の意味が2つある。**
  **その性質が現れなかったのか、モデルが見落としたのか、区別できない。**
  後者なら、**測定器の偏りを性格に焼き付けている**ことになる。
- **早い票が重い歪み**（§1 の代償）は残る。

### この一件から残すもの

**指示で直す／少数の報告を増幅する、はどちらも実測で潰れた。**
**残ったのは「言われなかったこと」を使う道だった。**

**判定器の偏りは、迂回はできるが、除去はできない。**

## 実測（2026-08-23 / 16d-2 / **腕B と腕C**）

**m13 とまったく同じ 72 ターンの台本**（`turns.txt` の md5 一致を確認）を、
**変えるものを1つに絞って**2本回した。生データは `scratchpad/m14/`。

| | m13 | **腕B**（サブモデルを 3B へ） | **腕C**（共感を外した4軸） |
|---|---|---|---|
| 最大の軸の割合 | **共感 79%** | **慎重さ 33%** | **陽気さ 31%** |
| 0票の軸 | **陽気さ** | なし | なし |
| `+1` : `-1` | 94% 上げ | **80%** | **85%** |
| **「なし」** | **0** | **0** | **0** |
| 破棄 | 0 | **3**（形式を崩した） | 0 |
| 目で読んだ噛み合い | 36% | **35%** | **32%** |

### 2つの仮説は**どちらも当たり、どちらも解決ではなかった**

- **モデルの能力である** —— 腕Bで共感が **79% → 19%**、陽気さが **0 → 10票**。
  [ADR-0021](0021-memory-extraction-format.md) §10 と同じ形。
  **ただし 3B は代わりに形式を 4% 崩し、向きの誤りを増やした**（2件 → 5件）。
- **`共感` は受け皿の軸だった** —— 腕Cで **31/25/24/21% とほぼ均等**になった。
  m13 で陽気さが0票だったのは、**同じ 14B が同じ会話で陽気さに 22 票入れる**（腕C）ことから、
  **共感が吸っていた**と言える。

### **受け皿は移る**

腕C は **t1〜t5 が5回続けて `陽気さ+1`**、泣いている子どもの回に `好奇心+1`。
**`共感` という語が悪いのではない。「何か選べ」と言われたら、何かが受け皿になる。**

### **受け皿を外すと、今度は全軸が上端へ行く**

腕C に一律の閾値（K=2）を当てると **3軸が 10/10 に到達**する（t26 / t53 / t63）。

> **「1軸だけ振り切れる」が「全部振り切れる」に変わっただけだった。**
> **軸を選び直しても、閾値だけでは端に着く。**

### **3本とも残ったもの＝依頼の形そのもの**

**216 ターンを通して「なし」はゼロ**（「なし」が正解と読める 17 回すべてに提案が出た）。
**上げ偏り 8割、噛み合い 3割台も3本とも揃う。**

**モデルを替えても軸を替えても直らない。** これが §決定7（閾値に出させる）の直接の根拠である。

> **副産物: [ADR-0024](0024-stat-drift.md)「次に試す順」の 3（モデルを替える）は、この測定で片付いた。**
> **替えても「なし」は出ない。** 残るのは **1（「なし」を出させる）** と **2（軸ごとの説明）** で、
> **1 は §決定7 が構造で迂回した。**

### **残った限界 —— 分化しない**

腕C に本 ADR の規則（λ=1 / K=1）を当てると、**72ターンで 5/5/5/5 → 6/6/6/6。**

**全部が同じだけ上がっただけで、キャラクターは分化していない。**

> **規則はもう健全である。入力が 32〜36% しか噛み合っていないので、出力が均される。**
> **構造でできることはここまで。次は入力の質である。**

## 追測（2026-08-23 / **経済的な値付け**）

利用者の提案:

> **需給曲線的に、各パラメーターごとに変動が多い（供給が多い）なら、
> 変動させたい需要は一定なのでコスト（変動値の係数）を下げる。**
> **ゲームのようにレベル MAX が近づいたり、各レベルごとに1上がるのに必要な経験値が異なるのも、その一種。**

**前半は既に入っていた** —— **§決定1 の希少度の重み `1/n` は「供給が増えると価格が下がる」そのもの**である。

**後半（レベルごとに値段が違う）は入っていなかった。** 測った。

### 9. **1段動かす費用を、現在値と向きの関数にする**

> **⚠ この節の表は `1/n` 時代・傾き `2` の数である。** 訂正 1 が傾きを、訂正 2 が費用の基準を、
> **訂正 3 が重みを変えた。決定（中点を基準にした非対称の値付け）は生きている。数は訂正 5。**

**中点を基準に、上げは高い値ほど高く、下げは高い値ほど安い。**

```
費用(v, 上げ) = K × (1 + 傾き × (v − 尺度/2) / 尺度)
費用(v, 下げ) = K × (1 − 傾き × (v − 尺度/2) / 尺度)
```

**中点では両方 `K`** なので、**中間の振る舞いを一切乱さない**（実測で「なし」89% を維持）。

**実測**（腕C の提案列 / λ=1 / K=1）:

| 初期値 | 一律 | **レベル依存＋非対称（傾き 1.5）** |
|---|---|---|
| **8（上端寄り）** | 上げ5 下げ5 / 総和 32→32 | 上げ4 **下げ9** / 総和 32→**27** |
| 5（中間） | 上げ6 下げ2 / 20→24 | 上げ6 下げ3 / 20→23 |
| **0（育てる）** | 上げ9 / 0→9 | **上げ17** / 0→**17** ⚠ |

> **⚠ 「0（育てる）」の行は一度 `上げ20 / 0→19` と書いていた**（2026-08-24 に訂正）。
> **あれは傾き `2` の値で、「無償の1段」を含んでいた**（訂正節 1）。
> **傾き 1.5 の実測は `上げ17 / 0→17`。** 他の2行は**傾き 1.5 でも一字一句そのまま**である
> （端の費用が変わっても、中点に近い側は動かないため）。

**効くのは端だけ** —— **低いところは伸びが2倍以上速く、高いところは下向きが優勢になる。**
**これは上げ偏り 94% への、経済的な対抗策である。**

> **⚠ 一度、式を対称に書いて効かないことがあった**（2026-08-23）。
> `費用(下げ) = K × (1 + 傾き × (尺度 − v)/尺度)` と書くと**中点で上げも下げも `K × 1.5`** になり、
> **どちらも高くなるだけで非対称にならない。下げが 0 件になった。**
> **中点を基準に引くこと。**

### 10. **減衰と値付けは別物。両方要る**

**レベル曲線だけ（減衰なし）では下向きが出ない。** 実測（λ=0 / 腕C）:
**初期5 で 上げ8・下げ0、初期0 で 上げ22・下げ0。**

> **曲線は下向きを作らない。値段を付け直しているだけである。**
> **下向きの源は §決定2（選ばれなかった軸が薄れる）ただ1つ。**

| 部品 | 役割 |
|---|---|
| **§2・§3 の減衰** | **下向きの源。** 唯一の供給元 |
| **§9 の値付け** | **速さと向きの偏り。** 序盤を速く、上端で下向き優勢に |

### 11. **ゼロから育てると分化する。中間から始めると均される**

**これがいちばん実用に効く発見である。**

**実測**（m13 の提案列 —— **受け皿があり、共感が 79%、陽気さが 0 票**の最悪の入力）:

2. **⚠ 減衰の源が消えるかもしれない。**

   「**0 と採点された軸**」に置き換わる。**モデルが全部に `+1` を付ければ 0 が1つも出ず、

3. **希少度の数え方が壊れる。** §決定1 は「その軸が何回提案されたか」で割るが、

  docs/05-development.md「属性を実験の切り替えスイッチとして使う」と同じ作法。
- **分解器は「0 と採点された軸」と「行が無い軸」を区別すること。**
  **行が無いのは形式の崩れであって 0 ではない。**
- **応答のトークン上限を N 行ぶんに広げること**（いまは 64）。

### **測る問い（1つ）**

> **`0` は実際に出るか。**

**出れば**、「なし」を**モデルと閾値の両方**が出せることになり、
**`K` をもっと小さくできる**（＝キャラクターがもっと敏感に動く）。

**出なければ**、**「モデルは何を尋ねても肯定的な答えしか返さない」**という、
**より強い結論**になる。**それ自体がこの基盤にとって重要な発見である。**

**m13 とまったく同じ 72 ターンの台本**（md5 一致）× **`PERSONACORE_DRIFT_FORM=all`**。

> **`0` は判断ではなく「割り当て」である。** モデルは**毎ターンほぼ1個だけ `0` を書く。**

| 危険 | 結果 |
|---|---|
| **1. 列挙で崩れる** | **起きた。ただし予想と違う形。** |
| **2. 全部に `+1` を付ける** | **起きなかった。** 減衰の源は消えていない |
| **3. 希少度が一律に戻る** | **半分起きた。** |

**危険1 —— 崩れは 22/72（31%）。同じ 14B・同じ台本の `single` は 0% だった。**
**だが「行を飛ばす／重ねる」は1件も無い**（**72/72 が5行ちょうど**）。

## 訂正（2026-08-24 / 作業単位 16e-b の実装で判明）

**実装者が、この ADR の記述と当て直しの道具（`scratchpad/m16/all.awk`）の食い違いを3つ見つけた。**
**どれも ADR 側の誤りである。**

### 1. ⚠ **傾き `2` は「無償の1段」を作る。既定を `1.5` に下げる**

**§9 の式は `費用(v, 上げ) = K × (1 + 傾き × (v − 尺度/2) / 尺度)`。**
**`v = 0` を入れると `K × (1 − 傾き/2)` で、傾き `2` では厳密に 0 になる。**

**費用が 0 だと、累積が 0 のままでも段が動く** ——
**値 0 の軸が、会話で何も言われなくても毎ターン 1 に上がる。**

> **`傾き < 2` は尺度に依らない普遍の条件である**（中点が常に `尺度/2` なので）。
> **上限は 2 未満にすること。**

**既定を `1.5` にする**（`費用(0, 上げ) = K × 0.25`）。**最終値は変わらない**（実測）:

| | 傾き 2（**誤**） | **傾き 1.5** |
|---|---|---|
| 初期 5 | なし85% / 上げ8 / 下げ7 / **8-2-4-4-8** | なし86% / 上げ8 / 下げ7 / **8-2-4-4-8** |
| 初期 0 | なし88% / 上げ18 / **飽和0** / 0→15 / **6-0-0-3-6** | なし86% / 上げ16 / **飽和1** / 0→15 / **6-0-0-3-6** |

**飽和が 1 になるのは正しい振る舞い** —— 値 0 の軸に `-1` が来て、下端で止まる。

### 2. **薄れる量の式は、依頼の形で違う**

**§決定3 は `λ × (v/尺度) × w / (N−1)` と1つだけ書いていたが、実際は2つある。**

| 形 | 薄れる軸 | 1軸あたりの量 |
|---|---|---|
| **`single`** | 選ばれなかった **N−1 軸** | `λ × (v/尺度) × w / (N−1)` |
| **`all`** | **`0` と採点された軸**（0〜N 軸） | `λ × (v/尺度) × (1/N)` |

**`all` に `w` が無いのは、`0` と採点された軸が票を持たないから。**
**薄れる軸の数が可変なので、1軸あたりを定数にした。**

**`1/N` を選んだ理由**: **全軸が `0` のとき、合計が `single` の1ターンぶんと釣り合う。**
**`1/(N−1)` でも回るが、実測で総和が 25→23 と減る**（`1/N` は 25→26）。**どちらも可。**

### 3. **§9 の ⚠ の数と、「値付けあり」の表の λ**

- **「対称に書くと中点で `K×1.5`」は傾き `1` の値。** 傾き `2` なら `K×2.0`。
  **数ではなく性質で読むこと** —— **両端から測る式は `K` を下回る場所が無いので、下向きが出ない。**
- **「値付けあり → 総和 0→18」は `λ = 0` の値。** **`λ = 1` では 0→15**（「当面の設定」の表と一致）。
  **飽和の数（4 → 0）は `λ` に依らない**ので、値付けの効果はそちらで読むこと。

> **3つとも「公表した数を出した道具」と「書いた式」がずれていた形である。**
> **当て直しの道具はスクリプトなので、ADR に写した時点で写しが2つになる。**
> **実装が3つ目の写しになって初めて食い違いが出た。**

## 訂正 2（2026-08-24 / **尺度に依存していた**）

利用者の指摘:

> **数値の変動が、パラメーターの幅によって大きく意味合いが変わってくる。**
> **`0-10` での 1 の変動と `0-100` での 1 の変動は、全く意味合いが変わってくる。**

**加味できていなかった。** §決定1〜3・§9 のうち**2つは尺度で正規化されている** ——
薄れ `λ × (v/尺度) × …` も、費用の傾き `(v − 尺度/2)/尺度` も**比なので尺度に依らない。**

**残る1つが漏れていた** —— **「1段は必ず 1」なのに、その1段の費用がどちらの尺度でも `K`。**
**尺度 100 では、範囲の1割を動くのに 10 段＝10 倍の証拠が要る。**

### 実測（腕E の採点表 / λ=1 / 傾き1.5 / K=1 / 初期値は尺度の中間）

| 尺度 | **いまの規則** | **1段の費用を尺度で正規化** |
|---|---|---|
| **10** | 80% / 20% / 40% / 40% / 80% | **80% / 20% / 40% / 40% / 80%（同一）** |
| 50 | 56% / 44% / 46% / 48% / 56% | 80% / 24% / 38% / 36% / 78% |
| **100** | **53% / 46% / 48% / 49% / 53%** | **80% / 23% / 37% / 35% / 75%** |

**尺度 100 では、同じ会話でキャラクターがほとんど動かない**（全軸が 46〜53% に張り付き、**分化が消える**）。
道具は `scratchpad/m16/scale.awk`。

### 決定 —— **1段の費用を `K × (既定尺度 / 尺度)` にする**

```
費用(v, 上げ) = K × (既定尺度/尺度) × (1 + 傾き × (v − 尺度/2) / 尺度)
費用(v, 下げ) = K × (既定尺度/尺度) × (1 − 傾き × (v − 尺度/2) / 尺度)
```

**既定尺度は `StatScale::DEFAULT` = 10。**

- **尺度 10 の振る舞いは1バイトも変わらない**（上表の1行目が完全一致）。
  **これまでの測定値・この ADR の表・既存の見張り番はすべてそのまま有効。**
- **`K` の意味が「1段の費用」から「尺度を10段ぶん動かす費用」へ変わる。**
  **同じ `K` が、どの尺度でも「範囲の何割を動かすのにどれだけの証拠が要るか」を表す。**

> **⚠ 亜正規数の門（訂正節 1 の対称の形）も締まる。**
> **いちばん安い段は `K × (既定尺度/最大尺度) × (1 − 傾き上限/2)` = `K × 0.1 × 0.1` = `K × 0.01`。**
> **`DriftTuning::new` の検証をこの係数に合わせること。**

> **完全に一致はしない。** 値が整数なので丸めが残る（尺度10 の 20% に対し 尺度100 は 23%）。
> **見張り番は「割合が近いこと」で置くこと**（数ポイントの許容つき）。

### **利用者の当初の提案は、ここを指していた**

> **投票方式（1か0か）ではなく、float を使って経験値方式。**

**整数の1段では、尺度ごとに1段の意味が変わる。** **蓄積を連続量にしたのはそのためだった。**
**蓄積は入れたが、取り出す側（費用）を尺度で割るのを落としていた。**

## 訂正 3（2026-08-24 / **速さの目標そのものが違っていた**）

利用者の指摘:

> **私はこれを受けて 0-10 の時の振る舞いを変えるかなと思っていました。**

> **ローカルLLM という、ある種無限に会話できる環境を前提にこの謎ツールを作っているので、**
> **会話を重ねていって何日か経ったら「何か変わった？」という経験も大事では。**

**訂正 2 は「尺度 100 を尺度 10 に合わせる」形だったが、合わせる先を検討していなかった。**

**いまの規則は 72 ターンで範囲の 30% 動く**（5 → 8 / 5 → 2）。
**一晩の会話で「自信が平均から高へ、好奇心が高から低へ」。**
**「本質はそう簡単に変わらない」とは言えない。**

### **`K` は速さのつまみとして使えない**

**重み `1/n` の合計は調和級数なので、対数でしか伸びない。**
**72 ターンで貯まる上限は約 4.6** —— **`K = 5` では原理的に永遠に届かない。**
**実測でも `K = 5` 以上は 0 段**（崖であって、遅くなるのではない）。

### **実機がこれを確認した**（16f / 腕H）

**`自信` は上げ 53 票を集めながら、累積 `0.911` に対し費用 `1.000` で止まった。あと `0.089`。**

> **「早く決着して、あとは凍る」。**
> **利用者の要望（何日か経ったら変わる）と、構造的に逆である。**

### 決定 —— **重みを `1/n` から `1/√n` へ。係数 `0.1`**

**実測**（腕E の採点表を 14 回繰り返して 1008 ターンに伸ばしたもの）:

> **既定の `λ = 1` では表のとおりにならない。** 結論（`1/√n × 0.1`）は変わらないが、
> **`all` の薄れの式を一緒に直して初めて成り立つ。**

- **200ターン超で 4 段** —— **「何日か経って、何か変わった？」**

**2つは直交している。** 正規化を入れると**役割が分かれる**:

| つまみ | 意味 |

| **尺度** | **粒度** —— `0-10` か `0-100` か。**速さには影響しない** |

## 訂正 4（2026-08-24 / **訂正 3 の表は `λ = 0` で出ていた**）

**作業単位 16g を出す前に、司令塔が訂正 3 の表を自分で再現しようとして見つけた。**
道具は `scratchpad/m18/shape*.awk`（腕E の採点表 `m16/e.tsv` を 14 回繰り返す）。

### 再現の結果 —— **薄れが切ってあった**

| 訂正 3 の行 | 再現に必要だった `λ` | 一致 |
|---|---|---|
| `1/n × 1`（現在） | **`λ = 0`** | 72・504・1008 が完全一致（216 だけ 2 桁ずれ＝転記の誤り） |

**既定は `λ = 1` である。** つまり訂正 3 の表は、**この設計の下向きの唯一の源である薄れを

### **⚠ そして、いまの実装も長期では崩れる**（16g が持ち込む欠陥ではない）

`λ = 1` / 重み `1/n` / 薄れ `1/N` —— **出荷済みの規則そのもの**を 1008 ターン回すと:

| 初期 | 72 | 216 | 504 | **1008** |
|---|---|---|---|---|
| 中間から | 8 2 4 4 8 | 8 1 2 1 7 | 8 1 1 0 4 | **8 0 0 0 2** |
| ゼロから | 6 0 0 3 6 | 6 0 0 1 6 | 6 0 1 0 4 | **6 0 0 0 2** |

**5軸のうち4軸が 0 に落ちて戻らない。** 16f が 72 ターンしか回さなかったので見えていなかった。

**原因は釣り合いの崩れである。**

```
票の重み   = 1/n        … n とともに減る
薄れの重み = 1/N（定数） … 減らない
```

**`n` が増えるほど薄れが相対的に強くなる。** 重みを `1/√n × 0.1` にすると
**初手から薄れが 30 倍強くなる**ので、崩れが 1008 ターンから序盤へ前倒しになるだけだった。

> **`single` の形には最初から無い。** あちらは `w/(N−1)` で、**票の重みに比例している。**
> **崩れているのは `all` の `1/N` だけ**である。

### 決定 —— **`all` の薄れも、その回に立った票の重みに比例させる**

```
all の薄れ = λ × (v/尺度) × (その回に立った票の重みの合計) / N
```

**定数 `1.0` が `票の重みの合計` に変わるだけ**で、割る数 `N` は公表済みの値のまま。
**これで `single`（`w/(N−1)`）と同じ形になる** ——
**「その回に配られた票を、受け取らなかった軸が失う」**という一つの規則に揃う。

### 実測（`1/√n × 0.1` / λ=1 / 傾き1.5 / K=1）

| 薄れ | 72 | 216 | 504 | **1008** | 下げ |
|---|---|---|---|---|---|
| **`1/N`（いまの実装）** | 6 4 4 3 5 | 6 2 2 1 5 | 7 1 1 0 4 | **7 0 0 0 3** | 17 |
| **`票の重み/N`（採用）** | **6 5 5 5 6** | **6 4 5 5 7** | **7 4 5 5 8** | **8 3 5 5 9** | **2** |
| `票の重み/(0 の軸の数)` | 6 4 5 5 6 | 6 4 5 4 7 | 7 3 4 3 7 | 8 2 4 3 8 | 6 |

**採用した行は、訂正 3 が狙っていた軌跡をそのまま満たす** ——
**一晩で 2 段・200ターンで 4 段・1000ターンで 9 段、飽和 0、下げも出続ける。**
**訂正 3 の結論（`1/√n × 0.1`）は撤回しない。前提を1つ補う形になった。**

**ゼロから育てる形でも崩れない**（§決定6 の要件）:

| 薄れ | 72 | 216 | 504 | **1008** |
|---|---|---|---|---|
| `1/N` | 2 0 1 1 3 | 4 0 1 0 3 | 4 0 1 0 3 | **5 0 1 0 2（凍結）** |
| **`票の重み/N`** | 2 0 1 1 3 | 4 0 1 1 4 | 5 0 2 1 6 | **6 0 3 1 7（伸び続ける）** |

### **却下した形**

- **`票の重み/(0 と採点された軸の数)`** —— **完全な保存則**（配った票と失う票が釣り合う）で
  いちばん美しいが、**`k = 0`（誰も採点されない）で 0 除算、`k = N` で薄れが消える**という
  端が2つ増える。**下げが 2 → 6 に増える効果は `λ ≈ 2.5` で届く**ので、
  **つまみで済むものを場合分けにしない。** 数は上表に残した。
- **`λ` を 0.1 に下げる** —— 定数のままなので**崩れる時期が遅れるだけ。**

### **訂正 2（尺度の正規化）は、この形でも効いている**

`1/√n × 0.1` ＋ `票の重み/N` ＋ 1段の費用 `K × (既定尺度/尺度)` で、**尺度 100 が尺度 10 に揃う:**

| 尺度 | 72 | **1008** |
|---|---|---|
| **10** | 60% 50% 50% 50% 60% | **80% 30% 50% 50% 90%** |
| **100** | 60% 43% 50% 50% 62% | **85% 28% 57% 46% 90%** |

**丸めぶんの数ポイントだけずれる**（訂正 2 が予告したとおり）。

### この一件から残すもの

> **散文で書いた式は、実装が3つ目の写しになって初めて食い違いが出る。**
> **表もそうだった —— 表は「どの設定で出したか」を書いていないと、写しですらない。**

**この ADR に載せる表は、以後 `λ` / 傾き / `K` / 初期値 / 尺度 を必ず添えること。**

## 訂正 5（2026-08-24 / **`single` と `K` の表を新しい規則で測り直す**）

**訂正 2〜4 で `1/n` 時代の数がすべて古びた。** §7 と §9 の表がどこからも参照されない状態に

**16h の組で `λ` を振っても結果がほとんど動かなかったのは、そもそも薄れが届いていないから。**

### 決定（提案）—— **`λ` と `K` は「決める」ものではなく「測って合わせる」もの**

**単一の既定値で両方の組に合わせることはできない。** 手順の側に落とす:

1. **記録専用モードで 60〜100 ターン回す**（[ADR-0026](0026-drift-by-accumulation.md) §決定1）
2. **軸ごとの「上げの割合」と「`0` の率」を出す**
3. **上げの割合が 85% を超える軸があれば、`λ` `K` を触る前に軸を replace する**（§16i）
4. **残った組に対して `λ × K` を振り、上の5条件で選ぶ**

**当面の既定値**（**16i の組で 5/5 になった点のうち、上げと下げが両方出て段数が中央のもの**）:

| | 値 |
|---|---|
| `λ` | **0.5** |
| `K` | **0.3** |

> **⚠ この値は当て直しの上でしか確かめていない。**
> **16h §5 のとおり、記録専用モードの当て直しは着地点を過大評価しうる**
> （`自信` は値が高いと上げの割合が 34 ポイント落ちる）。
> **`on` の腕で確かめるまで、この2つの数は「順位付けの結果」でしかない。**

### 4. ~~**⚠ 5/5 の点はすべて下向きである**~~ **解けた（16n）**

> **⚠ 2026-08-25 / 16n で解決。末尾の「16n」節を見ること。**
> **下向きは判定の癖ではなく、台本の弧だった。**
> **平坦な台本では上げの割合が 59%、弧の底では 43%。** 当て直すと**上2 下2 で釣り合う。**


| λ | K | 上げ | 下げ |
|---|---|---|---|
| 1 | 0.5 | 1 | **5** |
| 0.5 | 0.3 | 3 | **8** |
| 0 | 0.3 | 3 | **5** |

**349 ターンで、初期 5 から平均 4.6 へ。** **わずかに下がっている。**

**3500 ターンでどうなるかは、この測定では分からない。**
**16i の軸の組は上げの割合が 49% で、票がほぼ相殺する。**
**相殺したところに薄れが乗れば、下向きにしかならない。**

> **未解決。** **§決定3 の薄れは「値に比例して 0 へ引く」ので、長期には床へ向かう力である。**
> **上げ偏りが消えた組では、この力を相殺するものが無い。**
> **`λ = 0` にしても下げが多い**ので、薄れを切っても解けない。
> **判定そのものが下向きに寄っている可能性がある**（16i の台本は関係が壊れる弧である）。
> **平坦な台本で測るまで、切り分けられない。**

### この一件から残すもの

> **つまみの既定値は、軸の組を決めてからでないと意味を持たない。**
> **`λ` は「薄れの強さ」ではなく「`0` と採点された回に効く強さ」なので、**
> **`0` の率が違う軸の間では、同じ数が違う意味になる。**

## 実測（2026-08-25 / **16n ＝ 平坦な台本**）—— **16j §4 の宿題が解けた**

> **16i / 16l がわずかに下向きだったのは、あの台本が「行き違いと修復」の弧だったからである。**

`MAX_DRIFT_RESPONSE_TOKENS = 8192` に対して **1行 86** なので、

——**期待値は `DRIFT_LINE_TOKENS` から作らず、`StatAxis::MAX_CHARS` 文字の軸名で
最悪の応答を実際に組み立てて測る**（定数を動かす変異が両側で一緒に動くのを避けるため）。

#### **「最悪」に引用記号は含めない**

16e-c は「**31% の応答が依頼の引用記号を持ち込む**」を実測しているので、
実際に届く行は `> - {軸名} +1` になりうる。**それでも `86` には含めていない。**

**現実の軸名は 5〜10 文字**で、見込んでいる「20 文字すべてが 4 バイト文字」との差は
**桁で開いている**——記号の 2 バイトはその余裕に吸収される。
**枠が足りなくなるのは「20 文字すべてがアストラル面の文字の軸名」という病的な場合だけ**で、
そのときは記号の有無に関わらず切れる。**実装は変えない**（B-1-2 で判断）。

**見張り番の側も同じ形で抜けていた** ——
`the_response_limit_covers_the_worst_case_scorecard` は `Single` について
**「本数に追随しないこと」しか見ておらず**、`All` に課している
**「最悪の1行が収まること」を `Single` には一度も課していなかった。**

**決定: `single` の上限も `all` と同じ「最悪の1行」で出す**
（`drift_response_tokens` は**見込む行数だけを形で分け**、1行に見込む量は共有する）。
**`DRIFT_RESPONSE_TOKENS` は消えた。**

#### ⚠ **`DRIFT_RESPONSE_TOKENS <= EXTRACTION_RESPONSE_TOKENS / 4` を外した**

あの `const assert` は「**小さい上限を送っている**」という主張を、
**定数どうしの写しではない形で守るために置かれていた**（16b の「定数を倍にする変異が全緑」対策）。

**しかし `320 / 4 = 80 < 86` なので、正しい値にするとビルドが通らない。**
**比そのものが、上限を誤った 64 に縛り付けていた。**

**押さえは、抽出の都合ではなく答えの形から出す。**
抽出の上限は**あちらの実測**（応答の長さ / 行列の待ち時間）で動く数で、
**変容の答えが1行に収まるかどうかとは何の関係も無い。**

**代わりに置いたのは、比より狭い押さえ**
——`the_response_limit_covers_the_worst_case_scorecard` が
**最悪の応答を実際に組み立てて `estimate_tokens` で測り、上限がそれと一致すること**を要求する
（`>= needed` かつ `<= needed`）。**大きくする変異も小さくする変異も、どちらも赤になる。**
**定数から期待値を作っていない**ので、`DRIFT_LINE_TOKENS` を倍にする変異も半分にする変異も通らない。

### 2. **上端の理由と出どころがずれていた**（24 とまったく同じ構図）

旧: 上端は「**最悪の応答の2倍未満**」（＝応答の長さ）。
理由は「**喋り続けるモデルが本文生成の GPU を握り続ける**」（＝行列）と書いてあった。

**変容側には行列の実測が無い。** 抽出側の `QUEUE_SAFE_MAX_EXTRACTION_RESPONSE_TOKENS`(368) は
**抽出の応答の長さで測った数**で、**変容の応答はそれよりずっと短い**——**写さない。無い数を作らない。**

**決定: 上端は「答えの形」から素直に出す。**
受け付ける答えは `single` なら1行、`all` なら軸の本数ぶんの行しか無く、
**それ以上は `parse::drift` が丸ごと捨てる。** つまり
**最悪の答えより長い上限を送っても、採れる情報が1つも増えない。**

> **⚠ これは「行列の余裕が守られている」ではない。**
> **`relay::IDLE_BUDGET` との関係を自動で確かめている検査は、どこにも存在しない**
> （ADR-0021 §17 の同じ但し書きと、ロードマップ B-5）。
> **秒そのものは本番の定数にしない**——機の速さに依存する事実を `const assert` に埋めると、
> 別の機でビルドが通らなくなる。

### 3. **打ち切られた回は、行を選ばず丸ごと捨てる**

**抽出（ADR-0021 §17）とは意図的に違う判断である。**
あちらは**最後の1行だけ**を捨てればよかった——**前の行は完結している**から。

| 経路 | 打ち切られると何が起きていたか |
|---|---|
| **主経路** | 行末の符号が落ちて `split_delta` が失敗し、`malformed` で丸ごと捨てられる。**ログには出る**が、読んだ人は「モデルが形式を崩している」と診断して**プロンプトを直しに行く。打ち手が正反対。** |
| **副経路（静か）** | `parse_drift` は**2行以上を丸ごと捨てる**（`multiple_lines`）。**モデルが2行書いた回で、打ち切りが2行目を丸ごと消すと、本来捨てられるはずの回が「1行の正当な提案」として通る。** 捨てるはずのものが**適用される**向きなので、**ログ上は正常な `applied` に見える。** |

**副経路が理由である。** **何行あったのか分からない以上、残った1行を信じる根拠が無い。**
**`multiple_lines` と同じ扱いにする。**

- **新しい理由を1つ足した** —— `DriftDiscardReason::Truncated`（集計キー `truncated`）。
  **既存の理由に混ぜない**（`malformed` は「プロンプトを直す」、`missing_axis` は
  「全部書けと指示する」、`truncated` は「上限を上げる」——**打ち手が全部違う**）。
  `ALL` は 5 → 6。`all_lists_every_discard_reason_exactly_once` は `match` なので
  **足し忘れるとコンパイルが通らない。**
- **判定の入口は `Some(FinishReason::Length)` のときだけ。**
  `Stop` / `Other` / **申告なし**では捨てない
  ——倒すと、**停止理由を返さない上流に繋いだ瞬間、変容が丸ごと止まる。**
  しかもログには `truncated` と出るので、**「上限に張り付いている」としか読めない。**
- **申告が無い回は、それ自体を `warn` に残す**（`変容の応答に停止理由が付いていません`）。
- **`all` の 96 本以上のキャラクターで末尾が切れる回**（`MAX_DRIFT_RESPONSE_TOKENS` の doc）は、
  **これまで `missing_axis` に化けていた。** いまは `truncated` に出る。

#### 24 と**共有したもの** / **しなかったもの**

#### 決定点を `parse::drift` ではなく `server::drift` に置いた

**24 は「数えるのは `parse` の側」と決めた。** 理由は
**`server` が行を削ってから渡すと、捨てた数が `DiscardCounts` に乗らない**から。

**変容にはその危険が無い。** 変容は**1ターンに結末が1つ**で、
集計は `drift_outcome=` の**1つの値**であり、その値は `DriftDiscardReason::Truncated.label()`
——**抽出と同じ語彙の中に落ちる。**

そして**丸ごと捨てる規則は行の中身を一切見ない**ので、`parse` に渡す理由が無い
（`parse_drift` / `parse_drift_all` / `parse_drift_all_report` の**3つの入口すべてに引数を足す**
ことになり、**得られるものが1つも無い**）。

> **⚠ 1つだけ落としかけたもの: `drift_quotes`。**
> 引用記号を剥がした行数は「**採否に関係なく数える**」決まりの指標（16e-c）なので、
> **丸ごと捨てるついでに落とすと、是正の効き目を測る指標が打ち切りの回だけ静かに欠ける。**
> **分解そのものは通し、結末だけを差し替える形**にした
> （`DriftReading::truncated` は**構造体を作り直す**ので、
> **効果を運ぶ欄が増えた日にコンパイラが判断を求める**）。
> 見張り番は `a_truncated_scorecard_still_reports_the_quotes_it_stripped`。

### 見張り番

| 何を押さえるか | 見張り番 |
|---|---|
| **静かな方の経路**（届いたのが「1行の正当な提案」でも捨てる）＋ **対照**（切れていなければ通る） | `a_truncated_turn_is_dropped_whole_even_when_what_arrived_reads_as_one_valid_line` |
| **切られた位置が違う3つの形が、同じ1つの値へ落ちる**（**2行目が丸ごと消えた** / **2行目が途中で切れた** / **1行が途中で切れた**。＋印が無ければ `applied` / `multiple_lines` / `malformed` と**別の結末になる**という前提）。**「最後の1行だけ捨てる」を止めるのはこの1本** | `every_shape_of_a_truncated_response_lands_on_the_same_value` |
| `malformed` に混ぜない | `a_truncated_turn_is_not_counted_as_malformed` |
| **4つの申告すべてを通す**（`length` だけが捨てる） | `only_the_length_reason_throws_the_whole_drift_response_away` |
| **`all` でも丸ごと**（行が揃った回も、足りない回も） | `a_truncated_scorecard_is_dropped_whole_whether_or_not_a_line_is_missing` |
| 引用記号の数を落とさない | `a_truncated_scorecard_still_reports_the_quotes_it_stripped` |
| 申告が無い回がログに残り、**あった回には出ない**（**`WARN` も `session_id` も同じ行で見る**） | `a_drift_response_without_a_finish_reason_is_recorded` |
| 抽出の文言と混ざらない | `the_two_missing_finish_reason_messages_never_contain_each_other` |
| **上限が最悪の答えちょうど**（`single` も `all` も。**定数から期待値を作らない**） | `the_response_limit_covers_the_worst_case_scorecard` |
| **依頼が実際に運ぶ上限**が最悪の1行ちょうど | `the_drift_request_carries_a_small_response_limit` |
| **`all` で末尾が切れ始める本数**（95 本で一致・96 本で溢れる。**上の算術そのもの**） | `the_axis_count_where_the_worst_case_scorecard_stops_fitting`（B-1-2） |
| 新しい理由が `ALL` と綴りに載る | `domain` の `all_lists_every_discard_reason_exactly_once`（**`match` なのでコンパイルで止まる**） |

### 残っているもの

- **`truncated` は実データでまだ一度も出ていない。**
  **`single` の上限は 64 → 86 に上がった**ので、踏む確率は下がる向き。
  **`all` は変わっていない**（もともと1行 × 本数）。
- **行列の余裕は、変容側では一度も測っていない**（ロードマップ B-5 / ADR-0021 §17 と同じ穴）。
  **測るまで、上端に「秒」を根拠として書かないこと。**
