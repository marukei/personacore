## 3. この期間に分かった、運用の形

- **「本検査は最初から引き直す」**。第3巡で「線を満たした」形は、1段目を前の巡から使い回した当たりで、引き直すと消えた（ADR-0051 の表）。測定の担当には、固定した形を新しい引きで、設計に関わっていない読み手に読ませる。
- **検証用の会話は使えば減る。** 翼・弥生の2人しか DB に無く、δ4 の段階で使い切った（利用者の DB を写し直しても新しい会話は無かった）。
- **重い裏方は本文と窓を取り合う**（ADR-0052 M4: 統合 KV で合計が窓を超えた瞬間、本文も裏方も 500 で落ちる）。新しい裏方の仕事を足すときは「抽出と同じ上限・抽出の鎖で直列」に収めるのが一番安い。鎖を長くすると次の往復の抽出が `skipped=busy` で捨てられるので、補助の段は横取りできるようにする（A-12c-1）。
- **文書だけの変更でも、見張り番が読むファイルなら全テストを回す**（配布物の README の書き換えで `tests/distribution.rs` が赤になり、作業者に指摘された）。
- **途中経過は測定の NOTES から読める**（利用者の指摘）。長い測定は、報告を待たずに NOTES を覗いて次の手を考える。
- **機が落ちることがある**（2026-10-22 の夕方。測定の途中で落ち、NOTES の追記だけが残った）。測定・作業の担当には、途中経過をファイルに残させ、区切りで途中コミットさせる。API の接続が切れて作業者が止まったときも、未コミットの変更は残っていて再開できた。
- 機のメモリが詰まると rustc が os error 1455 で落ちる。`cargo test -j 4` で回した。
