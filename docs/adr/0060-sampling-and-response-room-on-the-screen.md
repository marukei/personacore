## 背景

上流プロファイルの面には、画面に欄の無い値が3つある。

| 鍵 | 書ける面 | 決めた ADR |
|---|---|---|
| `sampling.repeat_penalty` | `main` / `sub` | ADR-0058 |
| `sampling.reasoning_effort`（`"none"` / `"low"`） | `main` だけ | ADR-0059 §決定1 |
| `response_tokens` | `main` だけ | ADR-0059 §決定2 |

ADR-0058 §決定6 と ADR-0059 §決定5 は、画面に欄が無いあいだの守りとして、編集の依頼にこれらの欄を持たせず、保存はいまのファイルの同じ名前・同じ面の値を残すと決め、欄を足す作業を後へ回した。そのため今は次のようになっている。

- **見えない。** `GET /admin/upstream/profiles` の面はこれらの欄を載せない（`profile_editor.rs` が写さない）。どの値で送っているかは、起動時と切り替え時のログでしか分からない。
- **書けない。** 依頼の型（`WrittenFaceRequest`）は知らない欄を拒むので、`sampling` や `response_tokens` を送ると 400 になる。値を変えるには、利用者が `upstreams.json` を手で直すしかない。
- A-18（ADR-0059）で、長い会話で返答が縮まないように本文の面で思考を入れる道ができた。その道を使うにも手で書く必要がある。

## 決定

### 1. 読む口: 面に `sampling` と `response_tokens` を載せる

`GET /admin/upstream/profiles`（と、同じ形を返す保存の応答）の各面に、2つの欄を足す。応答の他の欄と同じく、**欄は必ず載せ、書いていなければ `null`** にする。

- `sampling`: 書いた鍵だけを持つオブジェクト（例 `{ "repeat_penalty": 1.0, "reasoning_effort": "low" }`）。既定値（`repeat_penalty` の 1.1、思考の `"none"`）で埋めない。**鍵を1つも持たない `"sampling": {}`（読み込みは通す）は `null` で返す**（書いていない面と送る値が同じなので、見え方も揃える）。
- `response_tokens`: 書いた整数。書いていなければ `null`。

### 2. 保存の口: 依頼に2つの任意の欄を足す。省けば今までどおり残す

依頼の型に `sampling` と `response_tokens` を任意の欄として足す。値の意味は依頼の `api_key`（ADR-0056）と同じ三値にする。

| 依頼の欄 | 保存の結果 |
|---|---|
| 書いていない | **いまのファイルの、同じ名前・同じ面の値を残す**（ADR-0058 §決定6 / ADR-0059 §決定5 のまま。手で書いた `{}` も、そのまま残す） |
| `null` | 消す（ファイルに鍵を書かない） |
| 値 | 置き換える |

- **省いたら残す規則を保つのは、API 1.8 までの使い手のためである。** 省いたら消す規則にすると、欄を知らない使い手が保存するたびに、手で書いた値が知らせずに消える。これは要求の意味を変えるので、ADR-0047 では大きい側になる。
- **`sampling` はオブジェクト丸ごとで置き換える**（鍵ごとに合成しない）。書ける鍵の集合は閉じていて（知らない鍵は読み込みが止める）、画面は書ける鍵を全部持つ（§決定4 の見張り番が固定する）。鍵ごとの三値（鍵ごとの `null`）は、依頼の形を二重にするわりに使い道が無い。外の使い手が片方だけ変えるときは、読んでから丸ごと送る（API のガイドに書く）。
- **空のオブジェクト `{}` を送ったら、`null` と同じに扱う**（ファイルに `"sampling": {}` を書かない）。書いていない面とバイト列を揃えるため。
- **線の上では、2つの欄の中身を型の付かない JSON の値で受け、判定は読み込みの関数に委ねる。** 型付きで受けると、知らない鍵や範囲の外が 400 `invalid_body` になり、どの欄の何が悪いかが画面に届かない（`context_tokens` を `u64` で受けて判定を委ねたのと同じ理由。ただし `context_tokens` と違い、負の数や文字列も 422 で返す）。400 になるのは、依頼の本文が JSON として読めないときと、ほかの欄の形が違うときだけ。
- **検証は読み込みと同じ規則で、保存の前に行う。** 止めたら保存せず 422 を返し、問題の `key` と `reason` は読み込みと同じ値を使う（新しい値を足さない）。

| 止める条件 | `key` | `reason` |
|---|---|---|
| `sampling` がオブジェクトでない・範囲の外・`reasoning_effort` の知らない値 | `sampling` | `sampling_unusable` |
| `sampling` の知らない鍵 | `sampling` | `unknown_sampling_key` |
| `sub` 面の `reasoning_effort` | `sampling` | `main_face_only` |
| `sub` 面の `response_tokens` | `response_tokens` | `main_face_only` |
| `response_tokens` が 0・整数でない・32 ビットの外 | `response_tokens` | `response_tokens_unusable` |
| `response_tokens` が同じ面に書いた `context_tokens` 以上 | **`context_tokens`** | `context_tokens_unusable` |

- **環境変数 `PERSONACORE_CONTEXT_TOKENS` の窓との組は、保存では止めない。** 保存の検証は読み込みと同じで、読み込みは環境変数を見ない（ADR-0042 §決定8）。面に窓を書かず、環境変数の窓が `response_tokens` 以下なら、ADR-0059 §決定2 のとおり、起動とそのプロファイルへの切り替えが止まる。画面はこの組を保存の前に言わない（画面は環境変数を知らない）。止まったときの理由は切り替えの失敗として今までどおり画面に出る。

### 3. 画面: 面ごとに欄を出す。本文の面だけの値は本文の面にだけ出す

- **一覧**では、面ごとに書いた値を見せる。書いていなければ「書いていない」と言い、送る値（既定の 1.1・思考を切る・1024）を、書いた値と区別できる形（「既定」の印）で添える。一覧の「書いていない鍵を決まる値で埋めない」原則（`web/src/lib/upstreamProfiles.ts` の一覧の doc）は、値の欄を埋めないという意味で保ち、既定の印はその例外として doc に書く。
- **下書き**の欄:

| 欄 | `main` 面 | `sub` 面 | 置き場所（起こす面・繋ぐ面とも） | 空・既定のとき |
|---|---|---|---|---|
| 思考（`reasoning_effort`） | 出す（「切る（既定）」「入れる（`low`）」の2択） | 出さない | すぐ出す | 「切る」なら書かない |
| 返答の上限（`response_tokens`） | 出す | 出さない | すぐ出す | 空なら書かない（送る値は 1024） |
| 繰り返しの罰（`repeat_penalty`） | 出す | 出す | 詳細に畳む | 空なら書かない（送る値は 1.1） |

  - 思考と返答の上限は、長い会話で返答が縮まないように使う値（ADR-0059）で、変える人が多いと見て、すぐ出す。繰り返しの罰は上流ごとの微調整なので、詳細に畳む。
  - 思考の「切る」は `"none"` を書くのではなく鍵を書かない形にする。送る値は同じ（ADR-0059 §決定1）。ファイルに手で `"none"` と書いていた面は、画面から保存すると鍵が消えるが、送る値は変わらない。
- **画面は一覧で読んだ値をそのまま下書きに入れ、保存では2つの欄を必ず送る**（省かない）。空の欄は `null` で送る（省くと「残す」に当たり、空にしたつもりの値が知らせずに残る）。`sampling` は、思考と繰り返しの罰の欄が両方とも空なら `null`、片方でも書いてあれば、書いてある鍵だけのオブジェクトにする。`sub` 面の依頼には `reasoning_effort` と `response_tokens` を載せない。
- **画面の事前の検査は便宜で、権威はサーバの 422** にする。画面は保存の前に、`repeat_penalty` の範囲（0.5〜2.0）と、`response_tokens` が正の整数で、同じ面に書いた `context_tokens` より小さいことを、それぞれの欄で言う。**同じ面に `context_tokens` を書いていなければ、窓との比較はしない**（照会した窓との組は実行時に既定へ戻して `warn` を出す。ADR-0059 §決定2 と追記）。
- **サーバの 422 は `key` のとおりの欄に結びつける。** `key: "context_tokens"`（返答の上限が窓以上）は窓の欄に出る。起こす面では窓の欄が詳細に畳まれているが、理由を名指された欄が詳細の中にあれば詳細を開く今の振る舞い（作業単位 D-19）で見える。`key: "sampling"` は、`reason` だけでは思考と繰り返しの罰のどちらかを区別できないので、2つの欄の組（サンプリングの欄の見出し）に出す。
- **範囲は推奨ではなく柵だと、欄の隣で言う。** 0.5〜2.0 は壊れた値と打ち損じを止める柵で、測って決めた範囲ではない（`llm::REPEAT_PENALTY_MIN` の doc）。
- **思考を入れて返答の上限が空（または 1024 以下）なら、欄の隣で言う**: 「思考は返答の上限の中で書かれる。足りないと本文が切れたり空になったりする」。**数（2048 など）は画面に出さず、値も自動で入れない。** 測った思考の量（最大で 500〜900 トークン前後。ADR-0059 の背景）はこの機の1つのモデルの値で、上流によって変わる（ADR-0033 / ADR-0036）。上流ごとの候補を示すのは A-19（marukei/personacore#37）の役目にする。
- **保存しただけでは、動いている上流には効かない。** 今の画面の案内（保存の後は、同じ名前へ切り替え直すと効く）に従い、この欄にも同じ案内を出す。切り替え直すと、書き直した `sampling` / `response_tokens` が送る値と予算に入る見込みである（`response_tokens` を消せば余白は 1024 に戻る）。切り替えは名前ではなく面ごとの値（`switch.rs` の `Target`。`sampling` と本文の面の値を含む）を比べ、名前が同じでも値が違えば面を差し替えるため。鍵の案内（同じ名前へ切り替え直すと効く）と同じ仕組みに乗る。**起こす面で値だけが違うとき、起こした子（推論サーバの子プロセス）を起こし直さないこと**も、実装で確かめる（§決定6 の腕9）。

### 4. 例外の節から外し、画面の欄と読み込みの鍵を見張り番で揃える

- `FACE_KEYS` の doc の主規則（「画面の編集がその欄を持つまでは足さないこと」）の例外から、`sampling` と `response_tokens` を外す。例外として残るのは `api_key` と `allow_key_over_plain_http` だけになる。
- 画面の写し（`web/src/lib/upstreamProfiles.ts`）では、`EDITABLE_FACE_KEYS` / `EditableFaceKey` に2つを入れ、保存の 422 が `key: "sampling"` / `"response_tokens"` を欄に結びつけられるようにする。
- **画面が持つサンプリングの欄の鍵の集合と、読み込みが受け付ける `sampling` の鍵の集合が一致することを、見張り番で固定する。** `sampling` は丸ごと置き換えるので、読み込みに鍵を足して画面の欄を後回しにすると、画面からの保存が手で書いたその鍵を知らせずに消す。**`sampling` に鍵を足す作業単位は画面の欄も同じ作業単位で足す**（この見張り番が赤になって止める）。

### 5. API の版は `1.9`（小さい側）

応答の欄の追加と、要求の任意の欄の追加だけなので、ADR-0047 の表の小さい側に当たる。省いた依頼の意味（残す）は変えない。保存の 422 が `key` に `sampling` / `response_tokens` を名指すようになる（値は 1.7・1.8 で `enum` に入っている）。

### 6. 見張り番

少なくとも次を観測する。フィクスチャの値は既定と同じ値（1.1・1024・`"none"`）を避け、`main` と `sub` で違う値にする。

| 腕 | 観測すること |
|---|---|
| 1 | 依頼が欄を省くと、手で書いた `sampling` / `response_tokens`（と `{}`）が残る |
| 2 | `null` で消え、消した面は書いていない面と1バイトも違わない。`sampling` と `response_tokens` を両方書いた面で、片方だけ `null` にするともう片方が残る |
| 3 | 値で丸ごと置き換わる（いまのファイル `{ repeat_penalty, reasoning_effort }` に依頼 `{ repeat_penalty }` を送ると、`reasoning_effort` が残らない） |
| 4 | `sampling` を書いてある面に `{}` を送ると消え、`null` を送ったときとバイト列が一致する |
| 5 | §決定2 の表の各行が、保存されずに（ファイルが1バイトも変わらずに）422 になり、`key` と `reason` が表のとおり。`response_tokens == context_tokens` の境界を含む |
| 6 | 読む口が書いた値を返し、書いていない面と `{}` の面は `null` を返す。3件以上のプロファイルで、真ん中の1件だけに書いた値が、その1件にだけ出る |
| 7 | 画面: 一覧の表示と既定の印、下書き → 依頼の写像（空の欄は省かず `null`、思考の「切る」で `reasoning_effort` だけが落ちて `repeat_penalty` が残る、`sub` 面の依頼に本文の面だけの欄が載らない）、422 の `key` が欄に結びつく（`sub` 面の失敗が `main` の欄に出ない、`context_tokens` の 422 で詳細が開く）、思考を入れて上限が空のときの案内 |
| 8 | 画面のサンプリングの欄の鍵の集合が、読み込みの `sampling` の鍵の集合と一致する（§決定4） |
| 9 | 保存の後に同じ名前へ切り替え直すと、書き直した値が送る値と予算に入る。起こす面では、子を起こし直さない |

**既存の見張り番の意味が変わる。** `tests/upstream_profile_editor.rs` の `a_hand_written_sampling_survives_a_save_from_the_screen` と `a_hand_written_response_room_survives_a_save_from_the_screen` は、依頼に欄を載せると 400 になることも見ている。この ADR でその腕は 200（置き換え）に変わるので、400 の腕は腕3・腕5に置き換え、「省いたら残す」の腕は腕1として意味を変えずに残す（司令塔の決定）。

### 7. 採用したときに直す記述

- ADR-0058 §決定6 の「この作業単位では依頼の型に `sampling` を足さない」「画面の写しでは `EDITABLE_FACE_KEYS` から除く」「画面で値を表示・編集できるようにする作業は、別の作業単位で後から行う」と、ADR-0059 §決定5 の「依頼の型には足さない」「`EDITABLE_FACE_KEYS` からは除く」に、取り消し線とこの ADR への誘導を付ける。「送らなければ残す」と、`endpoint` / `model` が変わっても落とさない規則は生きているので残す。
- コードの doc（`FACE_KEYS` の例外の節、依頼の型の「省いた鍵と `null` は同じ意味」の例外、`FaceEdit::to_value` の doc、`openapi.rs` の版の注記）と、API のガイドは、実装の作業単位で直す。

### 8. この ADR で決めないこと

- 本文の温度（marukei/personacore#32、ADR-0058 §決定7）。鍵を足すときは §決定3 の表に行を足し、§決定4 の見張り番に従う。
- 実行時に既定へ戻った返答の上限（照会した窓が足りない・分からないとき。ADR-0059 の追記）を画面に出すか。いまはログだけで言う。
- プロファイルの削除と名前の変更（marukei/personacore#35 / D-20）。同じ画面の作業なので、リリースはまとめる。

## 理由

### 却下した選択肢

- **欄を足したら、省いた依頼は「書かない」（消す）にする**（`context_tokens` と同じ扱い）: 画面の欄と依頼の欄の扱いは揃うが、API 1.8 までの使い手が保存するたびに、手で書いた値が知らせずに消える。§決定2 のとおり大きい側の変更で、得るものに見合わない。
- **`sampling` を鍵ごとの三値にする**: 書ける鍵は2つで、画面は両方を持つ。将来の鍵で画面が遅れる危険は、§決定4 の見張り番で止める。外の使い手は読んでから丸ごと送れば足りる。
- **画面が知らない鍵を、読んだ値から写して送る**: 画面と exe は同梱なので、知らない鍵がある時点で §決定4 の決まりが破られている。写す仕組みを持つより、決まりを見張り番で守るほうが単純。
- **思考を3択（書かない / `"none"` / `"low"`）にする**: 送る値は「書かない」と `"none"` で同じなので、利用者に区別させる意味が無い。
- **思考を入れたら返答の上限に 2048 を自動で入れる・推奨として数を出す**: その数はこの機の1つのモデルで測ったもので、上流が変われば外れる。外れたときに画面が言った数を信じた利用者が、切れた本文の原因に辿り着けない。候補は A-19 で上流ごとに測って示す。
- **環境変数の窓との組も保存で止める**: 保存の検証は読み込みと同じ規則にする（ADR-0042 §決定8）。環境変数は起動ごとに変わりうるので、保存の時点で止めても、起動の時点の組を保証しない。

## 結果

### 得られるもの

- 思考を入れる・返答の上限を上げる・繰り返しの罰を変える、が画面からできる（効かせるには切り替え直す）。
- どの値を書いたかが画面で見える。

### 諦めるもの・新しく負うもの

- 画面から保存すると、手で書いた `"reasoning_effort": "none"` は鍵ごと消える（送る値は同じ）。
- 依頼の欄が2つ増え、三値の規則を持つ欄が `api_key` と合わせて3つになる。
- `sampling` に鍵を足す作業単位は画面の欄も同時に足す必要がある。

### この ADR が答えていないこと

- 実行時に既定へ戻った返答の上限を、画面でどう見せるか（§決定8）。
