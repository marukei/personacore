# ADR-0031: FE は Svelte + Vite + TypeScript で書き、axum が配る

- 状態: **採用**
- 日付: 2026-08-26
- 関連: [ADR-0001](0001-openai-compatible-boundary.md)（OpenAI 互換の境界）/
  [ADR-0008](0008-admin-api.md)（管理は `/admin/` の HTTP API）/
  [ADR-0022](0022-repairing-memories-without-deleting.md)（記憶の修復の導線）/
  [ADR-0024](0024-stat-drift.md) §9（変容は本文に出さない）

## 背景

**利用者が実際に使う導線が、まだ何も無い。** `curl` と OpenAI 互換クライアントだけ。

**そのせいで、欠陥の見つかり方が「測定」に偏っている。**
実際に使えば出るはずの欠陥を、**台本を書いて再現する形でしか拾えていない。**

**特に効くのが2つ:**

- **記憶の一覧と修復**（[ADR-0022](0022-repairing-memories-without-deleting.md)）——
  **API はある。画面が無いだけ。**
- **性格値と変容の可視化** —— **変容は本文に出さない決定**（[ADR-0024](0024-stat-drift.md) §9）なので、
  **画面が無いと、動いたことがログを読まないと分からない。**

## 決定

### 1. **Svelte 5 + Vite 8 + TypeScript 7、パッケージマネージャは pnpm**

**版は 2026-08-26 に npm レジストリから実際に引いた値**
（`svelte 5.56.10` / `vite 8.2.2` / `typescript 7.0.2` / `react 19.2.8` / `vue 3.5.41` / `astro 7.2.7`）。

### 3. **axum が配る。別プロセスにしない**

**絶対制約「サーバは `127.0.0.1` にのみバインドする」がそのまま効く。**
同一オリジンにすれば **CORS も認証境界も増えない。**
開発時のみ Vite の dev server を使い、**API は proxy で同一オリジンに見せる。**

### 4. **⚠ UI のフォールバックが API の 404 を飲み込まないこと**

**`/v1/*` と `/admin/*` の未知パスは、いまも OpenAI 形式のエラーを返さなければならない**
（見張り番は `unknown_route_returns_an_openai_shaped_error`）。
**UI へ落ちるのは、その2つに属さないパスだけ。**

**⚠ 判定は生パスに対して行わない**（2026-08-26 に追記 / D-0 のレビュー）。
**`//v1/…` / `/./v1/…` / `/%76%31/…` は、`starts_with` で見ると全部 UI へ落ちる。**
**`//v1/…` は base URL が `/` で終わるクライアントが普通に作る形**で、
**`POST //v1/chat/completions` が本文の無い 405 になる**（`ServeDir` は GET / HEAD しか受けない）。
**分類の前に正規化すること**——条件と、`..` をどちらへ寄せたかは
**`src/server/web.rs` のモジュール doc に書いてある。**

**SPA フォールバック（`index.html` を常に返す）は入れていない。**
**入れるときは `src/server/web.rs` のモジュール doc の条件を先に読むこと**
——**いま「API のエラー形」と「UI 側の 404」を区別できているのは、入れていないから**であり、
入れると**フォールバックの順序を入れ替えた変異が「200 と `index.html`」で緑を通る。**

#### **型検査は `svelte-check --tsgo`。素の `tsc` ではない**

**⚠ 2026-08-26 に訂正**（D-0 のレビュー）。当初ここには
「`tsc` と `vite build` を完了条件にする。**追加のツールチェーンは入れない**」と書いたが、
**実際に入れたのは `svelte-check` ＋ TypeScript 2つ**である。**決定を実態に合わせる。**

- **`.svelte` を検査できるのが `svelte-check` だけ**だから入れた。
  素の `tsc` は `.svelte` を読まないので、**画面のコードが1行も検査されない。**
  **画面がほぼ全部 `.svelte`** なので、それでは「型検査を完了条件にする」が空文になる。
- **TypeScript が2つ入る**（`typescript: 6.0.3` ＋ `@typescript/native: npm:typescript@7.0.2`）。
  **`svelte-check` 4.7.6 は TS 7 単独では起動を拒否**し、
  **TS 6 と TS 7 の両方 ＋ `--tsgo`** を要求する（`svelte-check` 自身がそう言う）。
  **実際に検査しているのは 7.0.2 の方。**
  **⚠ 「6.0.3 に落としたのでは」「片方が冗長では」と読んで消さないこと。**

#### ⚠ **`svelte-check` は、型検査器を起動できなかったときに `exit 0` を返す**

**この決定の唯一の守りが、黙って空振りしうる**という意味なので、実測を残す。
**原因は上流**（`svelte-check` 4.7.6 が子プロセスの終了コードを見ていない）。

**手当て**: `pnpm check` の前に**型検査器そのものを起動して版番号を出す。**

```json
"check": "node node_modules/@typescript/native/bin/tsc --version && svelte-check --tsconfig ./tsconfig.json --tsgo --fail-on-warnings"
```

**4通りを、直す前と直した後で測った**（2026-08-26 / D-0-2）:

| 仕込み | 旧 `check` の exit | 新 `check` の exit |
|---|---|---|
| 正常（型エラー無し） | 0 | **0**（`Version 7.0.2` が出る） |
| 正常 ＋ 型エラー | 1（`1 ERRORS`） | **1**（同じ） |
| **TS 7 のネイティブ exe を退避** ＋ 型エラー | **0**（`COMPLETED 2 FILES 0 ERRORS`） | **1**（`Executable not found: …tsc.exe`） |
| `@typescript/native` ごと不在 | **0**（`svelte-check failed` ＋ スタックトレース） | **1**（`Cannot find module …`） |

**黙って空振りする2行だけが 0 → 1 に変わり、正しく動く2行は変わらない。**
**版番号が毎回出るので、「TS 6 で検査しているのでは」という誤読も同時に消える。**

> **これは「Finished in 0.4s は直っていない、何もしていない」と同じ罠**
> （`~/.claude/CLAUDE.md` / CLAUDE.md）。**FE 側にも作らない。**

> ### ⚠ **後ろの2行は、レビューが「対象外にすら挙がっていない」と指摘して足したもの**
>
> **どちらも実測で素通りしていた**（各 520 全緑）——
> **`mod.rs` の `post(` → `get(`／`chat.ts` の `"POST"` → `"GET"`／
> `chat.ts` の `content-type` を `text/plain` へ。**
>
> **`content-type` を「写しではない」と書いていたのが誤り。**
> **`accept` は本当にサーバが1行も読まない**（`src/server/` に参照 0 件）**が、
> その理由は `content-type` には一切かかっていない** ——
> `chat.rs` は `Json<ChatCompletionRequest>` で受けるので
> **axum の抽出器が `application/json` を要求し、外すと `JsonRejection` →
> `ApiError::invalid_body()` でその回が丸ごと 400 になる。**
> **1つの理由を2つの欄に効くように書いた形**で、**CLAUDE.md の「doc が守っていない場所に
> 守ったと書く」の変種。行を割って両方とも見張る側へ移した。**

> ### 突き合わせ方が B-18 と違う（**TypeScript 側を読まない**）
>
> **Rust 側はソースを読み、TypeScript 側は本番の関数を実際に走らせる。**
> `sendMessage` に `fetch` の身代わりを噛ませ、**送った本体を覗き、
> Rust が置いた場所へ植えた目印が FE の手元に出てくるか**を見る。
> **`readFrame` は export されていない**ので、これ以外に「どの鍵から読んでいるか」を
> 見る手段が無い（**export を増やすのは本番の入口を観測対象から外す形** / CLAUDE.md）。
>
> ### **要求は「集合が一致」ではなく「送る／送らない」の分類**
>
> `chat.rs` は **`deny_unknown_fields` を付けない**（ADR-0001 / 実クライアントをそのまま使う）ので、
> **`temperature` / `max_tokens` を送らないのは正しい。**
> だから**一致ではなく、送らない欄を名指しして「全部省略可であること」まで見る** ——
> **Rust 側に必須の欄が増えた日に赤くなる**のがこの形の効き目。
>
> ### ⚠ **省略可否は「波括弧の深さ」までしか見ない**（レビューが実測した限界）
>
> `Relay::relay` の `role` は `if !self.started {` の中で載るので**省略可**と読む。
> **`if true {` にする変異は、この見張り番では緑**——**条件が実際に条件かを見ていない。**
> **走査を条件まで読む形には広げない**。理由は**権威が Rust 側に実在するから**で、
> `server::relay::tests::a_relayed_chunk_is_an_openai_compatible_chunk` が
> **厳密な JSON を丸ごと固定していて赤くなる**（レビューが実測 / `24 passed; 1 failed`）。
>
> **⚠ その Rust 側の権威と、こちらの「1つ残らず分類してある」は重複ではない。**
> **あちらは「Rust が何を出すか」しか言わず、
> こちらは「FE がどれを読み、どれを読まないか」しか言わない。**
> **片方を消すと、その分類は誰も守らなくなる。**

## 理由

### なぜ Svelte か

- **5画面ぶんのコード量が最小。** 会話のストリーミング・キャラ編集・記憶の一覧と修復・
  性格値の可視化・観測。**ほぼ全部が対話で、静的な内容がほとんど無い。**
- **実行時ランタイムがほぼ無い**ので、**上記5（型とビルドだけで守る）の下で
  守れる割合がいちばん高い。**
- SSE とストアの相性が良い。

### 却下した選択肢

- **Astro** —— **設計の中心が「静的な内容が主で、対話は島だけ」。**
  **この5画面は島がページのほぼ全部**になるので、**Astro の利点をどれも使わない。**
  **決め手は、Astro が対話部分の実行時を自前で持っていないこと** ——
  島の中身は React / Svelte / Vue のどれかを持ち込むので、
  **「Astro の代わりに3つ」ではなく「Astro ＋ 3つのどれか」**になる。
  設定面が1層増えて、その層の利点は使わない。
  **加えて Astro の SSR は Node/edge のランタイムを前提**にしていて、こちらは axum。
  静的出力モードで使うことになり、さらに機能が余る。
  **Astro が正解なのは、ドキュメントや紹介ページが主で対話が少しだけ、という形のとき。**
- **React** —— **作例が最多で、実装エージェントが書く前提だと実利がある。**
  却下の理由は**5画面には反面ボイラープレートが過剰**なことと、
  **ストリーミングの状態管理を自前で書くことになる**こと。**筋は通っていたので、記録に残す。**
- **Vue** —— Svelte と React の中間。**フォーム中心の画面とは相性が良い。**
  **決め手が無かったので、コード量の最小を採った。**
- **ビルド無し（素の HTML + ES モジュール）** ——
  **`node_modules` もビルド成果物も無いので「FE を再ビルドし忘れた」という失敗モードが
  原理的に存在しない**のは、このリポジトリの失敗の歴史から見て本当に魅力だった。
  **却下の理由は、型検査を完了条件にすると決めたこと。** 素の HTML では型が無い。
  **可視化の画面が手書きで重くなる**のもある。
- **別プロセスで配る** —— **`127.0.0.1` のみという絶対制約の下で、
  オリジンを2つにする理由が無い。** CORS の設定が増えるだけ。
- **Leptos / Dioxus（Rust の WASM）** —— ツールチェーンが1つで済むのは魅力だが、
  **wasm のビルドが増え、賭けが大きい。** 5画面に見合わない。

## 結果

### 得られるもの

- **記憶の修復と、変容の可視化に、初めて導線ができる。** どちらも API は既にある。
- **実際に使って欠陥を見つける経路**ができる。いまは台本を書かないと再現できない。

### 諦めたもの / 前提

- **FE は Rust 側と同じ水準では守らない**（上記5）。**これは意識的な選択である。**
- **API の型は写しなので、Rust 側を変えると黙って古びる**（上記6）。
- **`web/dist` を配る形なので、ビルドし忘れると UI が古いまま出る。**
  **起動ログに配り先のパスと、それが存在するかを必ず出すこと。**
  **「Finished in 0.4s は直っていない」と同じ罠**を、FE 側に作らないため。
