# ADR-0041: 配布物は OS ごとに実行ファイル1本。画面は埋め込み、DB は OS の作法の場所

- 状態: **採用**（2026-09-18 / 利用者が「そうなるだろうなという感じで落ち着いた。進めよう」と決めた）
- 日付: 2026-09-18
- 関連: [ADR-0031](0031-front-end-stack.md)（**FE のビルド成果物 `web/dist` を axum が配る、と決めた回。この ADR はその配り方を変える**）/
  [ADR-0036](0036-the-range-of-machines-is-a-constraint.md)（**動く環境の幅** —— 「この機でしか動かない」を制約違反と読む側）/
  作業単位 `F-1`（`start.ps1`）/ `F-9`（上流プロファイル）/ **`F-4`（この ADR が開く）**

---

## 背景 —— **開発フォルダを動かしたら、その場で起動できなくなった**

2026-09-18、利用者が **`<repo>` をそのまま Desktop へ複製して `start.ps1` を叩いた。**
**FE のビルドで落ちた** —— `Cannot find module '...\web\node_modules\vite\bin\vite.js'`。

**原因は2つあり、どちらも `git status` には出ない**（[04-environment.md](../04-environment.md) の「改名すると黙って壊れるもの」）:

| 何 | なぜ動かない |
|---|---|
| **`web/node_modules`** | pnpm のリンクは Windows では**絶対パスのジャンクション**。複製先では 305 本すべてが元の場所を指す |
| **`start.ps1` そのもの** | **毎回 `pnpm run build` と `cargo run` を回す**。つまり動かす機に Rust と pnpm の環境が要る |

**⚠ つまり `start.ps1` は開発用の起動器であって、配布の形ではなかった。**
**同じ日の朝、改名で同じ穴を踏んで直したばかりだった**（`<親>\ai-llm-chat` → `<repo>`。
ジャンクション 305 本と `target/` 38 GiB）。**置き場所に依存するものが実行ファイルの外にある限り、動かすたびに壊れる。**

**利用者の判断:**
- **マルチプラットフォーム化はいったん置き、Windows 用を先に作る。** Linux は低いが **Mac は 0 ではない。**
- **判断軸は「今後、どちらの形を確立しておくと配布しやすいか」。**
- **DB は OS の作法の場所でよい。ただし開発中でスキーマが変わりうるので、初期化の方法を持つこと。**

**ロードマップの `F-4` は「先回りしない。痛みが残っていたら測って決める」と書いてあった。痛みが出た。**

## 決定

### 1. **配布物は OS ごとに実行ファイル1本**

**`personacore.exe`（Windows）／`personacore`（Mac）だけを配る。** 横にフォルダを要求しない。
**動かすのに Rust も pnpm も要らない。** 置き場所の規約を持たない（どこへ置いても、どこから叩いても同じ）。

**フォルダ配布（exe ＋ `web/` ＋ 起動スクリプト）を採らない理由:**
**起動スクリプトが OS ごとに要る。** いまの `start.ps1` は PowerShell で Mac には標準で無い。
**フォルダの形を採ると、`F-9` の上流プロファイルや llama 起動の論理を OS ごとに写すことになる。**
**外に残すものを DB だけにすれば、写すものが無くなる。**

### 2. **画面（`web/dist`）はコンパイル時に実行ファイルへ埋め込む**

- **埋め込む元は `web/dist` の1箇所**（`vite.config.ts` の `outDir` と同じ綴り。
  見張り番 `the_default_web_dir_is_where_vite_actually_builds` は**埋め込み元の綴り**を見る形に移す）。
- **debug でも release でも同じく埋め込む。** 「debug はディスクから読む」種類の切り替えを持たない
  （**この機の既定とコードが偶然同じ、という形の穴を作らない**。CLAUDE.md §4）。
- **⚠ `web/dist` が無くても素の `cargo build` は通ること。** `build.rs` が空の `web/dist` を作ってから埋め込む。
  **画面が空のまま起動したら、起動行がそう言う**（いまの `web_dir_exists=false` の WARN と同じ役目）。
  **`cargo test` は FE をビルドしない**ので、この形でないと `cargo build` が門でなくなる。
- **`PERSONACORE_WEB_DIR` は残す。** 設定されていれば**ディスクから配る**（いまの `ServeDir` の経路）。
  **用途は開発**（`vite build --watch` の成果物を exe を組み直さずに見る）。**未設定なら埋め込みを配る。**
- **配り方の規則は変えない** —— `/v1` / `/admin` の未知パスは OpenAI 形式の 404 のまま、
  SPA のフォールバックは入れない、`..` は API と読まない、percent デコードは1回だけ
  （すべて [`src/server/web.rs`](../../src/server/web.rs) の doc と `tests/server_web_ui.rs` が固定している）。
  **埋め込み側もディスク側も、同じ判定を通ること。**
- **Content-Type は拡張子から引く。** 埋め込みには `ServeDir` が居ないので、ここは自前になる。
  **引けない拡張子は `application/octet-stream`**（止めない。画面のビルドが新しい種類のファイルを出したとき、
  配布が壊れるより「表示が変」のほうが原因に近い）。

**⚠ 埋め込みの中身はコンパイル時に決まるので、テストからは植えられない。**
**埋め込みの探索は「名前 → バイト列」の表を引数で受ける形にし、植えた表で判定を測る**
（`15b` の作法。実ファイルの表と植えた表の両方を同じ本体に通す）。

### 3. **DB の既定は OS の作法の場所**

`PERSONACORE_DB_PATH` が未設定のとき:

| OS | 場所 |
|---|---|
| Windows | `%LOCALAPPDATA%\personacore\personacore.sqlite` |
| Mac | `~/Library/Application Support/personacore/personacore.sqlite` |
| Linux | `$XDG_DATA_HOME/personacore/personacore.sqlite`（無ければ `~/.local/share/...`） |

- **ディレクトリは起動時に作る。**
- **場所が決められない環境（ホームが無い等）は起動を止め、`PERSONACORE_DB_PATH` を設定するよう言う。**
  黙ってカレントディレクトリへ落とさない（**今日の事故の形 —— 置き場所に依存するものが外にある**）。
- **⚠ 今の既定 `personacore.sqlite`（カレントディレクトリ直下）は捨てる。**
  ロードマップが「既に踏める地雷」と呼んでいたもの（リポジトリ直下に `0004` までの古い空 DB がある）が、これで消える。
- **`start.ps1` は影響を受けない** —— 自分で `PERSONACORE_DB_PATH` を立てる（リポジトリ直下 `data/`）。
  **開発の DB と遊びの DB が別の場所になる。** これは意図した形。

**`%LOCALAPPDATA%` を採り、exe の隣の `data/` を採らなかった理由:**
利用者の判断。**フォルダごと持ち歩く用途より、置き場所を変えても DB が1つである方を採った。**
**「複製して遊ぶ」は `PERSONACORE_DB_PATH` で表現できる。**

### 4. **初期化は「消す」ではなく「退避する」 —— `--fresh`**

開発中はスキーマが変わる。**ただしこの家の規約（適用済みのマイグレーション SQL は編集しない）が守られている限り、
変更は常に前向きの追加で、起動時に自動で当たる。普通は初期化は要らない。**

要るのは2つの場合 —— **まっさらから遊び直したいとき**と、**規約が破れてチェックサム不一致で起動できないとき。**
どちらも **`personacore --fresh`**:

- DB を開く前に、**`personacore.sqlite` を `personacore.sqlite.bak-<YYYYMMDDTHHMMSS>` へ改名する。**
  `-wal` / `-shm` が在れば**同じ接尾辞で一緒に**改名する（片方だけ残すと、次に開いたとき古い WAL が新しい DB に当たる）。
- **改名した先の名前を起動ログに出す。** 手で戻せる。
- **ファイルが無ければ何もしない**（初回に `--fresh` を付けても失敗しない）。
- **削除する経路は作らない。** `memory` の行を DELETE しないのと同じ向き。

**引数の解析は `--fresh` 1つだけ。** 知らない引数は起動を止める（綴り違いを黙って無視しない）。
**依存（clap 等）は足さない。** 1つの真偽値に引数解析の依存は釣り合わない。**増えたら、そのときに決める。**

### 5. **作り方は `scripts/package.ps1` の1コマンド**

`pnpm run build` → `cargo build --release` → `dist/personacore.exe` へ複製。
**⚠ 順番が本質** —— 埋め込みはコンパイル時なので、**FE を先にビルドしないと古い（または空の）画面が入る。**
**Mac も同じ2コマンドで済む**（スクリプトの写しは要る。OS ごとの分岐は `F-4b` で decide）。

### 6. **上流の指定は当面、環境変数のまま**（`F-4b` へ）

`PERSONACORE_LLM_ENDPOINT` / `PERSONACORE_SUB_LLM_ENDPOINT` / `PERSONACORE_MODEL` / `PERSONACORE_SUB_MODEL` は変えない。
**`F-9` の上流プロファイル（`upstreams.json` の読み ＋ llama の起動）は `start.ps1` の中に在る。**
**exe 側へ移すのは `F-4b`。** そこで初めて Mac でも同じ操作になる。

## 却下した選択肢

| 案 | なぜ採らない |
|---|---|
| **フォルダ配布**（exe ＋ `web/` ＋ 起動スクリプト） | 決定1。OS ごとに起動スクリプトが要り、置き場所の規約が残る |
| **debug はディスク、release は埋め込み** | 「この機の既定とコードが同じ」形の穴。CLAUDE.md が3回踏んだ族 |
| **`web/dist` が無ければビルドを止める** | `cargo test` は FE をビルドしない。素の `cargo build` が門でなくなる |
| **exe の隣の `data/`** | 利用者の判断（決定3）。複製して遊ぶ用途は `PERSONACORE_DB_PATH` で表現できる |
| **`--reset` で DB を削除** | 削除の経路を作らない。退避なら戻せる |
| **既定が決められなければカレントディレクトリへ落とす** | 今日の事故と同じ形（置き場所依存が外に出る）。止めて言う |
| **clap を入れる** | 真偽値1つに引数解析の依存は釣り合わない |
| **`start.ps1` に `-Exe` を足して cargo を飛ばす** | 開発用の起動器を配布物に寄せる向き。配布物は exe 単体で立つべき |

## 結果

- **exe を Desktop に置いて叩けば動く。** Rust も pnpm も要らない。
- **`start.ps1` は開発用のまま残る**（cargo と pnpm を要求する。それでよい）。
- **失うもの: 何も無い。** `PERSONACORE_WEB_DIR` でディスク配信も残る。
- **⚠ 埋め込みの分、exe は画面のぶんだけ大きくなる**（`web/dist` は 140 kB 程度。無視できる）。
- **⚠ `cargo build` が `web/dist` の内容に依存するようになる。** FE を直したら exe を組み直すこと
  （`package.ps1` はその順で回す。開発中に「画面が古い」と見えたら、まずこれ）。

## 見張り番（`F-4a` が置くもの）

- **埋め込みの探索を植えた表で測る**（`/v1` / `/admin` を飲み込まない／`..` を辿らない／Content-Type の表）。
- **`PERSONACORE_WEB_DIR` 有りはディスク、無しは埋め込み** —— 両腕を1本で対比する（片腕だけでは決め打ちが緑）。
- **DB の既定の場所を、機の既定と違う値で測る**（`assert_ne!` では防げない族。CLAUDE.md §4「実行時に決まる値を入れたら、機械の既定と違う状態で回る腕を必ず1本」）。
- **`--fresh` の退避は tempdir で実測** —— 3ファイル揃い／DB だけ／無し、の3状態。**退避後に元の名前が無く、退避先に在ること。**
- **知らない引数で止まる。**
- **起動行が「画面はどこから来たか」を言う** —— `the_startup_line_says_whether_the_web_dir_exists` の後継
  （**置いた**: `the_startup_line_says_where_the_ui_came_from`）。

**⚠ 上の6つに加えて、3周のレビューで次の6つを新設した**（§実装で分かったこと 8〜12）。
**`tests/fresh_cli.rs` は3本まとめて1行**なので、**行は6つ・テストの本数はそれより多い**:

| 見張り番 | 何を止めるか |
|---|---|
| `two_stashes_in_the_same_second_both_survive`（`server::fresh`） | **同じ秒の2回目が1回目の退避を上書きすること** |
| `a_failure_halfway_puts_the_first_file_back`（同上） | **途中で失敗して、本体だけ退避されたまま残ること** |
| `a_rollback_never_overwrites_what_took_the_name`（同上） | **巻き戻しが、空いた名前を取った側を上書きして消すこと** |
| `tests/fresh_cli.rs`（実行ファイルを起こす3本） | **`main` の `if args.fresh()` が死ぬこと** |
| `tests/server_database_dir.rs` | **`App::bind` が DB の置き場所を作らなくなること** |
| `the_package_script_builds_the_web_before_the_executable`（`tests/start_script.rs`） | **`package.ps1` の順番が入れ替わること** |

## ⚠ 実装で分かったこと（作業単位 `F-4a` / 2026-09-18）

**決定は1つも変えていない。** 決めたときに見えていなかったことを、ここに足す。

### 1. **`AppConfig::from_lookup` は純粋なままにできなかった**

**指示は「`from_lookup` は純粋なまま保つ」だった。** 出来なかった。

**OS の作法の場所を「参照関数」の側から引く**（`LOCALAPPDATA` / `HOME` / `XDG_DATA_HOME` を
同じ閉包で読む）**形にすると、`from_lookup(|_| None)` が `ConfigError::DataDir` になる。**
**そういう呼び出しがリポジトリに 30 箇所あり、どれも直後に `with_database_path` を呼んでいる**
——**止める意味のない所を全部止めることになる。**

**採った形**: **純粋な本体を `AppConfig::from_lookup_with_data_dir(lookup, data_dir)` に置き、
`from_lookup` はそこへ `os_data_dir()` を渡すだけにした。**
**「この機の既定と違う場所で回す腕」は本体の側にある**
（`the_database_falls_back_under_the_data_dir_it_is_given` が **2つの植えた場所**で回し、
**どちらもこの機の既定ではないことをテスト自身が確かめる**）。

### 2. **起動行の欄は「実在」ではなく「件数」にした**

**`web_dir_exists`（真偽値）の素直な後継は `ui_files`（件数）だった。**
**埋め込みには「ディレクトリが在るか」という問いが無い**ので、
**2つの腕で同じ意味を持つ欄は「何件配れるか」しかない。**

**⚠ これで振る舞いが1つ変わった** —— **空のディレクトリを配り先に指すと、警告が出るようになった**
（以前は `web_dir_exists=true` で黙っていた）。
**`UiFiles::exists` の doc が「ファイルが置いてあった場合も `false`。そこからは何も配れないので」と
書いていた向きを、空のディレクトリにも当てた形である。**

**欄は3つ**——`ui_source`（`embedded` / `disk`）/ `ui_origin`（埋め込み元、または配り先の綴り）/
`ui_files`（件数）。**後継の見張り番は `the_startup_line_says_where_the_ui_came_from`**
（**3腕を1本に置く**: ディスク・中身あり / ディスク・中身なし / 埋め込み）。

**警告の文面も2つに割れた。** **直す手が違う**からである
——ディスクなら `pnpm build` だけ、**埋め込みは `pnpm build` の後に `cargo build` が要る。**

### 3. **埋め込み元の綴りの写しは、消せずに3つになった**

**`include_dir!` はリテラルしか受け取らない**ので、`DEFAULT_WEB_DIR` を渡せない。
**さらに `build.rs` は lib の定数を参照できない**ので、そこにも綴りが要る。

| 写し | 見張り番 |
|---|---|
| `web/vite.config.ts` の `build.outDir` | `the_default_web_dir_is_where_vite_actually_builds`（定数と突き合わせ） |
| `src/server/web.rs` の `include_dir!` の綴り | **`the_embedded_ui_comes_from_the_default_web_dir`（新設。ソースを走査する）** |
| **`build.rs` が作って `rerun-if-changed` に登録する綴り** | **無い** |

**⚠ 3つ目は無防備である。** 食い違ったときの現れ方は
**「`pnpm build` しても実行ファイルの中の画面が変わらない」**（ビルドは通る）。

### 4. **埋め込む道具は `include_dir`。`rust-embed` を採らなかった**

**`rust-embed` は既定で「debug はディスクから読む」形**になり、
**`debug-embed` を有効にし忘れた瞬間に、この ADR §決定2 が却下した穴そのものができる。**
**`include_dir` は常に埋め込むので、忘れようがない。** フィーチャは1つも要らない。

### 5. **退避先の綴りは SQLite の作法を保つ形にした**

§決定4 は「`-wal` / `-shm` も**同じ接尾辞で**」としか書いていない。2通り書ける:

* `personacore.sqlite.bak-<時刻>-wal` ← **採った**
* `personacore.sqlite-wal.bak-<時刻>`

**前者にすると、退避した3つがそのまま SQLite の3点セットになる**ので、
**戻さずにそのまま `sqlite3` で開ける。**

### 6. **埋め込み側にも `ServeDir` と同じメソッドの作法が要った**

§決定2 は「配り方の規則は変えない」としか書いていないが、
**`ServeDir` は GET / HEAD しか受けず、それ以外は本文の無い 405 を返す。**
**埋め込み側も同じにした**（違うと、`PERSONACORE_WEB_DIR` の有無で
画面側の 405 / 404 の形が変わる）。

**⚠ ディレクトリの `index.html` は、いまはルート（`/`）だけ。**
`ServeDir` は**どのディレクトリでも** `index.html` を返すが、
**埋め込みの表はディレクトリを持たない。** `web/dist` は入れ子の `index.html` を作らないので、
**いまは差が出ない。**

### 7. **`std::env::args()` は使えない**

**Unicode でない引数で panic する**（CLAUDE.md「本番コードパスに panic! を置かない」）。
`args_os()` ＋ `to_string_lossy` にした。**読めない綴りは「知らない引数」として止まる**ので、
§決定4 の意図はそのまま成立する。

### 8. **同じ秒に2回 `--fresh` すると、1回目の退避が消えていた**（レビュー1周目 / 指摘1）

**[`std::fs::rename`] は宛先が在れば黙って上書きする。** 接尾辞は**秒まで**なので、
**同じ秒に2回叩くと1回目の退避が消えた**（実測: 退避先が1つしか残らず、中身は2回目の空の DB）。
**§決定4「削除の経路を作らない」に反する、唯一の利用者データ破壊経路**だった。

**⚠ 見落とした論法がそのまま doc に書いてあった** ——
「`--fresh` が呼ぶのは `rename` だけで、`remove_file` は1つも無い」。
**`remove_file` が無いことは、消えない理由にならない。**

**塞いだ形**: **宛先が1つでも塞がっていれば、3つとも次の番号へ**
（`…bak-<時刻>-2` / 同 `-wal` / 同 `-shm`）。
**組を作る道を private モジュール `names::choose` 1本に閉じた**ので、
**モジュールの外からは「空きを確かめずに組んだ組」を `rename` へ渡せない。**

> **⚠ `F-4b` が Mac 用の写しを作るとき、ここを落とさないこと。**
> **「同じ接尾辞で3つまとめて」だけを写すと、この穴がそのまま復活する。**

### 9. **途中で失敗すると、本体だけ退避されて `-wal` が残っていた**（レビュー2周目 / 指摘7）

**§決定4 が名指しした「片方だけ残す」形そのもの**だが、**見張り番が無かった。**

**塞いだ形**: **失敗したら、動かした分を逆順で戻す**（`stash_with`）。
**戻すのにも失敗したら、両方の理由を持つエラーで止める**（`FreshError::Rollback`）。
**改名は引数で受け取る**ので、テストが「2つ目で失敗する改名」を植えて3状態を測れる。

### 10. **埋め込みが `web/dist` の2段目で止まっていた**（レビュー1周目 / 指摘2）

`include_dir` の `files()` / `dirs()` は**非再帰**。
**ディスク側は 8 段降りていた**ので、**現れ方がいちばん悪い形**になっていた ——
**`PERSONACORE_WEB_DIR` を立てた開発中は 3 段目が出るのに、配布物では 404。**

**塞いだ形**: **再帰にして、深さの上限（`MAX_UI_DEPTH`）を2つの腕で共有する。**

### 11. **見張り番が1本も無かった場所が3つあった**（レビュー1周目 / 指摘4・5・7）

| 場所 | 変異 | 実害 |
|---|---|---|
| `main` の `if args.fresh()` | 常に偽にする | **`--fresh` が何もしない**（`fresh` モジュールは厚く見ていた） |
| `App::bind` の `create_dir_all` | 殺す | **初回起動が全部落ちる**（既存のテストは親が必ず先に在るパスだけを指していた） |
| `package.ps1` の順番 | 2つの呼び出しを入れ替える | **古い画面が入る。作成も起動も成功する** |

**どれも「配線だけの場所」で、部品の側は厚く見ていた**
（CLAUDE.md「部品の被覆率は、組み上げの被覆を1ミリも意味しない」）。

### 12. **巻き戻しの向きでも `rename` は上書きしていた**（レビュー3周目）

**§実装8 の「`remove_file` が無いことは消えない理由にならない」を、
退避の向きにしか当てていなかった。**

**窓はこう開く** —— **`--fresh` は DB を開く前に走るが、
同じ置き場所を指した別の personacore を止める手段は無い:**

1. 本体の退避に**成功する**（元の名前が空く）。
2. **別のプロセスが、空いた元の名前で新しい DB を作る。**
3. 次（`-wal`）の改名が**失敗する**。
4. 巻き戻しが `rename(退避先, 元の名前)` を呼び、**2 で作られた DB が消える。**
   **しかも退避先も戻し切って消えるので、痕跡がゼロになる。**

**塞いだ形**: **戻す先が塞がっていたら、戻さずに [`FreshError::Rollback`] で止める。**
**割り込んだ側が生き残り、退避先も残る**（手で戻せる）。

> **⚠ `F-4b` が Mac 用の写しを作るとき、ここも落とさないこと。**
> **「失敗したら戻す」だけを写すと、この穴がそのまま復活する。**
