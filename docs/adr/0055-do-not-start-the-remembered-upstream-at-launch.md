# ADR-0055: 覚えたプロファイルで起きたときは上流を起こさず、画面で聞く。`--upstream` を明示したときは今までどおり起こす

## 背景

personacore は起動時に、最後に選んだプロファイル（`selected-upstream.txt`）で起きる（ADR-0042 §決定9）。そのプロファイルの面が `gguf` を名指ししていれば、待ち受けを開いた直後に llama を起こす（§決定2・3）。

C-21 で、第三者の推論サーバの中継（以下「中継」。ADR-0056 の「鍵で守られた中継」）を遊ぶ用の上流にすると決めた。中継の先の推論サーバは personacore が起こさない外の上流で、読み込むと 12GB の GPU をほぼ使い切る。利用者の覚えた名前はいま `qwen-official`（Qwen3.6-35B-A3B Q6_K の `gguf` 付き）なので、**その推論サーバにモデルを載せたまま personacore を起動すると、起動した瞬間に llama が VRAM を取り合う。** 利用者は中継で遊ぶたびにこれを踏みうる（利用者の指摘 / 2026-11-01。まだ実際には踏んでいない）。

覚えた名前は「前回そう選んだ」という**過去の意図**である。そのあいだに利用者が別の上流（中継の先の推論サーバ）を手で起こしていても、personacore には分からない。

## 決定

### 1. 覚えた名前で起きたときは、`gguf` の面を起こさない

- 起動時のプロファイルが**覚えた名前**から来たときは、`gguf` を名指しした面を起こさない。待ち受けは今までどおり先に開く
- その面の状態は新しい状態 **`起こしていない（起こすのを待っている）`** になる（ADR-0042 §決定3 の状態の一覧に足す）
- 宛先・モデル・窓（ADR-0054）などのプロファイルの中身は今までどおり読み込む。起こさないだけである
- `gguf` の無い面（外の上流。中継もこれ）は今と同じで、起こすものが無い

### 2. `--upstream <名前>` を明示したときは、今までどおり起こす

起動の旗はその時点の意図である。開発の `start.ps1 -Upstream` もこの経路を通る。ADR-0042 §決定9 の優先順位（`--upstream` ＞ 覚えた名前 ＞ 環境変数の既定）は変えない。変わるのは「覚えた名前のときに起こすかどうか」だけである。

### 3. 画面が「起こしますか」と聞き、押したら起こす

- `#/upstream` の画面と会話の画面は、本文の面が `起こしていない` なら、そう言い、**起こすボタン**を出す
- 会話の画面は、ADR-0042 §決定3 の追記（自分が起こす面が「載せている／失敗／止めた」なら送信を止めて理由を言う）と同じ扱いで、`起こしていない` でも**送信を止めて理由を言う**。裏方の面の状態では止めない（§決定3 の追記と同じ）
- 起こすのは、今の差し替え（`POST /admin/upstream/profile`、ADR-0042 §決定4）と同じ経路を通す。**同じ名前を頼まれ、`起こしていない` 面があるときは、その面を起こす。** 起こし終わった面は差し替えと同じく測り直す。同時に1つだけ・`409` の規則も同じ
- 起こした後の覚えた名前は今と同じ（受け付けたときに覚える）

### 4. 外のクライアントには今の上流エラーの形で返る

`起こしていない` 間に OpenAI 互換の口へ来た要求は、今の「載せている」間と同じく、上流エラー（接続拒否）の形で返る。サーバの振る舞いは隠さない（ADR-0042 §決定3）。

## 却下した選択肢

- **起こす前に GPU の空きを見て、足りなければ起こさない** —— 手間は増えないが、NVIDIA の `nvidia-smi` に頼る（Mac と他社の GPU で成り立たない）。「足りる」の閾値はモデルと文脈長で変わる実測由来の値で、ADR-0036 の問い「外したら壊れるか」に対して「外すと取り合う＝壊れる」側に置くことになる。しかも空きは起こした後に変わる（中継の先の推論サーバは会話中に expert cache を入れ替える）
- **運用で避ける（中継で遊ぶ前に画面で中継のプロファイルを選んでおく）** —— personacore は変えずに済むが、忘れたときに取り合う。忘れる形の事故を利用者の注意で防ぐことになる
- **覚えた名前を `gguf` のあるときだけ忘れる** —— 「最後に使ったもの」で起きるという ADR-0042 §決定9 の利用者の決定を崩す。画面でどれを起こすかを毎回選び直すことになる
- **起動から一定時間待ってから起こす** —— 待つ時間に根拠が無い。取り合いは時間で解けない

## 結果

- 中継の先の推論サーバにモデルを載せたまま personacore を起動しても、llama は起きない。画面が「起こしますか」と聞く
- 覚えた名前が `gguf` 付きのときは、**起動のたびに1手（起こすボタン）が増える。** 利用者がこの手間を選んだ
- `--upstream` を明示する起動（開発の `start.ps1 -Upstream`、端末からの起動）は変わらない
- 作業単位は F-10a（Rust: 起こさない起動・新しい状態・同じ名前で起こす経路・`GET /admin/upstream`）と F-10b（web: 2つの画面の表示とボタン、送信の停止）に分ける
