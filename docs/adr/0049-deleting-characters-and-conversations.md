# ADR-0049: 会話のあるキャラクターと、会話を消す

- 状態: **採用**（2026-10-21 / 利用者が問いに答えた。細部は司令塔）
- 日付: 2026-10-20
- 関連: [ADR-0016](0016-character-update-and-delete.md) §2（削除は会話が無いときだけ。「会話のあるキャラクターを消したくなったときの導線は**別途決める**」）/
  [ADR-0008](0008-admin-api.md)（`memory` に更新・削除を作らない）・[ADR-0022](0022-repairing-memories-without-deleting.md)（記憶は消さずに直す）/ origin#55（A-10）

## 背景

利用者が遊んでいて「過去の会話・記録を消せない。そのため、会話したキャラクターも消せない」と報告した（2026-10-14）。

- `DELETE /admin/characters/{handle}` は、会話が1件でもあると 409 `character_has_sessions` で断る（`src/store/character.rs` の `DELETE_CHARACTER` が `NOT EXISTS (SELECT 1 FROM session …)` を同じ文に持つ）。ADR-0016 §2 の決定どおり。
- 会話・メッセージ・記憶を消す口は無い。
- **スキーマはもともとカスケードで消える形をしている。** キャラクターを指す表（`session`・`memory`・属性・性格値・変容の票・軸の候補など）と、会話を指す表（`message`・`summary`・変容の票など）は、どれも `ON DELETE CASCADE` を持つ。いま消えないのは、スキーマのためではなく、`DELETE_CHARACTER` の条件が止めているからである。
- **記憶は、どの会話から取り出したかを持たない**（`memory` に `session_id` / `message_id` の列が無い）。記憶はキャラクターに付く。

## 「記憶を消さない」制約との線引き

CLAUDE.md §1 の「`memory` の行を DELETE / UPDATE しない」は、**直すとき**の規則である。理由は時系列の保持で、「以前は X だったが、いまは Y」を想起させるために古い行を残す。

**キャラクターや会話を丸ごと捨てる操作には、この理由が及ばない。** 想起する主体ごと（または、その時系列ごと）無くなるので、保つべき時系列が残らない。この ADR は、次のように線を引く。

- **直す**（1件の記憶が間違っている）→ 今までどおり corrections と `superseded_by`。行は消さない。
- **捨てる**（キャラクター丸ごと）→ カスケードで物理的に消してよい。

`message.raw_content` を必ず保持する制約（パースの失敗を調べる唯一の手段）も、同じく「残っている会話について」の規則として読む。捨てた会話の調査の材料は残らない。それを受け入れる。

## 利用者に問うたこと（2026-10-20）

| 問 | 答え |
|---|---|
| 消したい理由は「一覧を片付けたい」か「中身ごと消したい」か | **両方** |
| 会話を1つだけ消す口も要るか | **記憶の整理と一緒に**（記憶の出どころを持たせる設計が決まってから） |

## 決定

### 1. 「しまう」と「完全に消す」の2段

- **しまう**（論理削除）: キャラクターに「しまった時刻」を持たせる（新しいマイグレーションで列を足す）。しまったキャラクターは、`GET /v1/models` と画面の一覧に出ない。会話・記憶・性格値などの中身は**1行も変えない**ので、**戻せる**。
  - 口: `PATCH /admin/characters/{handle}` に任意の欄（しまう／戻す）を足す。応答のキャラクターには、しまった時刻の欄を足す。どちらも ADR-0047 §② の表で `1.x`（任意の要求の欄・応答の欄の追加）。
  - しまったキャラクターへの chat（`model` に名指し）は断る。黙って会話を足さない。
  - 管理の読み取りの口（会話の一覧・メッセージ・記憶）は、しまったキャラクターにも今までどおり答える（中を見てから消すかを決められるように）。
- **完全に消す**（物理削除）: **しまったキャラクターだけ**を、カスケードで消す。**控えは残さない**（中身ごと消したい、という利用者の答え）。
  - 口: 既存の `DELETE /admin/characters/{handle}` の受け付ける範囲を広げ、「会話が無い」 **または「しまってある」** なら消す。しまっていない、会話のあるキャラクターは今までどおり 409 `character_has_sessions`。今まで通った要求は通り続け、今まで 409 だった要求の一部が通るようになるだけなので `1.x`（受け付ける範囲を広げる）。
  - 画面では、確認として**識別子（handle）を打ち込ませる**。取り消しが効かないことを伝える。
  - 判定と削除は、今の `DELETE_CHARACTER` と同じく**1つの文**に置く（数えてから消すと、その隙に戻されたキャラクターや、会話が足されたキャラクターを消しうる）。
- **2段にする理由**: 「片付けたい」は戻せる方が安全で、「中身ごと消したい」は戻せない操作が要る。**完全に消す前に必ず「しまう」を通る**ので、一覧から1回の誤操作で中身を失う事故が起きない（ADR-0016 が守りたかったもの）。
- 完全に消した後は、同じ識別子をもう一度使える。しまっただけのあいだは、識別子は使用中のまま。

### 2. 会話を1つだけ消す口は、記憶の整理の設計と一緒に作る

会話を消しても、その会話から取り出した記憶は残る（記憶は出どころを持たない）。会話とそこから来た記憶を一緒に消せる形にするには、記憶に出どころを持たせる必要がある。その持たせ方は、記憶を整理する設計（origin#57）と一緒に決める。その設計が記憶の形を変えるからである。
> **2026-10-21 追記**: 記憶を整理する設計（ADR-0050）は「まとめは先回りしない」と決め、出どころは**まとめを作るときに一緒に作る**ことになった（ADR-0050 §決め直し 3・4）。会話を1つだけ消す口は、それまで作らない。

### 3. 裏方との重なり

完全に消すのは1つの `DELETE` 文（カスケード）で、外部通信は挟まない。裏方（抽出・変容・軸の候補）が同じキャラクターに書いている最中に消すと、裏方の書き込みは外部キーで失敗する。その失敗は「キャラクターが消えた」として捨て、エラーとしては報告しない（ログには残す）。この扱いは作業単位で確かめる。しまっただけのキャラクターには、裏方は今までどおり書いてよい（中身を変えない約束は「利用者の操作では変えない」という意味で、走りかけの抽出を止めるためのものではない）。

> **2026-10-21 追記（A-10 の実装で分かったこと）**: 決定3の前提「裏方の書き込みは外部キーで失敗する」は、**いつも成り立つわけではない**。`character.id` は AUTOINCREMENT ではないので、いちばん新しいキャラクターを完全に消してすぐ作ると、**同じ id が使い回される**。そのとき、消す前から走っていた裏方の書き込みは外部キーで落ちず、**新しいキャラクターに書かれる**（持ち主を取り違えた記憶は、正しい持ち主へ移せない —— CLAUDE.md §1）。
> **決定**: 裏方の書き込み（記憶・変容の票・値・累積・軸の候補・試みの記録）は、**それを生んだ会話が今も在り、同じキャラクターのものであること**に縛る。`session.id` は AUTOINCREMENT（`0003`）で使い回されない。判定と書き込みは、1つの文か、書きロック（`BEGIN IMMEDIATE`）を取った直後の確かめで行う。縛りに落ちたら何も書かない。会話が無いときは `StoreError::TurnSessionGone` で、「キャラクターが消えた」としてログ（`info`）に残す。会話が在るのに別のキャラクターのものだったときは `StoreError::SessionOfAnotherCharacter` で、これは本物の取り違えなので `warn` に出す（「消えた」とは読まない）。**会話の id を持たない裏方の書き手を将来足すときは、同じ縛りが要る。** `character` を AUTOINCREMENT で作り直す案は、`character` を直接指す表だけで 10 あって移行が重いので採らなかった。
> 欄の名前（実装）: しまう／戻すは `PATCH` の `archived`、しまった時刻は応答の `archived_at`、しまったキャラクターへの chat は 409 `model_archived`（ADR-0047 の API の版 1.1）。
> **本文側の保存も同じ扱い**（A-10 のレビュー）: 応答を生成している間に「しまう → 完全に消す」をすると、往復の保存が失敗する。A-10 より前は会話のあるキャラクターを消せなかったので、届かなかった経路である。失敗の原因がキャラクターの消失だと確かめられたときだけ、エラーではなくログ（`info`）に落とす。

## 却下した選択肢

- **会話のあるキャラクターも、いきなり完全に消せるようにする**（`DELETE` の 409 をやめる）。一覧から1回の誤操作で中身を失う。ADR-0016 がこれを避けるために 409 を置いた。
- **完全に消す前に DB の控えを自動で取る**。「中身ごと消したい」という答えと食い違う。控えが要るなら、利用者が DB のファイルを写せばよい。
- **完全に消す専用の口を足す**。既存の `DELETE` の範囲を広げれば足りる。口を増やすと、同じ削除に入口が2つになる。

## 結果

- 会話したキャラクターも消せるようになる。ただし必ず「しまう」を経由する。
- `memory` の行を消すのは「キャラクターを丸ごと完全に消す」ときだけ。CLAUDE.md §1 の「直すときは消さない」は変わらない。
- 会話を1つだけ消すことは、まだできない（決定2）。
