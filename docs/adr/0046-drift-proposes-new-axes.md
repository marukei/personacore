## 背景

利用者の発案（2026-09-26）: 性格の軸を全部手で起こすのは難しい。**固定の n 本 ＋ 変容が埋める m 本の枠**にして、枠の中は変容が見いだした軸でカバーしていきたい。

利用者が決めたこと: **承認制**（候補が合格しても、利用者が採用するまで正式な軸にしない）。**v0.1.2 の後に、この ADR から始める。**

リポジトリには、この発案をそのまま自動にすると踏む穴が2つ記録されている:

1. **モデルに軸名を考えさせると、張り付く名前を出しやすい。** 張り付いた6本のうち5本は `誠実さ` `慎重さ` `落ち着き` `共感` `自信` —— 助手の美徳の名前だった。`甘えたがり` のような「利用者との距離が縮まる向きの語」も張り付いた（ADR-0030 §決定2）。**モデルに「このキャラの新しい軸を」と頼めば、まさにこういう語を出す。**
2. **綴りが揺れる。** 送り仮名・簡体字が混ざり、許可リストは完全一致なので揺れた綴りは別の軸か捨て票になる（ADR-0029 / ADR-0030 §決定3）。

一方で、**軸の良し悪しを数で決める手順はすでにある**（ADR-0030 §決定4: 記録専用で 60 ターン回す → 上げの割合が 90% を超えた軸・`0` の率が 90% を超えた軸を落とす）。**手で回していたこの手順を、枠の中で自動で回す**のがこの ADR の骨子である。

## 決定（提案）

### 1. **枠はキャラクターごとに持つ。既定は 0（見いださない）**

キャラクターに**見いだす枠の数 `m`**（0〜4）を持たせる。**既定 0** なので、足しただけでは何も起きない。
固定の n 本（いまの性格値）には**一切触らない**。枠の軸は、採用されるまで固定の軸と別の場所に置く（§決定6）。

> 上限 4 の根拠は無い（**測っていない値**）。削れない枠に載る行が増えるので、上限は要る。測ってから動かす。

### 2. **候補は「溜まってから」出させる。入力はそのキャラクター自身の記憶**

空いた枠があるとき、**そのキャラクターの記憶（`subject = character`）が前回から `N` 件増えたら**1回だけ、裏方に候補を1つ出させる（ADR-0028 §決定2 と同じ形 ——「なし」を言わないモデルに毎ターン尋ねない）。

- 入力は**記憶**であって生の会話ではない（ADR-0028 §決定1: 主語が付き、上限を持つ型を通っている）。
- 依頼には**いまの軸名（固定・試用中・採用済み）と、却下・不合格になった名前**を載せ、同じものを出させない。**ただし最後の判定は依頼ではなく照合で行う**（下）。
- 返ってきた名前は `StatAxis::parse`（上限つきの型）を通し、**既存の軸名・却下済みの名前と完全一致したら捨てる**。綴りの正規化はしない（ADR-0030 の却下どおり。許可リストが緩む）。

> **名前で美徳を弾く規則は置かない。** ADR-0030 §決定2 の ⚠ のとおり、**名前からの推測は当たりを付けるためだけ**で、判定は §決定3 の数で行う。依頼文に「助手の美徳・利用者との距離の語を避ける」と書くのは当たりを付ける範囲で許す。

### 3. **候補はまず「試用」になる。値を動かさず、別の依頼で採点する**

候補は枠に入ると**試用**になる。試用の間:

- **本文のプロンプトには載らない**（演技に影響させない）。
- **値は動かさない**（記録専用と同じ。票だけを残す）。
- **固定の軸の採点とは別の依頼で採点する。** ⚠ **ここがこの ADR でいちばん大事な選択**:
  CLAUDE.md §4「複数の項目を1回で採点させると、項目は独立に判定されない」。**候補を固定の軸と同じ依頼に混ぜると、試用中の候補が固定の軸の票を動かす** —— 固定の軸の変容が、試用の有無で変わってしまう。**別の依頼にすれば、固定の軸の振る舞いは1バイトも変わらない。**
  代償は、**試用中だけ裏方の呼び出しが1ターンに1回増える**こと。

### 4. **合否は数で決める（ADR-0030 §決定4 の線）**

試用は **T ターン**（既定 60。ADR-0030 は「張り付きは早く出る。60 ターンで足りる」）回したら判定する:

| 判定 | 条件 | 行き先 |
|---|---|---|
| **張り付き** | 非ゼロの票のうち上げが 90% を超える | 不合格 |
| **沈黙** | `0` の率が 90% を超える | 不合格 |
| **標本不足** | 非ゼロの票が `K` 件未満（ADR-0030 §実測3 の宿題「非ゼロが N 件未満なら割合を読まない」） | 不合格（沈黙の側に数える） |
| それ以外 | | **合格 → 利用者への提案** |

> 線（90% / `K`）は ADR-0030 の実測の分布の隙間に置いたもので、**候補の分布では測っていない。** §測る問い で測ってから固める。

### 5. **採用は利用者だけ。採用した軸は 0 から始める**

合格した候補は、**利用者への提案**として画面に出る（試用の票の内訳 —— 上げ・下げ・`0` の件数 —— を添える）。

- **採用** → 固定の軸と同じ正式な軸になる。**初期値は 0**（ADR-0027 §11: ゼロから育てると分化する。0 の軸は本文には載らず、変容の依頼には載る —— CLAUDE.md の「値 0 の軸」の制約のとおり）。以後は普通の変容で動く。枠が1つ埋まる。
- **却下** → 記録して枠を空ける。**同じ名前は二度出させない**（§決定2 の照合）。
- **不合格**（§決定4）も同じく記録し、二度出させない。

**採用・却下・不合格は追記で残す**（ADR-0028 §決定5・7 と同じ ——「なんか前と違う」以上が分からない状態を作らない）。

### 6. **データの形: 候補は別の表。試用の票も別の表**

- `stat_axis_candidate`（追記。候補の名前・出どころの記憶・状態の移り変わり: 試用 → 合格／不合格 → 採用／却下）
- 試用の票は**変容の票（`stat_drift_vote`）と混ぜない**別の表（固定の軸の集計・画面・測定の道具を1つも変えないため）
- 採用した時点で、いまの `stat_alloc` に値 0 の行として足す（書き込み経路は1つ）

### 7. **記録専用から始める**（ADR-0028 §決定8 / ADR-0026 §決定1 と同じ順）

最初の段は**候補を出して試用し、判定を記録するだけ**で、提案の画面も採用も作らない。
**その記録で §測る問い に答えてから**、提案の画面と採用を作る。

## 測る問い（着手前に決めておく）

**「候補の生成器は、合格する軸を、割に合う率で出すか。」**

既存の測定の台本（`<measurements>\`）で候補を出させて試用し、**合格率**と、**不合格の内訳（張り付き・沈黙・標本不足）**を数える。**合格率がほぼ 0 なら、この仕組みは作る価値が無い**（手で軸を選ぶ手順の案内を画面に出すほうがよい）。**美徳の名前がどれだけ出るか**も同じ回で数える（ADR-0030 §決定2 の予言が候補でも当たるか）。

## 危険（実測に基づく）

- **張り付く名前を出しやすい**（背景 1）。→ §決定4 で落とす。落ちる率が高ければ §測る問い が「作る価値が無い」と答える。
- **綴りの揺れ**（背景 2）。→ 採用前に利用者の目に映る。採用後は完全一致の許可リストなので、**採用した綴りが以後の唯一の綴り**になる。
- **裏方の負荷**。試用中は1ターンに裏方の呼び出しが1回増える（§決定3）。split で裏方を CPU 寄りに置いている構成では、ターンの間隔が裏方の所要より短いと、次のターンの裏方ごと飛ぶ（既存の `Busy`）。
- **抽出の誤りが入力に乗る**（ADR-0028 §決定1 の ⚠ と同じ）。→ 採用は人が行う。

## 却下した選択肢

- **合格したら自動で採用する** —— 利用者が承認制を選んだ。
- **試用なしで、モデルが出した名前をそのまま軸にする** —— ADR-0030 の張り付きをそのまま踏む。
- **候補を固定の軸と同じ依頼で採点する** —— 呼び出しは増えないが、試用の有無で固定の軸の変容が変わる（§決定3）。
- **綴りをアプリ側で正規化する** —— ADR-0030 の却下どおり。
- **生の会話を入力にする** —— 主語が付いておらず、上限を持つ型も通っていない（ADR-0028 §決定1）。**ただし性格は台詞の口ぶりに出るもので、記憶に残りにくい可能性がある** —— §測る問い で候補が出にくければ見直す。
