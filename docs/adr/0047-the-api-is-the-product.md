## 背景

personacore は最初から「OpenAI 互換 API サーバとして FE と推論サーバの間に立つ」形で作ってきた（CLAUDE.md の冒頭の図）。画面（Svelte）は exe に埋め込まれているが、**画面が呼ぶのは公開の HTTP の口だけ**である（2026-09-29 に司令塔が `web/src` の呼び先を数えた）:

- `/v1/chat/completions`（OpenAI 互換 —— 会話）
- `/admin/...`（キャラクター・記憶・性格値・変容・属性・会話の履歴・上流の管理）

画面専用の裏口は無い。**画面にできることは、他のソフトも HTTP で全部できる。** 画面の成果物（`web/dist`）は 173KB で、exe（約 13MB）の容量の負担でもない。

利用者は「API として機能する部分と GUI を分離してパッケージ化するのが正解ではないか」と問うた。**分離はすでに設計の中にある**ので、問いは「何が組み込みの妨げになっているか」に置き換わる:

1. **API に約束が無い。** 仕様書も、版の番号も、互換を壊すときの方針も無い。画面とサーバは同じリポジトリの中で型を写し合って守っている（`web/tests/api-fields.test.ts` の写しの走査）ので、外のソフトからは次の版で壊れないかが分からない。
2. **文書が日本語だけ。**
3. **「画面なしで使ってよい」と名乗っていない。**
4. **認証が無い。** `127.0.0.1` にしか結ばない（CLAUDE.md の絶対制約）ので今は問題ないが、組み込み先は同じ機の別のプロセスに限られる、という前提を書いていない。

## 決定

**API が本体で、画面はその最初の使い手の1つである。** 配布物は ADR-0041 のとおり1本のまま画面を同梱し、次の段で「組み込んでよい形」を足す。

### 段の定義

| 段 | 中身 | 状態 |
|---|---|---|
| **① 画面なしの形を名乗る** | 起動の旗で画面を配らない形を選べるようにする。**利用者向けの zip は今のまま画面同梱** | **採る**（P-1） |
| **② API を約束にする** | 仕様書・版・互換の方針・英語の API ガイド | **採る**（P-2a〜c） |
| ③ 中核をライブラリにする | `domain` / `prompt` / `parse` など純粋な部分を Rust のライブラリ crate として切り出す（ADR-0002 の見込み） | **保留** —— 具体的な使い手（Rust で組み込みたい人）が現れてから |
| ④ 配布物を2つに割る | サーバの exe と画面のパッケージを別々に出す | **採らない（当面）** —— 利用者は2つの版の組み合わせを気にすることになり、「exe を1本叩けば動く」（ADR-0041 / 勝ちの線）が崩れる。①②で組み込む側の必要は満たせる |

> **2026-10-21 追記**: ① ② は済んだ（P-1 = origin#44、P-2a〜c = origin#45〜47）。下の §② の「作業単位の最初に実測する」や §結果 の「P-2a はその費用を最初に測る」などの未来形は、着手前に書いた計画として残す。結果は各 Issue のコメントと `src/server/openapi.rs`・`docs/api/README.md` にある。

### ① 画面なしの形（P-1）

1. **起動の旗 `--no-ui`**: 画面を配らない（`/` と画面の資産に 404）。**ブラウザも開かない**（`--no-browser` を含む —— 開く頁が無い）。起動ログに「画面は配らない」と1行出す。
2. **API の振る舞いは1バイトも変えない**（`/v1` も `/admin` も、旗の有無で同じ応答）。
3. **ビルドの選択肢（cargo の feature で画面を埋め込まない exe）は、この段では作らない。** 埋め込みの仕掛け（`build.rs` の `web/dist` の扱い）に触れる割に、得るものは 173KB だけである。要ると分かってから。
4. 環境変数の形（`PERSONACORE_NO_UI` 等）は足さない —— 旗で足りる。つまみを増やさない（CLAUDE.md / ADR-0036 §決定3 の精神。これは測定値のつまみではないが、同じく「要ると分かってから」）。

### ② API を約束にする（P-2a〜c）

**P-2a: 仕様書をコードから生む。** 第一案は **`utoipa`**（Rust の型と handler の注釈から OpenAPI 3.x を生成）。
- **理由**: 仕様書を手で書くと、コードと仕様書の2箇所に同じ事実が載る（CLAUDE.md「同じ発見を2箇所に書かない」）。生成なら**コードが唯一の正**になる。
- **作業単位の最初に実測する**: 依存のライセンス（MIT / Apache であること —— オープンソース化の監査で依存は全部緩いライセンスだった）、ビルド時間の増え方、`deny_unknown_fields` や `FieldUpdate` の3状態（省く / `null` / 値）を仕様書が正しく表せるか。**表せなければ、その型だけ手で補うか、案を変える**（却下した選択肢を参照）。
- **生成した仕様書と実際の応答が食い違わないことの見張り番**を置く（生成物を固定したスナップショットの突き合わせ、または主要な口を実際に叩いて仕様書で検証するテスト）。画面の写しの走査（`api-fields`）は残すか、仕様書へ寄せるかを P-2a の中で決める。

**P-2b: 版と互換の方針、仕様書を配る口。**
- **API の版はアプリの版と別に持つ**（例 `1.0`）。**口の綴り（パス）は変えない** —— `/admin/v1/...` のようにパスへ版を入れると、画面と既存の使い方がすべて壊れ、得るものが無い。版は仕様書の `info.version` と、応答のヘッダ（例 `X-Personacore-Api-Version`）で言う。
- **互換の方針**: 欄の追加・口の追加は版の小さい側（`1.x`）。欄の削除・改名・意味の変更は大きい側（`2.0`）で、**古い形を1つの Release のあいだ残す**。
- **安定度を口ごとに名乗る**: `/v1/chat/completions` は OpenAI 互換として安定。`/admin/*` の大半は版の範囲で安定。**実験中の口**（軸の候補 `/admin/characters/{h}/axis-candidates` など、ADR-0046 の第2段の前のもの）は仕様書で実験中と印を付け、互換の方針の外に置く。
- **exe が仕様書を配る**（例 `GET /openapi.json`）。組み込む側は、動いているサーバから、その版の仕様書を取れる。`--no-ui` でも配る（画面ではなく API の一部）。

- **版の綴りの正は1箇所**（`src/server/openapi.rs` の `API_VERSION`）。仕様書の `info.version` と、**ルータに届いた要求への全部の応答**（成功・エラー・404・405・413・画面の資産・SSE・`/openapi.json`）に付くヘッダ `X-Personacore-Api-Version` はそこから読む。**仕様書も全部の応答（`default` を含む）の `headers` でこのヘッダを名乗る**（`every_documented_response_names_the_version_header`）。
  - **⚠ HTTP として壊れた要求への 400（hyper が返す）には付かない** —— ルータに届く前に答えが決まり、ヘッダを付けるレイヤを通らない。使い手は「ヘッダが無い応答」を、personacore の API が答えていない応答として扱う。上の行はそれの写しで、走査（`the_adr_names_the_same_api_version`）が突き合わせる。**アプリの版（`Cargo.toml` の `version`）とは別に動く。**
- **`/v1/chat/completions` の OpenAI 互換の本文は変えない**（ヘッダが増えるだけ）。
- **仕様書は `GET /openapi.json`** で配る（`content-type: application/json`）。**この口自身も仕様書に載っている。** 組み立てに失敗したら 500 の `ErrorBody`（詳細はログだけ）。**要求ごとに組み直す**（起動時に作り置かない —— 起動を止める経路も、持ち置く状態も要らない）。
- `info.license` と `info.description` は `Cargo.toml` の `license` / `description` から（写しを作らない）。**空なら載せない。**

**互換の方針。**

| 変更 | 版 |
|---|---|
| 応答の欄の追加・**要求の任意の欄**の追加・口の追加 | `1.x`（小さい側） |
| **応答の `enum` に値を足す** | `1.x`（小さい側）。**使い手は知らない値を受け付けること** |
| 要求の受け付ける範囲を広げる（`enum` に値を足す・長さの上限を上げる等） | `1.x`（小さい側） |
| 欄の削除・改名・意味の変更 | `2.0`（大きい側）。**古い形を1つの Release のあいだ残す** |
| **要求に必須の欄を足す・任意の欄を必須にする** | `2.0`（大きい側）—— 古い使い手の要求が全部 400 になる |
| **要求の受け付ける範囲を狭める**（`enum` から値を減らす・長さの上限を下げる・受け付けていた形を拒む等） | `2.0`（大きい側） |
| **既存の状態コードを変える**（成功の 200 → 201、失敗の 404 → 409 等） | `2.0`（大きい側）—— 使い手は状態コードで分岐している |
| **新しい失敗の状態を足す**（今まで起きなかった条件に 409 を返す等）・エラー本文の `error.code` に値を足す | `1.x`（小さい側）。**使い手は知らない状態コードを 4xx / 5xx の類として扱うこと**。ただし**今まで成功していた要求を失敗にする**なら、それは受け付ける範囲を狭める変更なので `2.0` |
| **既にある条件の `code` を細分する**（状態コードと `type` は変えない。例: 上流の 401 / 403 を `upstream_failed` から `upstream_unauthorized` に分けた / A-13b-1） | `1.x`（小さい側）。`code` は開いた文字列で、使い手は知らない `code` をその状態コードの失敗として扱う前提（P-2c のガイド）。**ガイドに以前の `code` を書く** |

- **応答の `enum` は「いま返しうる値」であって、閉じた約束ではない。** 仕様書は閉じた綴りの欄に `enum` を付けている（P-2a）ので、厳密に検証する使い手には値の追加が壊れて見える。**それでも小さい側に置く** —— 状態の綴りが1つ増えるたびに大きい版を上げると、版が意味を失う。使い手には「知らない値は、知らない状態として扱う」ことを求める（P-2c のガイドにも書く）。
- **要求の側は「今まで通った要求が通り続けるか」で線を引く。** 任意の欄・`enum` の値を足すのは `1.x`（古い使い手は送らないだけ）。**必須の欄を足す・範囲を狭めると、今まで通った要求が 400 になる**ので大きい側。
- **例外: セキュリティの修正で、約束していなかった経路を断るのは版を上げない**（2026-10-01 / origin#54 B-58）。B-58 は `Host` / `Origin` が `127.0.0.1` / `localhost` と実際のポート以外の要求を 403 で断る。表の上では「今まで成功していた要求を失敗にする」＝`2.0` に当たるが、**外の名前（hosts の別名・DNS rebinding）で届く要求は、ガイドが最初から約束していない**（「同じ機の `127.0.0.1` から」）。約束の外の経路を塞ぐたびに大きい版を上げると、版が「使い手の要求が変わるか」を言わなくなる。**使い手がガイドのとおりに呼んでいる限り、今まで通った要求は通り続ける** —— 線はそこに引く。

**口ごとの安定度。**

| 口 | 約束 |
|---|---|
| `/v1/chat/completions`・`/v1/models` | OpenAI 互換として安定（OpenAI 互換の形に従う。独自の欄を足すときは上の表） |
| `/admin/*`・`/openapi.json` | 版の範囲で安定（上の表） |
| 仕様書で `x-personacore-stability: experimental` の印を持つ口（いまは `/admin/characters/{handle}/axis-candidates` だけ） | **互換の約束の外。** 版を上げずに形を変えうる |

**版の上げ方。** **仕様書の差分を見て、司令塔が決める。** 作業単位が API の形（口・欄・`enum` の値・状態コード）を変えたら、その単位の中で `API_VERSION` と上の「いまの API の版」の行を一緒に上げる（片方だけ直すと走査が赤くなる）。実験中の口だけの変更では上げない。

**形の指紋の表（作業単位 O-7 / Issue origin#91 で足した）。** 上の手続きは、それを見る見張り番が無かったので守られなかった（v0.3.0 / v0.3.1）。`tests/fixtures/api_shape_fingerprints.tsv` に「版 → その版の API の形の指紋」を置き、`tests/api_shape_fingerprint.rs` が、いまの形の指紋と `API_VERSION` の行の指紋を突き合わせる。指紋の入力は2つ —— **正規化した仕様書**と、**失敗の形の一覧**（`src/server/error.rs` の `error_catalog` が返す、全部の構築子の状態コード・`type`・`code`。仕様書の失敗の応答は `default` → `ErrorBody` だけで `code` は `enum` の無い文字列なので、仕様書だけでは新しい `code` も失敗の状態コードの変更も見えない）。一覧の網羅は、理由の enum の値については型が、構築子の名前と `code` の綴りについては同じファイルの見張り番が強制する。**実験中の口とその口だけが指す型・`info` の版とライセンスと説明・口の `summary`・`example` / `examples` は入らない**（版を上げただけ、説明の文を直しただけでは指紋が変わらない）。**`operationId` と型の名前は入る**（コード生成の使い手には改名に当たる）。**口・欄・`enum` の値・成功の状態コード・失敗の `code` と状態コードを変えて版を上げなければ赤になる。** 版を上げたら、赤の文面に出る行を表の最後に足す。
- **既存の行は書き換えない。** いまの版の行の指紋を書き換えて緑にすると、版が同じで形の違う配布物がまた出る。
- **意味だけの変更**（欄の形はそのままで、値の作り方が変わる。例: B-71 の `endpoint`・B-61 の `dialogue` / `narration`）と、**どの口がどの失敗を返すか**は指紋に出ない。それは今までどおり、差分を読んで決める。
- **綴りだけの変化でも、版の小さい側を上げて行を足す**（依存の更新で仕様書の書き方が変わった等。配る仕様書が変わるので）。`operationId` と型の名前は Rust の関数・型の名前から生まれるので、**内部の改名でも赤になる** —— 名前を変えずに保ちたいときは `#[utoipa::path(operation_id = …)]` / `#[schema(as = …)]` で固定する。
- **正規化は通常変えない。** 変えたら、表の全部の行を同じ正規化で作り直す（過去の版の行は、その版のタグのソースから組んだ仕様書と失敗の一覧で計算する）。O-7 のレビューで1度そうした（`summary`・例を外し、失敗の一覧を足した）。

**P-2c: 英語の API ガイド。** `docs/api/` に英語で —— 起動（`--no-ui`）、会話（`model` の綴り: `aoi` / `aoi@new` / `aoi@<id>`）、キャラクターと記憶の管理、変容の走らせ方、`127.0.0.1` だけに結ぶこと（認証が無い理由と、組み込み先が同じ機に限られること）、仕様書の取り方。**リポジトリで最初の英語の文書**になる。ADR 本体の英訳はしない（必要なら要約だけ）。

## 却下した選択肢

- **④ 配布物をいま2つに割る** —— 上の表。利用者の体験を崩す割に、組み込む側の得は①②で足りる。
- **仕様書を手で書く（`openapi.yaml`）** —— 依存は増えないが、コードと仕様書の2箇所に同じ事実が載り、見張り番で結ぶ費用がかかる。P-2a の実測で `utoipa` が合わなかったときの退路としてだけ残す。
- **型から JSON Schema だけを生み（`schemars`）、口の一覧は手で書く** —— 半分だけ生成になり、口と型の結び付けが手作業で残る。`utoipa` が合わなかったときの第二の退路。
- **パスに版を入れる（`/admin/v1/...`）** —— P-2b。
- **認証を足す** —— 結ぶ先が `127.0.0.1` だけという絶対制約の下では要らない。外へ開く設計にする日が来たら、その ADR で決める（それまで API ガイドに前提として書く）。
- **③ をいまやる** —— 使い手が見えないうちに crate の境界と公開の型を固めると、その後の変更がすべて破壊的変更になる。

## 結果

- 他のソフトが「画面なしの personacore」を、仕様書と版の約束つきで組み込める。
- オープンソース化の届け方（「SillyTavern / Open WebUI から使える」）の土台になる —— OpenAI 互換の口に加えて、管理の口の仕様書がある。
- **⚠ 仕様書を生むために、`admin.rs` などの要求・応答の型に注釈が増える。** 型の数は多い（画面の写しの走査が数えている構造体の数）。P-2a はその費用を最初に測る。
- **⚠ 「実験中」の印を付けた口は、画面が使っていても互換の約束の外**になる。画面は同じリポジトリの中で一緒に変わるので困らないが、外の使い手には印で伝える。
